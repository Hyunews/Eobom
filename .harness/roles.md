# roles.md — 역할 분담과 검증 게이트

> **언제 읽나**: 에이전트를 전환할 때 / "이거 누가 쓰는 거지?"가 헷갈릴 때 / 상대 작업물을 검토해야 하나 고민될 때
>
> 이 문서가 존재하는 이유: 양쪽 에이전트가 같은 것을 두 번 검증하던 낭비를 없애기 위해.

---

## 1. 소유권 표

원칙은 "한 폴더 한 주인"이 아니라 **"한 파일 한 주인"**이다. 공유가 필요한 곳은 소유자를 두지 않고 **덧붙이기 전용(append-only) + 에이전트 태그**로 충돌을 없앤다.

### 1-1. 산출물 영역 (단독 소유)

| 영역 | 쓰기 | 읽기 | 비고 |
|---|---|---|---|
| `docs/` (기획 SSOT) | **Gemini** | Claude | 도메인 명세·API/DB 스펙 |
| `reports/` (HTML·PDF) | **Gemini** | Claude | 사람 열람용 산출물 |
| `eobom/frontend`, `eobom/backend` | **Claude** | Gemini | 실제 소스코드 |
| `.harness/` (규칙·메모리·툴) | **Claude** | Gemini | 하네스 유지보수 |
| `assets/` (원천 데이터·로고) | **사람** | 둘 다 | 에이전트가 임의 추가 금지 |

### 1-2. 기록 영역 `docs/작업일지_및_기록/` (파일 단위로 나눔)

작업 기록은 **양쪽 다 남겨야 하므로** 폴더 통째로 한쪽에 주지 않는다.

| 파일 | 쓰기 | 규칙 |
|---|---|---|
| `에이전트_기록/claude_tasks.md` | **Claude** | 본인 날것 로그. 상대는 읽기만. |
| `에이전트_기록/gemini_tasks.md` | **Gemini** | 본인 날것 로그. 상대는 읽기만. |
| `에이전트_기록/walkthrough.md` | **Claude**(항목) + **Gemini**(판정) | Claude가 항목 추가, Gemini는 그 항목 **아래 판정 1줄만** 덧붙인다. 남의 항목 본문은 고치지 않는다. |
| `YYMMDD.md` (일별 일지) | **둘 다** | 덧붙이기 전용. 각 줄 앞에 `[Claude]` / `[Gemini]` 태그. 남이 쓴 줄은 수정·삭제 금지. |
| `에이전트_기록/history.md` | 아카이브 | 과거 이력. 원칙적으로 손대지 않는다. |
| `.harness/memory/context.md` | **마지막 작업자** | 세션 끝낼 때 갱신 |

> 충돌이 안 나는 이유: 각자 자기 파일에 쓰거나(1:1), 덧붙이기만 하기 때문(append). 같은 줄을 두 에이전트가 고칠 일이 구조적으로 없다.

### 상대 영역을 건드려야 할 때
직접 고치지 않는다. §2-1 편차 보고 절차를 따른다.

## 2. 파이프라인과 단일 검증 게이트

```
  [Gemini]  docs/ 기획·스펙 확정
      │
      │  ← Claude는 여기서 스펙을 재해석·재검토하지 않는다.
      │     이해 안 되는 부분만 질문하고, 나머지는 그대로 신뢰하고 구현한다.
      ▼
  [Claude]  eobom/ 구현 + 빌드/테스트
      │     완료 후 walkthrough.md에 요약 1건 추가 (편차 필드 포함)
      ▼
  ★ 검증 게이트 (딱 여기 한 번)
  [Gemini]  walkthrough.md만 읽고 스펙 대조 → 3가지 중 하나
      │
      ├─ 통과      → 종료. 다시 확인하지 않는다.
      ├─ 반려      → 사유 1줄. Claude가 수정 후 재제출.
      └─ 스펙 갱신 → 현실이 맞고 기획이 틀렸다. Gemini가 docs/를 고치고 종료.
```

**게이트는 `walkthrough.md` 한 곳뿐이다.** Gemini는 코드를 직접 읽고 리뷰하지 않는다 — 요약과 스펙만 대조한다. 코드 품질은 Claude의 빌드/테스트 책임.

## 2-1. 편차(Drift) — 구현이 기획과 틀어질 때

가장 자주 일어나고, **여기서 문서가 썩는다.** (실제 사례: 카카오 API 45건 캡, 공공데이터 배제로 가격이 전부 플레이스홀더, 위치정보법 때문에 GPS 트랙 사용 불가)

**Claude가 편차를 발견하면** — 아래 3가지를 하지 않는다:
- ❌ 조용히 다르게 구현 → 문서가 거짓말이 되고 다음 세션이 잘못된 전제로 쌓는다
- ❌ `docs/`를 직접 수정 → 기획 판단은 Gemini 몫. 구현 편의로 스펙을 바꾸지 않는다
- ❌ 멈추고 대기 → 사람이 창을 전환할 때까지 진행이 막힌다

✅ 대신: **동작하는 쪽으로 구현 + `walkthrough.md`의 `편차` 필드에 기록.** 판단은 Gemini가 게이트에서.

**진행 자체가 막히는 급한 편차**는 `context.md`에 올린다:
```
▶ 다음 할 일
[Gemini] 확인요청: docs/01_장례_묘지_매칭/10 — 예약 API 응답에 전화번호 필드가
없어 직통전화 UX 구현 불가. 스펙 보완 필요. (Claude 대기 중)
```

**Gemini는** `docs/`를 고쳤으면 **왜 고쳤는지 한 줄**을 남긴다. 이유 없는 스펙 변경은 다음 사람이 되돌린다.

## 3. `walkthrough.md` 기록 형식 (고정)

자유 서술 금지. 5개 필드를 반드시 채운다 — 다음 에이전트가 되물을 일이 없어야 한다.

```markdown
## YYYY-MM-DD | <작업 제목>

- **근거 스펙**: docs/<경로>.md (없으면 "스펙 없음 — 즉흥 구현" 명시)
- **건드린 파일**: eobom/backend/src/... , eobom/frontend/src/...
- **결과**: 무엇이 되게 됐는지 1~2줄. 빌드/테스트 통과 여부 포함.
- **편차**: 스펙과 다르게 구현한 것 + 이유. 없으면 "없음". ← 비워두지 않는다
- **다음 에이전트가 알아야 할 것**: 미완·가정·부작용. 없으면 "없음".

<!-- Gemini 판정 1줄: ✅통과 / ❌반려(사유) / 🔄스펙갱신(고친 문서) -->
```

`편차`에 습관적으로 "없음"을 채우는 순간 이 필드는 죽는다. 정말 없는지 확인하고 적을 것.

## 4. 에스컬레이션 — 혼자 결정하지 않는 것

아래는 사용자에게 묻는다. 나머지는 알아서 진행한다.

- 되돌리기 어려운 것: 파일 대량 삭제·이동, `git commit`/`push`, 배포, 외부 발행
- 돈이 드는 것: 유료 API 연동, 인프라 증설
- 법·규제: 개인정보 수집 범위 변경, 위치정보 사업자 신고 (→ `security.md`)
- 스펙과 구현이 충돌하는데 어느 쪽이 맞는지 판단이 안 설 때

## 5. 사람(사용자)의 역할

에이전트 창 전환(Antigravity ↔ Claude CLI), `assets/` 데이터 투입, §4 승인.
전환 시 할 일은 **§6 핸드오프 블록을 복사해서 상대 창에 붙여넣기**뿐이어야 한다 — 그 이상을 매번 확인해야 한다면 이 구조가 실패한 것이니 하네스를 고칠 것.

---

## 6. 핸드오프 안내 (턴을 넘길 때 반드시)

작업을 마치고 상대 에이전트 차례가 되면, **응답 맨 마지막에** 아래 블록을 출력한다.
사용자가 "이제 뭐라고 하지?"를 고민하지 않고 그대로 복사할 수 있어야 한다.

```
──────────────────────────────
▶ 다음: <Gemini(Antigravity) | Claude(CLI)>
아래를 복사해서 붙여넣으세요:

<상대에게 줄 프롬프트 1~3줄>
──────────────────────────────
```

**작성 규칙**
- 상대가 **바로 착수할 수 있게** 구체적으로. "확인해줘"(❌) → "게이트 확인 — walkthrough.md의 8/8 유품정리 항목, 편차(원클릭 삭제 불가) 판단 필요"(✅)
- `context.md`의 "다음 할 일"과 **같은 내용**이어야 한다. 블록은 말로 옮긴 것일 뿐, 정본은 `context.md`.
- 사용자 승인이 필요한 항목(§4)이 있으면 블록 **위에** 따로 묻는다. 블록 안에 섞지 않는다.
- 아직 자기 차례가 안 끝났으면 출력하지 않는다.

**예시**
```
──────────────────────────────
▶ 다음: Claude (CLI)
아래를 복사해서 붙여넣으세요:

docs/02_디지털_유산/16 기반으로 유품정리 API 구현해줘.
SNS 연동은 3사(카카오/네이버/구글) 전부 포함.
──────────────────────────────
```
