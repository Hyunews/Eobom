> **언제 읽나**: `walkthrough.md`에 항목을 쓰기 직전 / 판정을 남기기 직전
>
> 형식이 여러 곳에 흩어져 있으면 매번 다시 판단해야 한다. 이 문서 하나만 본다.
> 누가 어느 파일에 쓰는지(소유권)는 `roles.md` §1-2, 검증 게이트의 흐름은 `roles.md` §2.

## 1. `walkthrough.md` 항목 형식 (고정)

자유 서술 금지. 5개 필드를 채운다 — 다음 차례가 되물을 일이 없어야 한다.

```markdown
## YYYY-MM-DD | <작업 제목>

- **근거 스펙**: docs/<경로>.md (없으면 "스펙 없음 — 즉흥 구현" 명시)
- **건드린 파일**: eobom/backend/src/... , eobom/frontend/src/...
- **결과**: 무엇이 되게 됐는지 1~2줄. 빌드/테스트 통과 여부 포함.
- **편차**: 스펙과 다르게 구현한 것 + 이유. 없으면 "없음". ← 비워두지 않는다
- **다음 에이전트가 알아야 할 것**: 미완·가정·부작용. 없으면 "없음".

<!-- Gemini 판정 1줄: ✅통과 / ❌반려(사유) / 🔄스펙갱신(고친 문서) -->
```

`편차`에 습관적으로 "없음"을 채우는 순간 이 필드는 죽는다. 정말 없는지 확인하고 적을 것.

🔴 **판정 줄은 아래 네 형태만 쓴다**(2026-09-02). `harness-doctor.sh` #8이 이 표기로 게이트
대기열을 세므로, **다른 형태로 쓰면 '무표기'로 떨어져 큐에서 조용히 사라진다.**

| 뜻 | 표기 | 누가 |
|---|---|---|
| 대기 | `<!-- Gemini 판정 1줄: … -->`(양식 그대로) 또는 `<!-- Gemini 판정 대기 -->` | Claude가 항목 쓸 때 |
| 완료 | `<!-- Gemini 판정: ✅통과 (근거) -->` 또는 `- **판정**: …` | Gemini |
| 재판정 | `- **판정(재)**: …` (구 판정은 취소선으로 남긴다) | Gemini |

- 🔴 **반드시 줄 맨 앞에서 시작한다.** 들여쓰거나 문장 중간에 넣으면 안 세어진다. 반대로,
  본문에서 이 표기를 **언급**할 때는 백틱 안에 넣어 줄 중간에 둔다 — 줄 앞에 두면 그 항목의
  판정으로 잘못 세어진다(09-02에 실제로 3번 났다).
- 🟡 **무표기 15건**은 2026-08-07 양식 이전 옛 항목이다. doctor가 이 수를 찍는다 — **늘어나면
  새 항목이 위 표 밖의 표기를 쓴 것**이다.

### 1-1. `결과`는 **반증 가능하게** 쓴다 (2026-08-14 신설)

게이트가 이 항목만 보고 **직접 재현**한다(→ `GEMINI.md` "검증 범위" §2). 재현할 수 없게 쓰면
검증이 불가능해지고, 그러면 게이트는 문장을 되풀이하는 것 말고 할 수 있는 게 없다.

| 쓸 것 | 쓰지 말 것 |
| :--- | :--- |
| `"24시간 긴급상담" → "장례식장 바로 찾기"` (검색 가능한 원문) | `"긴급콜 문구를 정정했다"` (무엇을 뭘로?) |
| `JUDICIAL_SCRIVENER를 5곳에 추가 — schema.prisma, CounselingPage.tsx, …` (전수 열거) | `"관련 파일에 반영"` (몇 곳인지 모름) |
| `tsc --noEmit(frontend·backend)·vite build 통과` (재현할 명령) | `"검증 완료"` |

- **제거·교체한 문자열은 원문 그대로** 적는다. 게이트가 그걸로 검색해 0건인지 확인한다.
- **건드린 파일은 전수 열거**한다. 목록에 없는 파일이 바뀌어 있으면 반려 사유다.
- 빌드·테스트는 **돌린 명령 그대로** 적는다. "통과"만 적으면 재현할 수 없다.

**항목 본문은 일한 당사자가 쓴다.** 자기가 안 한 일을 옮겨 적으면 전언 오류가 난다(→ `GEMINI.md` 주의 §2). Gemini가 덧붙이는 건 판정 1줄뿐이고, 남의 항목 본문은 고치지 않는다.

## 2. 어디에 무엇을 쓰나

| 파일 | 무엇을 | 성격 |
|---|---|---|
| `에이전트_기록/walkthrough.md` | 완료 항목 5개 필드 + 판정 | 정제된 교차검증 로그 |
| `에이전트_기록/walkthrough_아카이브_YYMM.md` | 판정이 **끝난** 옛 항목 | 아카이브. **새로 쓰지 않는다** |
| `에이전트_기록/claude_tasks.md` | 시행착오·디버깅 과정·삽질 | 날것. 정제하지 않는다 |
| `에이전트_기록/claude_tasks_아카이브_YYMM.md` | 날짜가 지난 옛 날것 기록 | 아카이브. **새로 쓰지 않는다** |
| `에이전트_기록/gemini_tasks.md` | 검토 메모 | 날것 |
| `작업일지_및_기록/YYMMDD.md` | 그날 한 **실무** 작업 | 덧붙이기 전용, 줄 앞에 태그 |
| `.harness/_meta/` | 하네스 자체의 구조 변경 | 일지에 쓰지 않는다(이력 오염 방지) |

일지 줄 태그는 `roles.md` §0 표를 따른다 — `[Claude:Opus]` / `[Claude:Sonnet]` / `[Gemini]` / `[사용자]`.

## 3. 흔한 실수

- **결과에 "구현 완료"만 적기** — 무엇이 되게 됐는지가 없으면 다음 세션이 코드를 다시 읽어야 한다.
- **빌드 통과 여부 생략** — 안 적혀 있으면 안 해본 것으로 취급된다(→ `done.md` §2).
- **`claude_tasks.md`를 정제해서 쓰기** — 정제본은 `walkthrough.md` 몫이다. 여기선 실패한 시도가 오히려 자산이다.
- **하네스 구조 변경을 일지에 쓰기** — 실무 이력이 오염된다. `_meta/`로 보낸다.
