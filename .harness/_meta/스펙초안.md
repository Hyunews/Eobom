# 경량 하네스 스펙 초안 (가칭 — 이름 미정)

> biz-ttori의 "지금 상태를 세션 밖에서도 이어가기" 핵심 가치만 남기고,
> **1인 + 에이전트 1개(클로드/제미나이/코덱스 무관) + 옵시디언 볼트** 조합에 맞게 경량화.
> biz-ttori와는 별도 레포/워크스페이스, 개인 GitHub 계정에 올릴 것 (직장 워크스페이스와 분리).

---

## 1. 왜 biz-ttori를 그대로 못 쓰나

biz-ttori 규칙의 상당수는 **"클로드가 제미나이를 자동 호출하는 멀티에이전트 구조"** 를 안전하게 굴리려고 만든 장치다. 1인 + 에이전트 1개 조합에선 애초에 발생하지 않는 문제라 걷어낸다.

| biz-ttori 장치 | 존재 이유 | 1에이전트 환경에서 |
|---|---|---|
| AI 호출 3단계(T1/T2/T3) 정책 | 클로드가 제미나이(agy) 자동호출 시 비용폭탄/환각 전파 방지 | **불필요** — 애초에 두 번째 에이전트가 없음 |
| `memory/inbox.md`/`outbox.md` | 클로드↔제미나이 비동기 메일박스 | **불필요** |
| `memory/agent-names.md` | 여러 에이전트 호칭 관리 | **불필요** (에이전트 1개) |
| 코드작성 분신/리뷰 분신 분리(T3) | 확증편향 방지용 adversarial 서브에이전트 | **선택사항** — 툴이 서브에이전트를 지원하면 쓰고, 없으면 생략 |
| G-Brain "환각 방지용 안정 앵커" 강조 | 제미나이 인용 신뢰도 문제(과거 2회 환각 확인) 대응 | 완화 — 그래도 링크 부패 방지 원칙 자체는 유지 가치 있음 |

남기는 건: **"세션이 끊겨도 다음 세션이 지금 상태를 1분 안에 파악할 수 있게"** 하는 최소 장치들.

---

## 2. 벤더중립 핵심 과제 — 에이전트 CLI마다 다른 진입점 파일

각 CLI가 자동으로 읽는 "규칙 파일" 이름이 다르다는 게 벤더중립화의 유일한 진짜 기술적 난제다.

| 도구 | 자동 로드 파일 |
|---|---|
| Claude Code | `CLAUDE.md` |
| Gemini CLI / Antigravity | `GEMINI.md` |
| Codex CLI | `AGENTS.md` |

**해결 방식**: 진짜 내용은 `AGENTS.md` 하나에만 쓰고, `CLAUDE.md`/`GEMINI.md`는 **1줄짜리 포인터 파일**로 둔다.

```markdown
# CLAUDE.md
See [AGENTS.md](./AGENTS.md) — 이 저장소의 실제 행동 규칙은 전부 거기 있음.
```

> ⚠️ 확인 필요: Claude Code가 `AGENTS.md`를 직접 읽는 기능을 추가했는지는 버전에 따라 다를 수 있음 — 컷오프(2026-01) 기준 불확실, 최신 공식문서로 재확인 권장. 확인 전까진 포인터 파일 방식이 제일 안전함.

## 3. 파일 구조 (최소)

```
<repo>/
├── AGENTS.md              ← SSOT. 규칙 본문 (아래 §4)
├── CLAUDE.md              ← "See AGENTS.md" 1줄
├── GEMINI.md              ← "See AGENTS.md" 1줄
├── context.md             ← 지금 상태 스냅샷 (biz-ttori context.md와 동일 역할, 1화면 유지)
├── daily/
│   └── yymmdd.md          ← 그날 한 일 (biz-ttori daily/ 동일)
├── projects/
│   └── <실프로젝트명>/
│       └── context.md     ← 그 프로젝트 상태 + 실코드 경로(절대경로 포인터, 코드 복사 안 함)
└── tools/
    └── staleness-check.sh ← (선택) 문서-코드 최신성 체크, 필요해지면 추가
```

G-Brain 위키링크는 옵시디언 볼트 특성상 자연히 쓰게 될 텐데, **링크는 안정적 앵커(파일/모듈 단위)에만**, **함수 단위 링크 금지** 원칙은 biz-ttori에서 그대로 가져올 가치 있음(부패 방지가 핵심이지 멀티에이전트 전용 규칙이 아니었음).

## 4. `AGENTS.md` 본문 뼈대 (제안)

```markdown
# AGENTS.md — 작업 규칙

## 세션 시작 시
1. context.md 읽고 "지금 상태" 파악
2. 실프로젝트 작업이면 projects/<name>/context.md 확인

## 작업 순서
PLAN → CONFIRM → CODE → (선택) SELF-REVIEW → SAVE → UPDATE(context.md 갱신)

## 코드 ↔ 문서 링크
- 파일/모듈 단위로만 링크, 함수 단위 금지 (동기화 누락 시 링크=환각 소스가 됨)
- 실프로젝트 코드는 다른 워크스페이스에 그대로 둔다. 이 레포는 컨텍스트/계약만 보관 (외장 두뇌 모델)

## 검색·정보 품질
- 버전/스펙처럼 빠르게 바뀌는 정보는 "확인 필요" 명시, 공식문서 우선
```

biz-ttori의 S1~S3(검색 품질), G1~G5(G-Brain) 원칙 중 **멀티에이전트 언급만 빼고** 재사용 가능한 부분이 꽤 있음 — 통째로 재작성보다 발췌 편집이 빠를 듯.
