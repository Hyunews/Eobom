# 부팅 예산 구조 정리 (2026-08-12)

> 하네스 자체의 구조 변경 기록. 실무 일지(`docs/작업일지_및_기록/`)에는 쓰지 않는다(→ `record.md` §2).

## 문제

부팅 파일 합계가 예산(11,264B)을 상시 넘나들었다. 08-12 세션에서 `context.md`·`systems.md`에
정상적인 내용을 추가할 때마다 `harness-doctor`가 🔴를 띄웠고, **같은 세션에서 6번 이상 반복해서
바이트를 깎는 상황**이 벌어졌다. 매번 문장을 줄여 통과시켰지만 근본 원인이 남아 있었다.

원인은 `AGENTS.md` 하나가 **6,499B로 부팅 예산의 58%**를 차지한 것. 나머지 두 파일
(`context.md` 2.5KB, `pending-approvals.md` 2.2KB)은 각자 적정 크기였는데도 합계가 빠듯했다.

## 진단 — 예산이 아니라 중복이 문제였다

`harness-doctor.sh` 주석에 이미 원칙이 적혀 있었다:

> "다시 한계에 닿으면 예산을 올리기 전에 **'이 문서에 있을 내용이 맞는지'부터** 볼 것."
> (선례: 2026-08-10 `roles.md` 8,188B → 기록 형식을 `record.md`로 분리)

그 렌즈로 보니 **`AGENTS.md`가 자기 자신의 §7 "같은 문서를 두 곳에 복사하지 않는다"를
위반**하고 있었다.

| 섹션 | 실제 정본 | 중복도 |
|---|---|---|
| §3 재사용 절차 | `skills/README.md` "언제 여기 추가하나" | 거의 그대로 |
| §4 구조화된 메모리 | `memory/MEMORY.md` "타입" | 1개 항목 빼고 중복 |
| §5 문서↔코드 링크 | `memory/g-brain-map.md` "링크 원칙" | 거의 그대로 |
| §8 작업일지 | `record.md` §2 표 + §3 흔한 실수 | 그대로 |

네 섹션 모두 §0-1 조건부 로드 표가 **이미 해당 정본으로 라우팅**하고 있었다. 즉 부팅 때마다
읽히는 자리에 "조건부로 읽을 파일의 요약"이 들어가 있던 것 — 조건부 로드 설계의 취지를 스스로 깨는 배치.

## 조치

1. **§3·§4·§5·§8 삭제.** §0-1 표가 이미 라우팅하므로 대체물을 두지 않았다.
   - 최초 시도에서 "위임표"를 만들어 넣었다가 **파일이 오히려 6,536B로 늘었다** — 중복을 지운
     자리에 메타 설명을 채워 상쇄된 것. 위임표 자체가 §0-1과 또 중복이라 통째로 삭제했다.
2. **§0-1 표 보강** — `skills/README.md`(정확한 파일로), `g-brain-map.md`(§5 삭제로 고아가 될 뻔함) 추가.
3. **유일하게 중복이 아니던 규칙 1개 이관** — "코드·git 히스토리·이미 문서화된 것은 메모리로
   남기지 않는다" → `memory/MEMORY.md` 머리말.
4. **역참조 정리** — `record.md`가 `AGENTS.md §8`을 "규칙 정본"으로 가리키고 있었는데, 실제로는
   `record.md` 자신이 정본이었다(방향이 거꾸로). 자기참조 제거.
5. **§9에 재발 방지 규칙 2개 추가** — ①예산 초과 시 숫자를 올리기 전에 중복부터 볼 것
   ②섹션 번호 재사용 금지.
6. §0 제목 "이 2개가 전부"가 표의 3개와 불일치하던 기존 오류 수정.

## 결과

| | 이전 | 이후 |
|---|---|---|
| `AGENTS.md` | 6,499B | **5,749B** (-750B) |
| 부팅 합계 | 11,267B (예산 초과) | **10,493B** |
| 여유 | 3B | **771B** |
| doctor | 🔴 1건 | ✅ 105개 전항목 통과 |

**예산 숫자(11KB)는 건드리지 않았다.** 늘릴 필요가 없었다 — 들어가면 안 될 내용이 들어가 있었을 뿐.

## 남은 것

- 섹션 번호에 §3·§4·§5·§8 공백이 생겼다. **의도된 것이며 재사용하지 않는다** — `docs/00-04`가
  `AGENTS.md §7`을, `pending-approvals.md`가 `§0`을 참조하고 있어 재번호하면 그 참조가 깨진다.
  §9에 규칙으로 명시했다.
- `_meta/3에이전트_전환안.md`의 "`AGENTS.md` §2 소유권 표" 참조는 §2가 그대로라 유효하다.
