## 2. 지도 / 위치

| 시스템 | 상태 | 비고 |
|---|---|---|
| 카카오맵 JS SDK | ✅ 활성 (2026-08-08 확인) | 등록 도메인에 로컬 LAN IP 추가함 (기존엔 localhost만 등록돼 있었음) |
| 카카오 로컬 API (장소검색) | ✅ 사용 중 | 시설 데이터 수집에 사용 |

- 키: `VITE_KAKAO_MAP_KEY` (`eobom/frontend/.env`) — 프론트 번들에 노출되므로 도메인 제한 필수
- 활성화 경로: 카카오 디벨로퍼 > 이어봄 앱 > 제품 설정 > 카카오맵 > 활성화 ON
- ⚠️ **수집 한계**: 시/도 단위 검색 시 45건 API 캡 때문에 일부 지역(예: 광주 남구) 시설이 누락된다. 전수 수집하려면 시/군/구 단위로 재검색해야 함.
- 2026-08-08: 사용자가 등록 도메인에 로컬 LAN IP 추가 후 지도 정상 렌더링 확인함. 코드 수정 없이 콘솔 설정만으로 해결.

### 위치(Geolocation) 자동감지 — 로컬 IP 접속 시 항상 실패

Chrome 등 브라우저의 `navigator.geolocation`은 **보안 컨텍스트**(HTTPS 또는 `localhost`)에서만 동작한다.
`http://<LAN IP>:5173`은 여기 해당 안 돼서 브라우저가 요청 자체를 차단 → 코드는 실패 콜백(하드코딩 폴백:
서울 서초)으로 떨어진다. **코드로 고칠 수 없는 브라우저 정책** — 배포(HTTPS) 후에는 정상 동작한다.
UI에는 폴백 적용 시 경고 배지를 띄우도록 수정함(→ walkthrough.md 2026-08-08 (2) 항목).

### 로컬 LAN(폰 실기기) OAuth 테스트 — 보류

2026-08-08: PC(유선, `192.168.0.111`)와 테스트 폰이 다른 네트워크에 있어 로컬 LAN 매칭이 막힘.
**사용자 결정: 로컬 네트워크 맞추기는 보류, 백엔드 배포 후 실제 배포 도메인으로 테스트.**
프론트(`config.ts`)·백엔드(`authController.ts`) 양쪽에 동적 IP 대응 코드는 이미 구현 완료 —
사설 IP/localhost에서만 동작하고 배포 도메인에서는 자동으로 `FRONTEND_URL` env로 폴백하므로
백엔드 배포 시 추가 수정 없이 그대로 동작한다 (→ walkthrough.md 2026-08-08 항목).

## 6. 미구현 / 대기

- **제휴(`isPartner`) UI**: 스키마 필드는 있으나 전부 `false`. 배지·최상단 고정·VR 게이팅 UI 미구현.
- **360° VR 뷰**: 실제 파노라마 이미지 미확보로 기능 비활성화(코드 제거됨).
