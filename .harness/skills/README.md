# skills/ — 재사용 가능한 작업 절차 저장소

이 폴더는 "한 번 잘 풀었던 작업 절차"를 다음 세션(또는 다른 사람, 다른 에이전트)이
대화 이력이나 코드를 뒤지지 않고도 바로 따라할 수 있게 남겨두는 곳이다.
**초기 환경구성만큼 중요한 부분** — 여기가 쌓여야 "다른 사람 스킬을 흡수"하는 게 실제로 가능해진다.

## 언제 여기 추가하나

- 같은 종류의 작업을 **두 번째로** 하게 됐을 때 (반복 = 재사용 가치 있다는 신호, 처음부터 만들지 않는다)
- 다른 사람의 좋은 워크플로우/프롬프트 패턴을 가져와서 쓸 만했을 때
- 삽질 끝에 알아낸 "이렇게 하면 안 된다"도 포함 가능 (실패도 스킬이다)

## 파일 형식

- 파일명: `kebab-case.md` (예: `android-16kb-page-size-check.md`)
- 맨 위 한 줄: **언제** 이 스킬을 쓰는지 (트리거 조건)
- 본문: 절차·커맨드·주의사항. "무엇을 하는지"보다 **"왜 이렇게 하는지"**(비직관적인 이유, 함정)를 남긴다 — 당연한 건 생략.

```markdown
# <스킬 이름>

> 언제 쓰나: <트리거 조건 한 줄>

## 절차
1. ...

## 주의사항 / 함정
- <겪어봐서 아는 것>
```

## 도구별 연동 (선택)

- Claude Code처럼 네이티브 Skill 메커니즘(`.claude/skills/`)이 있는 도구는, 여기 쌓인 문서를 그쪽에도 등록해서 자동 로드되게 할 수 있음.
- 그런 메커니즘이 없는 도구(Gemini CLI, Codex CLI 등)는 `AGENTS.md`의 "작업 전 `skills/` 확인" 규칙으로 대체한다 — 사람이 아니라 규칙 파일이 "찾아봐라"를 강제하는 방식.
