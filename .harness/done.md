# done.md — "완료"의 정의 (유일 정본)

> **언제 읽나**: 작업을 끝났다고 선언하기 직전
>
> "완료"의 기준이 여러 곳에 흩어져 있으면 매번 다시 판단해야 한다. 이 문서 하나만 본다.

## 1. 완료 체크리스트 (전부 ✅여야 완료)

### 코드 작업 (Claude)
- [ ] 타입체크/빌드 통과 — `npm run build` 또는 `tsc --noEmit` 에러 0
- [ ] 실제로 동작 확인 — 최소한 해당 화면/엔드포인트를 한 번 실행해봤다
- [ ] 스펙과 다르게 구현한 게 있으면 **`편차` 필드에 기록** (→ `roles.md` §2-1). `docs/`를 직접 고치지 않았다
- [ ] `walkthrough.md`에 5개 필드(근거 스펙/건드린 파일/결과/**편차**/다음 에이전트가 알아야 할 것) 기록 → 형식은 `roles.md` §3
- [ ] `claude_tasks.md`에 시행착오·디버깅 과정 남김
- [ ] `context.md`의 "다음 할 일" 갱신
- [ ] Gemini 차례면 **핸드오프 블록 출력** (→ `roles.md` §6)

### 기획 작업 (Gemini)
- [ ] `docs/` 마크다운 정본 작성/갱신 완료
- [ ] `docs/00_DOCS_INDEX.md` 인덱스에 반영 (신규 문서인 경우)
- [ ] 인덱스가 가리키는 파일이 **실제로 존재**하는지 확인 — 없는 파일을 가리키는 링크를 남기지 않는다
- [ ] 대기 중인 `walkthrough.md` 항목에 판정(통과/반려/스펙갱신)을 남겼다 — 판정 없이 방치하면 Claude가 다음 작업을 못 쌓는다
- [ ] 편차 때문에 `docs/`를 고쳤으면 **왜 고쳤는지 한 줄** 남김
- [ ] `gemini_tasks.md`에 검토 메모 남김
- [ ] `context.md`의 "다음 할 일" 갱신
- [ ] Claude 차례면 **핸드오프 블록 출력** (→ `roles.md` §6)

## 2. 완료가 **아닌** 것

아래는 "완료"라고 말하지 않는다. 정직하게 미완으로 보고한다.

- 빌드는 되지만 실행해보지 않음 → **미완**
- 코드는 짰지만 스펙과 다른 부분이 있고 아직 논의 안 함 → **미완**
- "아마 될 것 같다" / "이론상 동작한다" → **미완**
- 테스트가 실패하는데 "원래 실패하던 거다"라고 넘어감 → **미완** (사실이면 그 사실을 명시)
- 임시방편(하드코딩·주석처리)으로 막아둠 → **미완**, `context.md` 블로커에 반드시 남긴다

> 실패·미완을 숨기는 것이 이 프로젝트에서 가장 비싼 실수다. 다음 세션이 잘못된 전제 위에서 계속 쌓기 때문.

## 3. 세션 종료 시 (사용자가 "오늘 여기까지" 신호를 줄 때)

사용자가 요청하지 않아도 아래를 자동으로 수행한다.

1. `.harness/memory/context.md` — "다음 할 일" + 지금 상태 갱신
2. `docs/작업일지_및_기록/에이전트_기록/walkthrough.md` — 완료 항목 정리
3. `docs/작업일지_및_기록/에이전트_기록/claude_tasks.md` — 디버깅 과정·시행착오 등 날것 기록
4. `docs/작업일지_및_기록/YYMMDD.md` — 그날의 실무 작업 일지
5. `bash .harness/tools/harness-doctor.sh` 실행 → 빨간불 있으면 사용자에게 보고

## 4. 게이트 판정 처리

Gemini는 `walkthrough.md` 항목 아래 판정 1줄을 남긴다. 별도 파일을 만들지 않는다.

| 판정 | 뜻 | 다음 동작 |
|---|---|---|
| ✅ 통과 | 스펙대로 구현됨 | 종료. 재확인하지 않는다. |
| ❌ 반려(사유) | 구현이 스펙을 못 맞춤 | Claude 수정 후 같은 항목에 "재제출" 표시 |
| 🔄 스펙갱신(문서) | **현실이 맞고 기획이 틀림** | Gemini가 `docs/` 수정 + 이유 1줄. Claude는 재작업 없음. |

- 3회 이상 반려가 반복되면 **스펙 자체를 의심**하고 사용자에게 에스컬레이션 — 구현이 아니라 기획이 틀렸을 가능성이 크다.
- 판정이 오래 비어있는 항목이 쌓이면 그것도 블로커다. `context.md`에 "[Gemini] 게이트 대기 N건"으로 올린다.
