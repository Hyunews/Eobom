# g-brain-map.md — 지식 그래프 인덱스

> biz-ttori G-Brain의 경량판. "예쁜 그래프"가 목적이 아니라 ① 안정적 앵커 ② 프로젝트별 계약 통로 ③ 문서-코드 추적성, 이 셋만 취한다.

## 링크 원칙 (G1 — 부패 방지 최우선)

- 링크는 **파일/모듈 단위로만**. 함수 단위 링크 금지 — 세밀할수록 코드 변경 시 동기화 누락 → 링크가 거짓말(환각 소스)이 된다.
- 안정적 앵커(자주 안 바뀌는 파일·계약)에만 건다. 자주 바뀌는 구현 디테일엔 걸지 않는다.
- 링크 남발 금지 — "실제 참조가 필요할 때"만. `tools/gbrain-doctor.sh`로 주기적으로 깨진 링크 점검.

## 계약 SSOT (G3)

- 여러 프로젝트가 서로의 API/인터페이스를 참조해야 하면, 각 프로젝트 폴더에 `api-specs.md`를 두고 그걸 거쳐가게 한다. 전역 파일에 여러 프로젝트 계약을 섞지 않는다.
