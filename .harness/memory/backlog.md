## ⑱ 🔴 CRLF 줄바꿈 오염 — 사람 판단 필요 (09-17 발견 · 09-17 Opus 재측정)

🔵 측정 상세는 [`backlog_아카이브_2609.md`](backlog_아카이브_2609.md) ⑱. 여기는 결론과 요청만.

**사실**(`git cat-file`로 HEAD 블롭 직접 측정):
- 🔴 **추적 파일 285개 중 177개(62%)가 CRLF 블롭**이다. `.gitattributes`는 **없다**.
- 🔴 **09-16·09-17 커밋이 만든 문제가 아니다** — `index.css`는 `b6e2f70`(09-11)부터, `README.md`는
  `ba93691`부터 이미 CRLF였다. 그 커밋들은 **원래 CRLF이던 파일을 그대로 유지**했을 뿐이다.
- 🔴 `core.autocrlf`가 **세션마다 뒤집혔다** — 09-16에 repo-local `true`(WSL 88건→28건 해소),
  09-17에 누군가 `false`로 되돌림. **`false`가 오염을 부르는 방향**이다(작업 트리 CRLF가 그대로 커밋).
- ✅ **런타임 영향 없음** — 깨지는 것은 `git diff`/`blame` 가독성뿐.

**사람이 골라야 할 것 — 순서가 있다**:
1. 🔴 **먼저 `.gitattributes`**(없으면 또 뒤집힌다): `* text=auto eol=lf` + `*.ps1 text eol=crlf`. 🟡 `.sh`는 반드시 LF.
2. 그다음 **전면 재정규화 1회**(`git add --renormalize .` — 177개가 바뀌는 **대형 커밋**, 순수 줄바꿈임을 메시지에 명시) **또는 현상 유지**. 🔵 *"5개 파일만"* 은 부분 처방이라 권하지
   않는다 — 62%가 CRLF인데 5개만 LF로 바꾸면 혼재가 심해진다.
