💡 브라우저 창을 좁혀(≤768px) 아래 버튼으로 4개 모달을 각각 열어보세요.

대상 4개: MyPageFamilyDesignation·LoginModal·InquiryModal·AddressSearchModal (SummaryModal은 모바일 진입 자체가 없어 제외 확정).

제안: 각 모달의 backdrop·panel 인라인 스타일을 <modal명>-modal-backdrop/ -panel CSS 클래스로 옮기고(값은 지금 인라인과 동일 — 배경색·블러·z-index· 데스크톱 maxWidth·padding은 모달마다 그대로 유지), 바텀시트 규칙 하나를 @media (max-width:768px)로 4개 클래스에 한 번에 적용합니다: align-items:flex-end(하단 고정) · border-radius:16px 16px 0 0 (위만 둥글게) · max-height:88dvh+overflow-y:auto(내용이 길면 내부 스크롤) · 좌우 var(--gutter-chrome). 인라인 스타일은 미디어쿼리로 못 덮으므로 클래스 이전이 필수입니다(각 파일 값은 안 바뀜 — 그릇만 클래스로 바꿈).

실측(크롬 320~398px, getBoundingClientRect): 4개 다 바닥에 딱 붙음(bottomGap=0), 위쪽만 16px 라운드, max-height 88dvh 정확히 적용, 좌우 16px 거터, overflow-y:auto 확인. LoginModal의 기존 max-height:90vh(모바일 주소창에 잘리는 문제)는 새 규칙의 88dvh가 소스 순서상 나중이라 자동으로 덮어씀. InquiryModal· AddressSearchModal은 원래 모바일에서 넘치는 내용을 스크롤할 방법이 아예 없었는데 (잠재 버그) 이번에 같이 해결됨. AddressSearchModal의 다음 우편번호 위젯(420px 고정 높이)도 88dvh(≈500~700px대) 안에 여유 있게 들어감.
