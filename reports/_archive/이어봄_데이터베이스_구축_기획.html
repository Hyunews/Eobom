🗄️ 데이터베이스 구축 & 기획서 (DB Architecture Specification)

디지털 엔딩 & 웰다잉 토탈 케어 플랫폼(이어봄)의 서비스 기능별 데이터 요구사항 분석, 데이터베이스 엔진 비교 평가, 물리 스키마 설계 및 암호화 보안 전략

1. 구현 기능별 데이터 요구사항 (Data Requirements)

🔐 1. 디지털 유언장 & 엔딩노트
  • 요구 데이터: 암호화된 유언 텍스트, 사전연명의향서, 음성/영상 메모리얼 파일 URL.
  • 특이사항: 최고 등급의 개인정보 보안 필요. 필드 단위 암호화(AES-256) 및 열람 조건(사망 확정/지정일) 제어 로직 필요.
💼 2. 디지털 유산 & 계정 관리
  • 요구 데이터: 소셜/금융/구독 플랫폼 명, 계정 식별자, 사후 처리 방침(파기/유지/전달), 자격 증명.
  • 특이사항: 다양한 플랫폼별 가변 속성 데이터(JSONB 구조) 수용 및 처리 완료 여부 추적 트랜잭션.
🏛️ 3. 장례/추모 시설 검색 & 예약
  • 요구 데이터: 장례식장/봉안당/수목장 위치(위경도), 카테고리, 이용 요금, 1:1 상담 및 방문 예약 내역.
  • 특이사항: 공간 위치 쿼리(Spatial Query) 및 동시 예약 중복 방지 트랜잭션(ACID) 필요.
📩 4. 모바일 부고장 & 조의록
  • 요구 데이터: 고인 정보, 상주 계정, 빈소 위치, 조의금 계좌, 조문객 방명록/조의 메시지.
  • 특이사항: 부고 알림 트래픽 급증 시 빠른 읽기 성능(Read-Heavy) 및 조의 메시지 실시간 저장.

2. 데이터베이스 종류별 장단점 비교 평가

비교 항목 RDBMS (PostgreSQL) 추천 BaaS (Supabase - Postgres) NoSQL (MongoDB) Hybrid (Postgres + S3)
데이터 무결성 & ACID 최상 (외래키 & 엄격한 트랜잭션) 최상 (PostgreSQL 엔진 기반) 보통 (문서 단위, FK 결합 한계) 최상 (메타데이터 ACID 보장)
보안 & 접근 제어 우수 (Field Level Encryption) 최상 (Row Level Security RLS) 보통 (애플리케이션 단 검증) 최상 (DB 암호화 + S3 Presigned)
유연성 (가변 데이터) 우수 (JSONB 타입 지원) 우수 (JSONB 타입 지원) 최상 (Schema-less Document) 최상 (JSONB + 미디어 파일 분리)
미디어(대용량) 처리 부적합 (BLOB 저장 시 성능 저하) 우수 (Storage 제품 일체 제공) 제한적 (GridFS 사용 시 복잡도 증가) 최상 (S3 전용 스토리지 분리)
개발 생산성 & 백엔드 연동 우수 (Prisma / Node / NestJS) 최상 (자동 REST/GraphQL API) 우수 (Mongoose / Node.js) 우수 (표준 기업형 아키텍처)
종합 평가 및 판정 핵심 서비스 데이터용 1순위 빠른 MVP 구축 시 최적 비정형 복잡 데이터가 적어 비추천 최종 채택 아키텍처 (Standard)
💡 최종 채택: PostgreSQL + Prisma ORM + AWS S3 하이브리드 아키텍처

채택 사유: 웰다잉 플랫폼은 유언장 및 예약 정보 등 **트랜잭션 무결성과 관계형 결합도(FK)**가 극도로 중요한 시스템입니다. 따라서 메인 DB로 **PostgreSQL**을 채택하고, 타입 안전성이 뛰어난 **Prisma ORM**을 통해 백엔드를 연동합니다. 또한 대용량 음성/영상 엔딩노트는 **AWS S3 (또는 Supabase Storage)**로 이관하고 DB에는 암호화된 URL 및 메타데이터만 저장함으로써 저장 비용 절감과 조회 성능을 극대화합니다.

3. 데이터베이스 물리 스키마 명세 (Prisma Schema)

플랫폼 구축에 직접 활용되는 8개 핵심 엔티티 스키마 코드입니다.

datasource db { provider = "postgresql" url = env("DATABASE_URL") } generator client { provider = "prisma-client-js" } // 1. 회원 정보 테이블 model User { id String @id @default(uuid()) email String @unique name String phone String role String @default("USER") // USER, ADMIN, COUNSELOR createdAt DateTime @default(now()) updatedAt DateTime @updatedAt guardians Guardian[] wills WillNote[] estates DigitalEstate[] reservations Reservation[] obituaries Obituary[] } // 2. 지정 수령인 (보호자) 테이블 model Guardian { id String @id @default(uuid()) userId String user User @relation(fields: [userId], references: [id], onDelete: Cascade) name String phone String relationship String // 자녀, 배우자, 친척 등 isVerified Boolean @default(false) createdAt DateTime @default(now()) } // 3. 디지털 유언장 & 엔딩노트 테이블 model WillNote { id String @id @default(uuid()) userId String user User @relation(fields: [userId], references: [id], onDelete: Cascade) title String encryptedContent String @db.Text // AES-256 암호화된 유언문 releaseCondition String // ON_DEATH_VERIFIED, SPECIFIC_DATE 등 isReleased Boolean @default(false) files WillFile[] createdAt DateTime @default(now()) updatedAt DateTime @updatedAt } // 4. 유언장 첨부 미디어 파일 테이블 (S3 연동) model WillFile { id String @id @default(uuid()) willId String will WillNote @relation(fields: [willId], references: [id], onDelete: Cascade) fileUrl String // S3 객체 URL fileType String // audio/mp4, video/mp4 등 fileSize Int createdAt DateTime @default(now()) } // 5. 디지털 유산 및 계정 테이블 model DigitalEstate { id String @id @default(uuid()) userId String user User @relation(fields: [userId], references: [id], onDelete: Cascade) platformName String // Naver, Google, Kakao, Instagram 등 category String // SNS, 금융, 구독 서비스 encryptedCredentials String? @db.Text actionType String @default("DELETE") // DELETE, TRANSFER, MEMORIALIZE createdAt DateTime @default(now()) } // 6. 장례식장 및 추모 시설 DB 테이블 model Facility { id String @id @default(uuid()) name String category String // FUNERAL_HOME, MEMORIAL_PARK, NATURAL_BURIAL address String phone String latitude Float? longitude Float? reservations Reservation[] createdAt DateTime @default(now()) } // 7. 상담 및 시설 예약 테이블 model Reservation { id String @id @default(uuid()) userId String user User @relation(fields: [userId], references: [id], onDelete: Cascade) facilityId String facility Facility @relation(fields: [facilityId], references: [id]) reservationDate DateTime status String @default("PENDING") // PENDING, CONFIRMED, CANCELLED notes String? @db.Text createdAt DateTime @default(now()) } // 8. 모바일 부고장 테이블 model Obituary { id String @id @default(uuid()) userId String user User @relation(fields: [userId], references: [id]) deceasedName String funeralHome String bankAccount String? createdAt DateTime @default(now()) }

4. 데이터 보안 & 암호화 아키텍처

🔑 1. 필드 레벨 암호화 (AES-256-GCM)
유언장 내용(`encryptedContent`)과 자격 증명(`encryptedCredentials`)은 데이터베이스 저장 전 백엔드 애플리케이션 단에서 **AES-256-GCM 알고리즘**으로 암호화된 후 저장됩니다. DB 관리자조차 실데이터 원문을 볼 수 없습니다.
🛡️ 2. 봉투 암호화 (Envelope Encryption)
Master Key(KEK)는 AWS KMS 또는 HashiCorp Vault와 같은 전용 키 관리 서비스에 보관하며, 사용자별 Data Encryption Key(DEK)를 주기적으로 로테이션하여 높은 보안 수준을 유지합니다.

5. 데이터베이스 단계별 구축 로드맵

  • 1

    Phase 1: DB 개발 환경 구축 & 마이그레이션 (1주차)

    Docker 기반 PostgreSQL 서버 구동, Node.js/NestJS 백엔드 프로젝트 초기화 및 `prisma migrate`를 통한 초기 스키마 생성.

  • 2

    Phase 2: 장례/추모 시설 공공 DB 데이터 시딩 (2주차)

    전국 장례식장, 추모공원, 봉안당 공공 데이터 수집 후 `prisma/seed.ts`를 활용한 시드 데이터 배치 이관.

  • 3

    Phase 3: AES-256 암호화 & S3 미디어 파이프라인 연동 (3주차)

    유언장 암복호화 유틸리티 구현 및 음성/영상 메모리얼 파일 업로드를 위한 AWS S3 Presigned URL 생성 로직 연동.

  • 4

    Phase 4: 백엔드 REST API CRUD 연동 & 인덱스 최적화 (4주차)

    프론트엔드(`eobom/frontend`)와 REST API 연동 및 주요 쿼리(위치 기반 장례식장 검색) 인덱스 성능 최적화.
