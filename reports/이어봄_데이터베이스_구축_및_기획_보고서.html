📌 1. 데이터베이스 기획 배경 및 목적

eobom 플랫폼은 생전 웰다잉 준비(엔딩노트/유산 관리)부터 임종 직후(장례/추모시설 예약), 그리고 사후(모바일 부고장/디지털 유품 정리)로 연결되는 **한국형 디지털 엔딩 토탈 케어 서비스**입니다.

본 기획서는 세부 백엔드 API 구현에 앞서 **데이터의 무결성**, **최고 수준의 보안(암호화)**, **대용량 미디어 파일과의 효율적 분리**를 보장하는 최적의 데이터베이스 아키텍처를 정의하는 것을 목적으로 합니다.

📋 2. 서비스 기능별 데이터 요구사항 (Data Requirements)

🔐 1) 디지털 유언장 & 엔딩노트

  • 보관 데이터: 사전연명의향서, 비밀 유언 텍스트, 음성/영상 메모리얼 파일 메타데이터.
  • 보안 및 무결성: 극비 데이터로서 DB 내 필드 단위 암호화(AES-256) 저장 필수.
  • 열람 제어: 작성자 본인 및 사후 지정 수령인(보호자)에 한해 열람 조건 충족 시 공개.

💼 2) 디지털 유산 & 계정 관리

  • 보관 데이터: SNS, 금융, 락커, 구독 서비스 플랫폼 계정 정보 및 사후 처리 방침.
  • 가변성 구조: 플랫폼마다 자격 증명 양식이 다르므로 JSONB 형태의 유연한 가변 속성 데이터 필요.
  • 상태 추적: 파기, 양도, 추모계정 전환 처리 이력에 대한 트랜잭션 보장.

🏛️ 3) 장례식장/추모공원 검색 & 예약

  • 보관 데이터: 전국 장례식장/봉안당/수목장 위치(위경도), 카테고리, 이용 요금, 1:1 상담 신청 내역.
  • 트랜잭션: 위치 기반 반경 검색(Spatial Index) 및 동시 예약 중복 방지(ACID) 적용.

📩 4) 모바일 부고장 & 조의록

  • 보관 데이터: 부고장 생성 정보, 고인/상주 명의, 빈소 주소, 조의금 계좌, 조문객 조의록.
  • 성능 요소: 순간적인 부고 알림 클릭 급증 시 빠른 읽기 성능(Read-Heavy) 보장.

⚖️ 3. 데이터베이스 종류별 장단점 비교 평가

평가 항목 RDBMS (PostgreSQL) ⭐ BaaS (Supabase) NoSQL (MongoDB) Hybrid (Postgres + S3) 🏆
ACID & 관계 무결성 최상 (외래키 & 엄격한 트랜잭션) 최상 (Postgres 기반) 보통 (문서 단위, FK 제한적) 최상 (메타데이터 무결성 완벽)
보안 및 접근 제어 우수 (Field Encryption) 최상 (Row Level Security RLS) 보통 (앱 서비스 단 처리) 최상 (DB 암호화 + S3 Presigned)
가변 데이터 (JSON) 우수 (JSONB 인덱싱 지원) 우수 (JSONB 지원) 최상 (Schema-less Document) 최상 (JSONB + 미디어 분리)
대용량 미디어 처리 부적합 (BLOB 부하) 우수 (Storage 제품 탑재) 제한적 (GridFS 복잡성) 최상 (S3 전문 분리)
개발 생산성 (ORM) 우수 (Prisma / TypeScript) 최상 (자동 REST/GraphQL) 우수 (Mongoose) 우수 (표준 프레임워크 호환)
종합 평가 및 판정 핵심 서비스 DB 1순위 빠른 MVP 구현 시 유용 관계형 구조 미흡으로 비추천 최종 채택 (Standard Architecture)

🏆 최종 아키텍처 채택 사유: PostgreSQL + Prisma ORM + AWS S3 하이브리드 구성

웰다잉 토탈 케어 서비스는 유언장, 예약 트랜잭션, 지정 수령인 간의 엄격한 관계형 무결성(Foreign Key)이 필수적입니다. 따라서 메인 RDBMS로 PostgreSQL을 사용하고, Prisma ORM을 채택하여 100% Type-Safe한 백엔드를 구축합니다. 또한 영상/음성 메모리얼 파일은 AWS S3 (또는 Supabase Storage)로 이관하고 DB에는 암호화 URL만 보관함으로써 DB 쿼리 성능과 스토리지 비용을 동시에 최적화합니다.

💻 4. 물리 데이터베이스 스키마 명세 (`schema.prisma`)

실제 백엔드 구축 시 사용되는 8개 핵심 엔티티 모델 스키마 정의입니다.

🔒 5. 데이터 보안 & 암호화 보호 전략

🔑 1) Field-Level Encryption (AES-256-GCM)

유언장 본문(`encryptedContent`) 및 유산 계정 자격 증명(`encryptedCredentials`)은 데이터베이스에 전달되기 전 백엔드 애플리케이션 단에서 **AES-256-GCM**으로 암호화됩니다. DB 관리자나 시스템 침해 시에도 원본 텍스트 유출이 불가능합니다.

🛡️ 2) Envelope Encryption (이중 봉투 암호화)

Master Key(KEK)는 AWS KMS 또는 Vault 하드웨어 보안 모듈에 보관하고, 사용자별 Data Encryption Key(DEK)를 분리 관리함으로써 보안 키 탈취 위험을 철저히 차단합니다.

🚀 6. 데이터베이스 단계별 구축 실행 로드맵

Phase 1: DB 개발 환경 구축 & ORM 마이그레이션 (1주차)

Docker 기반 PostgreSQL 서버 인스턴스 생성, 백엔드 프로젝트 내 Prisma ORM 연결 및 초기 마이그레이션 스크립트 실행.

Phase 2: 장례/추모 시설 공공 데이터 시딩 (2주차)

전국 주요 장례식장, 추모공원, 봉안당 공공 데이터를 수집하고 `prisma/seed.ts`를 통해 시드 데이터 일괄 구축.

Phase 3: AES-256 암호화 모듈 & S3 미디어 파이프라인 연동 (3주차)

유언장 암복호화 유틸리티 함수 작성 및 대용량 음성/영상 메모리얼 업로드를 위한 S3 Presigned URL 파이프라인 연동.

Phase 4: 백엔드 API 연동 & 위치/검색 인덱스 최적화 (4주차)

프론트엔드(`eobom/frontend`)와 REST API 통신 구현 및 위치 기반 장례식장 검색 쿼리 인덱스 성능 검증.
