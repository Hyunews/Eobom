1. 지금 상태 (사실관계)

  • Domain 03(디지털 유품 정리 · 추모관)은 백엔드 모델이 전혀 없습니다. schema.prisma에는 User 모델

하나만 있고, SNS 계정 삭제 신청·현물 유품 수거·추모관 방명록/헌화 등은 전부 DigitalEstatePage.tsx

안의 프론트 로컬 state(useState)로만 존재하는 100% 목업입니다.

  • 따라서 지금 시점에는 "운영자 대시보드에서 회원 클릭 시 03 도메인 데이터 확인"을 만들 수 있는 실제

DB 데이터가 없습니다. 이 문서는 나중에 03이 실제 백엔드로 구현될 때 지켜야 할 설계 원칙을

남겨두는 용도입니다.

2. 설계 원칙 (대표 제안, 2026-08-11)

디지털 유품·추모관 관련 데이터는 성격상 특정 회원(User)에 종속된 데이터입니다. 운영자가 회원을

검색해서 찾을 수 있다면, 그 회원을 클릭했을 때 연결된 도메인 데이터(예: SNS 삭제 신청 처리 현황,

추모관 방명록/헌화 이력 등)를 함께 확인할 수 있어야 합니다.

구현 시 반영할 것: 03 도메인의 신규 Prisma 모델(예: DigitalAccountRequest, MemorialGuestbook 등)은

전부 userId FK로 User와 연결되어야 합니다. 그래야 운영자 대시보드의 "회원 상세" 화면에서

prisma.user.findUnique({ where: { id }, include: { ... } }) 형태로 조인해서 한 화면에 보여줄 수 있습니다.

이 원칙은 05 도메인에도 동일하게 적용됩니다(→ 05-01 참고, 다만 05는 열람 범위에 별도 제약이 있음).

3. 보류된 것 — 현물 유품 수거·정리 업체

현물 유품 수거/정리를 어떤 사업자 형태로 다룰지(신규 계정 유형을 만들지, 기존 Partner/Expert를

확장할지, 외주 제휴사로 처리할지)는 기획이 아직 나오지 않아 보류합니다. 착수 전 반드시 [Claude:Opus]

기획 검토를 거쳐야 합니다 — 회원 유형을 잘못 설계하면(예: Expert에 억지로 끼워맞추기) 나중에

다시 뜯어고쳐야 할 가능성이 높습니다.
