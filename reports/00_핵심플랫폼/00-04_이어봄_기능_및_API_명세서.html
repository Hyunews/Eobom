🌿 공통 플랫폼 명세서 Doc #00-04

기능 및 REST API 명세서 (전체 지도)

6개 네임스페이스 엔드포인트 전체 인벤토리, 4종 토큰(aud) 인증 체계 및 구현 상태

문서 목적: 이어봄 백엔드(eobom/backend)의 전체 엔드포인트 지도입니다. 어떤 네임스페이스가 있고 무엇이 구현됐는지를 한눈에 보는 것이 목적이며, 요청/응답 상세 규격은 각 도메인 문서가 정본입니다.
상태 표기: ✅ 구현 / ⬜ 미구현(계획) / ❌ 폐기

🔑 0. 인증 체계 — 4종 토큰

JWT aud(audience) 클레임으로 주체를 구분하고, 미들웨어에서 교차 사용을 차단합니다. 다른 주체의 토큰으로 접근하면 401입니다.

aud 주체 계정 생성 경로 액세스 토큰 수명
userB2C 일반 유저소셜 로그인(카카오/네이버/구글)7일
partner장사시설 사업자/api/partner/signup → 운영자 승인2시간
expert전문가(4대 직역)/api/expert/signup → 운영자 승인2시간
admin내부 운영자공개 가입 없음 — prisma/seed-admin.ts 스크립트만2시간
  • 파트너·전문가·운영자는 리프레시 토큰(30일) 회전 방식입니다. 구 토큰 재사용은 401.
  • 프론트는 토큰 만료를 스스로 검사하지 않습니다. API가 401을 반환하면 그때 로그아웃 처리합니다.

📡 1. B2C 인증 (`/api/auth`) — 정본 00-08

상태 엔드포인트 설명
✅GET /api/auth/kakao · /naver · /google소셜 OAuth 리다이렉트
✅GET /api/auth/{provider}/callback인증 콜백 및 계정 연동/통합 처리
✅POST /api/auth/confirm-link이메일 중복 시 통합(MERGE) / 독립 생성(CREATE_NEW) 확정
✅GET /api/auth/me내 프로필 + 연동된 소셜 계정 목록
✅POST /api/auth/demo-login개발용. 프로덕션 가드 적용됨

🪦 2. 시설 (`/api/facilities`) — 정본 01-01, 01-05

상태 엔드포인트 설명
✅GET /api/facilities목록. 쿼리: category, tag, q, lat/lng, page, pageSize
✅GET /api/facilities/:id시설 상세
✅POST /api/facilities/:id/reviews리뷰·별점 작성 (로그인 필요, 1인 1리뷰)
✅POST /api/facilities/:id/quotes업체 문의 → leadNo(EB-YYMMDD-NNNN) 반환
❌POST /api/facilities/:id/bookings답사예약 — 삭제됨(→ 01-05 §4.1·§5.3)

🏢 4. 사업자 (`/api/partner`) — 정본 01-05 §6.1

가입·로그인·내정보·시설 클레임·사진 업로드는 ✅ 구현 완료. 리드 목록 조회 및 정산 관련 엔드포인트는 ⬜ 미구현 (수수료 기준 확정 대기).

⚖️ 5. 전문가 (`/api/expert`, `/api/experts`) — 정본 02-03 §5

네임스페이스 인증 내용
/api/experts (복수)없음공개 목록·상세, 상담 신청 (status=APPROVED AND isPublished=true만 반환)
/api/expert (단수)aud=expert가입·로그인·내정보, 받은 상담 신청 조회·상태변경

🛡️ 6. 운영자 (`/api/admin`) — 정본 01-05 §6.2 · 02-03 §5.4

인증, 사업자 심사·정보수정, 전문가 심사·공개토글·정보수정, 시설 클레임 심사, 상담 신청 전체 조회가 ✅ 구현되었습니다.
회원 정보 수정 범위 원칙: 담당자명·연락처·사무실주소 등 운영 편의 정보만 수정 허용하고, 사업자번호·자격증번호 등 검증된 신원 정보는 직접 수정 금지(반려 후 재신청 수순).
