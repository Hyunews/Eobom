⚡ 00-04. 기능 및 REST API 명세서 (전체 지도)

문서 목적: 이어봄 백엔드(eobom/backend)의 전체 엔드포인트 지도입니다. 어떤 네임스페이스가 있고 무엇이 구현됐는지를 한눈에 보는 것이 목적이며, 요청/응답 상세 규격은 각 도메인 문서가 정본입니다(→ .harness/AGENTS.md §7 "같은 문서를 두 곳에 복사하지 않는다").

>

2026-08-11 전면 갱신: 기존 문서는 /api/auth·/api/facilities 두 개만 다루고 있었고, 그 사이 추가된 파트너·전문가·운영자 네임스페이스 30여 개 엔드포인트가 통째로 누락돼 있었습니다. 또 이미 삭제된 답사예약 API가 남아 있었습니다.

상태 표기: ✅ 구현 / ⬜ 미구현(계획) / ❌ 폐기

🔑 0. 인증 체계 — 4종 토큰

JWT aud(audience) 클레임으로 주체를 구분하고, 미들웨어에서 교차 사용을 차단합니다. 다른 주체의 토큰으로 접근하면 401입니다.

`aud`주체계정 생성 경로액세스 토큰 수명
userB2C 일반 유저소셜 로그인(카카오/네이버/구글)7일
partner장사시설 사업자/api/partner/signup → 운영자 승인2시간
expert전문가(4대 직역)/api/expert/signup → 운영자 승인2시간
admin내부 운영자**공개 가입 없음** — prisma/seed-admin.ts 스크립트만2시간
  • 파트너·전문가·운영자는 리프레시 토큰(30일) 회전 방식입니다. 구 토큰 재사용은 401.
  • 프론트는 토큰 만료를 스스로 검사하지 않습니다. API가 401을 반환하면 그때 로그아웃 처리합니다 — 이 처리가 없으면 토큰이 죽어도 화면은 로그인된 것처럼 보이면서 데이터만 비는 버그가 납니다(2026-08-11 실제 발생·수정).
  • 상세 원칙 → 01-05 §6.4

📡 1. B2C 인증 (`/api/auth`) — 정본 `00-08`

엔드포인트설명
✅ 구현GET /api/auth/kakao · /naver · /google소셜 OAuth 리다이렉트
✅ 구현GET /api/auth/{provider}/callback인증 콜백 및 계정 연동/통합 처리
✅ 구현POST /api/auth/confirm-link이메일 중복 시 통합(MERGE) / 독립 생성(CREATE_NEW) 확정
✅ 구현GET /api/auth/me내 프로필 + 연동된 소셜 계정 목록
✅ 구현POST /api/auth/demo-login개발용. **프로덕션 가드 적용됨**

🪦 2. 시설 (`/api/facilities`) — 정본 `01-01`, `01-05`

엔드포인트설명
✅ 구현GET /api/facilities목록. 쿼리: category, tag, q(이름), lat/lng(거리순), page, pageSize
✅ 구현GET /api/facilities/:id시설 상세
✅ 구현POST /api/facilities/:id/reviews리뷰·별점 작성 (로그인 필요, 1인 1리뷰)
✅ 구현POST /api/facilities/:id/quotes**업체 문의** → leadNo(EB-YYMMDD-NNNN) 반환. 동의 없으면 400
❌~~POST /api/facilities/:id/bookings~~답사예약 — **삭제됨**(→ 01-05 §4.1·§5.3)
  • 필터 간소화(2026-08-10): 예산·종교·하객수·지역 대분류 필터 제거. 삭제된 파라미터가 들어와도 무시하고 크래시하지 않습니다.
  • 운영자 대시보드의 "전체 시설" 탭도 이 공개 API를 그대로 재사용합니다(별도 어드민 API 없음).

🗺️ 3. 지역·지도 (`/api/geo`) — 정본 `01-02`

엔드포인트설명
✅ 구현GET /api/geo/regions시/도 · 시/군/구 드롭다운 목록
  • 전남·광주는 전남광주통합특별시 한 키로 병합 표기합니다. 다만 카카오 API는 옛 행정구역명 기준이라, 지오코딩 호출 직전에만 옛 명칭으로 되돌려 보냅니다(표시명 ≠ 조회명 이원화).

🏢 4. 사업자 (`/api/partner`) — **정본 `01-05` §6.1**

가입·로그인·내정보·시설 클레임·사진 업로드는 ✅ 구현. 리드 조회와 정산 관련 엔드포인트는 ⬜ 미구현(수수료 기준 확정 대기 → 01-05 §10-1).

사진 업로드는 현재 로컬 디스크 저장이라 배포 시 재배포마다 파일이 사라집니다. 실서비스 전 외부 스토리지 전환 필수(→ .harness/systems.md §5).

⚖️ 5. 전문가 (`/api/expert`, `/api/experts`) — **정본 `02-03` §5**

네임스페이스인증내용
/api/experts (복수)없음공개 목록·상세, 상담 신청. **status=APPROVED AND isPublished=true만** 노출
/api/expert (단수)aud=expert가입·로그인·내정보, 받은 상담 신청 조회·상태변경
  • 공개 API는 select 화이트리스트로 passwordHash·settlementAccount·licenseDocUrl·contactPhone 등을 차단합니다. 사무실 주소(officeAddress)는 공개 대상입니다(→ 02-03 §4.3).
  • 미승인·미공개 전문가 조회는 403이 아니라 404(존재 자체를 숨김).
  • ConsultRequest에는 과금 컬럼을 두지 않습니다 — 변호사법 제34조 가드레일(→ 02-03 §3.2).
