🎯 2. 범위 (Stage 1 = 무과금 루프)

Domain01에서 리드 인프라를 먼저 깔고 정산은 나중에 한 것과 같은 순서를 따릅니다 (→ 01-05).

  • 승인된 전문가 공개 목록/상세 API + CounselingPage 실연동
  • 상담 신청(ConsultRequest) 접수 — 개인정보 제3자 제공 동의 포함
  • 전문가 대시보드에서 받은 상담 신청 목록 조회 및 상태 변경
  • 신청번호 발번(EC-YYMMDD-NNNN)

⚖️ 3. 변호사법 가드레일 (설계의 제1 제약)

  1. ConsultRequest에 과금 필드를 두지 않는다. billable·billedAmount 등 컬럼 배제 — 없는 필드는 실수로 채워질 수 없음.
  2. 과금은 별도 테이블로 분리한다 (Stage 2). LAWYER 카테고리는 과금 테이블에서 배제.
  3. 월정액은 상담 건수와 완전히 무관해야 한다. 고정 광고료 성격 유지.
  4. 변호사 프로필에 성과·성공보수 표현 금지.

🗄️ 4. 데이터 모델

4.1 ConsultRequest & 4.2 ConsultNumberCounter

EC-YYMMDD-NNNN 발번. Lead 및 LeadNumberCounter와 별도 테이블로 분리. 과금 컬럼 전무.

4.3 Expert 모델 보강

  • consultRequests ConsultRequest[] 관계 추가
  • isPublished Boolean @default(false) 추가 — 승인(status=APPROVED)과 공개 노출을 독립 플래그로 분리.
  • officeAddress String? 추가 (2026-08-11 신설) — 사무실 주소. 4대 직역(변호사/세무사/행정사/장례지도사) 공용 필드로 설계. 공개 API 화이트리스트에서 제외하지 않고 정보 제공.

🔌 5. API 명세 (구현 완료)

5.1 공개 API

  • GET /api/experts & GET /api/experts/:id (status=APPROVED AND isPublished=true만 반환)
  • 민감 필드 제외 화이트리스트 필수: passwordHash, refreshTokenHash, settlementBank, settlementAccount, licenseDocUrl, contactPhone, rejectReason 전면 제외.

5.2 상담 신청 & 5.3 전문가 본인 & 5.4 운영자 API

  • POST /api/experts/:id/consult-requests: 동의 미체크 시 400, 미승인/미공개 전문가는 404.
  • GET/PATCH /api/expert/consult-requests: 소유권 검증 (남의 신청 403).
  • GET/PATCH /api/admin/experts: isPublished 토글 (미승인 시 400), PATCH /api/admin/experts/:id(연락처·사무실 주소·소개 인라인 수정 허용, 자격증 번호 등 신원 정보 수정 금지).
