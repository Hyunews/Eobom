## 1. 이 폴더는 무엇인가 — **기존 기록과 어떻게 다른가**

이미 기록 장소가 여럿 있습니다. **겹치면 아무도 안 봅니다.** 경계를 먼저 못박습니다.

| 장소 | 담는 것 | 찾는 방식 |
| :--- | :--- | :--- |
| `walkthrough.md` | **무엇을 했는가** — 구현 단위 검증 게이트 | 작업 번호 |
| `작업일지_및_기록/26MMDD.md` | **그날 무슨 일이 있었나** | 날짜 |
| `.harness/_meta/` | **하네스 자체**의 결정 경위 | 규칙 이름 |
| `docs/` 도메인 문서 | **어떻게 동작해야 하는가**(정본 스펙) | 기능 |
| 🆕 **여기** | 🔴 **증상 → 원인 → 조치 → 재발 방지** | **증상**(§3 표) |

> 🔴 **핵심 차이는 "증상으로 찾는다"입니다.** 나머지는 전부 *"내가 무엇을 했는지 알고 있을 때"* 찾는 색인입니다. 트러블슈팅은 **원인을 모르는 상태에서 증상만 들고 오는 사람**을 위한 것입니다.

### 1.1 무엇을 여기 쓰나

- ✅ **원인이 짐작과 달랐던 것** — 이게 제일 값집니다
- ✅ **조용히 실패하는 것**(에러가 안 나는 것)
- ✅ **함정** — 문서대로 했는데 다른 결과가 나오는 자리
- ❌ 평범한 버그 수정 → `walkthrough.md`로 충분
- ❌ 하네스 규칙 논의 → `_meta/`

### 1.2 🔴 누가 쓰나 — 소유권

`docs/`는 **Opus만 씁니다**(`AGENTS.md` §2). 그런데 문제를 실제로 밟는 쪽은 대개 Sonnet입니다.

```
[Sonnet] 발견 → walkthrough.md `편차` 또는 `다음 에이전트가 알아야 할 것`에 기록
          ↓
[Opus]   판정 후 여기로 승격 (TS 번호 부여)
```

**Sonnet은 이 폴더에 직접 쓰지 않습니다.** 정본 스펙(`00-33`·`00-34`)이 만들어진 경로와 같습니다.

## 2. 양식

새 항목은 `TS-NNN_짧은제목.md`로 만들고 **아래 6개 필드를 전부 채웁니다.**

```markdown
# TS-NNN. 제목

| | |
| :--- | :--- |
| **발생·발견** | 2026-MM-DD · 누가/무엇을 하다가 |
| **영역** | backend / frontend / DB / 하네스 / 인프라 |
| **심각도** | 🔴 데이터 손상·조용한 실패 / 🟡 기능 오작동 / 🟢 불편 |
| **상태** | ✅ 닫힘 / ⏸ 완화만 / 🔴 열림 |

## 1. 증상 — 눈에 보인 것
🔴 검색될 만한 **문구·에러 메시지·화면 표현 그대로** 적을 것.

## 2. 원인 — 실제로 무엇이었나
🔴 **짐작과 달랐다면 그 차이를 적을 것.** 이게 이 문서의 값이다.

## 3. 어떻게 찾았나
재현 방법·확인한 명령·계측 수치. 다음 사람이 같은 방법으로 확인할 수 있어야 한다.

## 4. 조치

## 5. 🔴 재발 방지 — 무엇으로 닫았나
| 수단 | 내용 |
| :--- | :--- |
| 코드 가드 | |
| 문서·스펙 | |
| 규칙 | |
> 🔴 **"주의하겠다"는 재발 방지가 아니다.** 셋 중 하나로 닫히지 않았으면 §6에 적는다.

## 6. 남은 위험
없으면 "없음"이라고 명시할 것. 비워두지 않는다.
```
