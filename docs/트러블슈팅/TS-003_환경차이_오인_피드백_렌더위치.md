# TS-003. "dev에선 뜨는데 배포에선 안 뜬다" — 환경 차이가 아니라 렌더 위치였다

| | |
| :--- | :--- |
| **발생·발견** | 2026-09-03 · 사람이 `SCR-018`(내 부고장·추모관) 실기동 검증 중 |
| **영역** | frontend |
| **심각도** | 🟢 불편 — 기능은 동작했고 **피드백 문구만 눈에 안 들어옴** |
| **상태** | ✅ **닫힘** — wt114에서 카드별 상태로 분리 |

## 1. 증상 — 눈에 보인 것

내 부고장 목록(`SCR-018`)에서 **"주소 복사"를 눌러도 복사 완료 문구가 안 뜬다.**
사람이 보고한 문장 그대로: **"클립보드 복사 문구 안뜸(dev에서는 뜨나 실제 페이지에선 안뜸)"**.
복사 자체는 됐다 — 붙여넣으면 주소가 나왔다. **안 뜬 것은 문구뿐**이다.

## 2. 원인 — 실제로 무엇이었나

🔴 **환경 차이가 아니었다.** dev↔배포(HTTPS·클립보드 권한·`navigator.clipboard` 폴백)를 의심하기
딱 좋은 증상이었지만, 실제 원인은 **렌더 위치**였다.

`MyObituaryListPage`의 피드백 문구가 **전역 `shareFeedback: string` 하나**였고, 그리는 자리도
`.map()` **바깥쪽 목록 하단**이었다. 그래서 문구는 **항상 마지막 카드 밖(목록 맨 아래)** 에 떴다.

- **dev에서 "떴던" 이유**: 카드가 1개뿐이라 목록 하단 = 그 카드 바로 아래였다. **우연히 맞았다.**
- **배포에서 "안 뜬 이유"**: 카드가 여러 개라 문구가 방금 누른 카드에서 멀리 떨어진 곳에 떴다.
  스크롤 밖이면 아예 안 보인다.

즉 **dev/배포가 아니라 "카드 1개 / 여러 개"가 갈랐다.** 같은 코드가 데이터 개수에 따라 다르게 보였다.

## 3. 어떻게 찾았나

사람이 두 번째로 보고한 문장이 결정적이었다 — **"여러개의 추모관 있을 때, 해당 div 아래에 떠야
하는데 상위 하단에 떠"**. "안 뜬다"가 아니라 **"엉뚱한 데 뜬다"** 로 증상이 바뀌는 순간 환경
가설이 무너졌다. 재현은 **부고장을 2개 이상 만들고 첫 번째 카드의 "주소 복사"** 를 누르면 된다 —
문구가 목록 맨 아래에 나타난다.

## 4. 조치

wt114(`eobom/frontend/src/pages/MyObituaryListPage.tsx`) — 전역 `shareFeedback: string`을
**`feedback: {id, message} | null`** 로 바꿔 어느 카드에서 눌렀는지를 함께 들고 다니게 하고,
렌더 위치를 `.map()` 안(해당 카드 내부)으로 옮겼다. `tsc --noEmit`(frontend) 0건.

## 5. 🔴 재발 방지 — 무엇으로 닫았나

| 수단 | 내용 |
| :--- | :--- |
| 코드 가드 | ❌ 없음 — 린트로 잡히는 종류가 아니다 |
| 문서·스펙 | 🆕 이 문서 — **증상("dev에선 되는데 배포에선 안 된다")으로 찾을 수 있는 색인** |
| 규칙 | 🔵 **목록(`.map()`) 안에서 일어난 동작의 피드백은 항목별 상태로 들고 다닌다.** 전역 문자열 하나면 항목이 1개일 때만 맞는다 |

## 6. 남은 것 — 🔴 진짜 교훈은 따로 있다

**"dev에선 되는데 배포에선 안 된다"는 말이 나오면 환경부터 의심하게 되는데, 이번엔 틀렸다.**
갈랐던 건 환경이 아니라 **데이터 개수**였다. dev는 시드 1건, 배포는 실제 데이터 여러 건이라
**목록 UI는 개수에서 갈리는 버그가 환경 차이로 위장된다.**

🟡 같은 위장이 남아 있을 만한 곳: 목록 화면에서 **전역 상태 하나로 피드백·에러·로딩을 그리는
자리**. 발견하면 여기에 덧붙인다.
