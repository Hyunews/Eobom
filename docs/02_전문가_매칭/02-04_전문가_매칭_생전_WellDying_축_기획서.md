## 📌 1. 문제 — 02는 이미 생전 업무를 하고 있는데, 문서가 그걸 모릅니다

### 1.1 기존 문서에 생전 업무가 이미 섞여 있습니다

`02-01` §2의 4대 버티컬 표를 다시 읽으면 **사후 업무가 아닌 항목이 이미 들어 있습니다.**

| 직역 | `02-01` §2에 적힌 자문 영역 | 실제 시점 |
| :--- | :--- | :--- |
| 변호사 | **"유언장 법적 효력 검토"** | **생전** — 유언은 살아 있을 때 씁니다 |
| 변호사 | 유류분 반환 청구, 유산분할협의서 | 사후 |
| 장례지도사 | **"맞춤 장례 예산 수립"** | **생전 가능** — 사전 장례 계획 |
| 세무사 | 상속세 시뮬레이션·세무조사 대치 | 사후 |
| 행정사 | 사망자 계정 삭제, 안심상속 조회 | 사후 |

**항목은 있는데 화법이 전부 사후입니다.** `02-01` §1 도메인 정의(*"상속세, 유산 분할, 유언장
법적 효력, 디지털 유품 대행, 장례 절차"*)도, `02-03`의 `ConsultRequest` 설계도 마찬가지입니다.
그래서 **생전 축이 있다는 사실 자체가 인식된 적이 없습니다.**

### 1.2 🔴 화면은 이미 약속했는데, 문서에도 스키마에도 없습니다

✅ **해소됨(2026-10-08 확인).** 이 절이 지적한 두 문제는 둘 다 닫혔습니다.

1. 홈 화면(`HomePage.tsx`)에는 지금 *"유언장 작성 가이드 및 공증 법무사 매칭"* 문구가 없습니다(홈 재설계 — `00-40`). 유언장 작성 도움은 엔딩노트 ⑨ "유언장 초안"이 맡습니다(06).
2. 법무사는 **5번째 직역으로 추가**됐습니다(08-14, `02-05` §3 · 개발자 확정 09-29) — 이 절의 권고("직역을 늘리지 말 것")와 반대로 정해졌습니다.

유언 공증은 **공증인**(공증인법)의 직무라는 점은 그대로입니다(`02-05` §3.1). 처음 진단·권고는 부록 §1.2.

### 1.3 🔴 "유언"이라는 단어의 면책 비대칭

"유언"이라는 단어를 쓰는 화면은 **법적 효력이 없다는 사실을 함께 알려야** 합니다. 지금 화면(2026-10-08 코드 확인):

| 화면 | 문구 | 면책 |
| :--- | :--- | :---: |
| `TaxSimulatorModal`(SCR-005) | 세액 추정 | ✅ *"이 결과는 참고용 추정치이며 **법적 효력이 없습니다**"* |
| `EndingNotePage`(SCR-002) ⑨ 유언장 초안 | *"유언장 초안"* | ✅ *"이 화면에서 만든 글은 유언장이 아닙니다. 자필증서 유언은 반드시 손으로 직접 쓰셔야 하며…"*(`endingNote/constants.tsx` `NOT_A_WILL_NOTICE`) + 자필증서 4대 요건 안내 |
| `EndingNotePage` 유언장 사진 보관 | 사진 보관 | ✅ *"사진은 사본이며 효력은 손으로 쓴 원본에만 있습니다"*(`WillPhotoUploadModal`·`WillPhotoVault`) |
| `EndingNotePage` 연명의료 메모 | 메모 | ✅ *"이 메모는 법적 효력이 없습니다"* |

*"유언 메시지"*·*"유언 편지"*·*"소중한 유언을 보관하세요"* 같은 문구는 지금 화면에 없습니다. 처음 비대칭 표(면책 ❌ 2곳)는 부록 §1.3.
엔딩노트 쪽 정본 = `06-02` §4(유언 방식) · `06-06`(유언장 사진 보관).

법적 유언은 민법 제1065~1072조의 **5가지 방식(자필증서·녹음·공정증서·비밀증서·구수증서)** 을
엄격히 따라야 효력이 생깁니다. **앱 입력창에 친 텍스트는 그중 어디에도 해당하지 않습니다** —
자필증서만 해도 전문·연월일·주소·성명을 **직접 손으로 쓰고 날인**해야 합니다.

> 🔴 **위험**: 이용자가 *"이어봄에 유언을 남겨뒀으니 됐다"* 고 믿고 실제 유언장을 만들지 않으면,
> 사후에 그 의사는 **법적으로 아무 효력이 없습니다.** 그리고 그 사실은 **되돌릴 수 없는 시점에
> 드러납니다.** `07-01` §1.2(상속포기 누락)와 같은 종류의 위험입니다.

**이것이 02의 생전 축에서 가장 중요한 지점입니다** — §3에서 다룹니다.

## 🔀 2. 생전 상담은 사후 상담과 무엇이 다른가

### 2.1 ✅ 4직역별 생전 / 사후 대비

| 직역 | **WellDying (생전)** | 유가족 (사후) |
| :--- | :--- | :--- |
| **변호사** | **유언장 작성·방식 선택·검토**, 유류분 사전 대비, 사전연명의료의향서 | 유류분 반환청구, 유산분할협의, 상속 분쟁 |
| **세무사** | **사전 증여 설계**(10년 합산 규정), 상속세 사전 시뮬레이션 | 상속세 신고·납부, 세무조사 대응 |
| **행정사** | **생전 위임 문서화**(→ §4) | 사망자 계정 정리, 안심상속 원스톱 |
| **장례지도사** | **사전 장례 계획**, 봉안당·수목장 사전 계약 | 장례 진행, 장지 선정 |

**4직역 전부 생전 업무가 있습니다.** 02가 "양쪽"인 것은 예외가 아니라 이 도메인의 본래 성격입니다.

### 2.2 ✅ 상담의 성격이 다릅니다

| | **생전 상담** | 사후 상담 |
| :--- | :--- | :--- |
| 심리 | 여유·신중·미룰 수 있음 | 긴급·경황 없음 |
| 시점 | 무기한 | D+0 ~ 6개월(기한 있음 — `07-01` §3.1) |
| 회수 | **반복** — 유언 갱신, 증여 설계 조정 | 대체로 1회성 |
| 이탈 사유 | **"나중에 하지"** | 없음(닥쳐서 함) |
| 가격 민감도 | 낮음(절세 효과가 상담료를 압도) | 높음 |

> **생전 축의 유일한 적은 "미루기"입니다.** 사후 상담은 안 하면 큰일 나니까 하지만, 생전 상담은
> 안 해도 당장 아무 일도 안 일어납니다. **그래서 02 단독으로는 생전 유입이 잘 안 생깁니다** —
> **06(엔딩노트)에서 넘어오는 흐름이 필요합니다.**

## 🔗 3. ✅ 06(엔딩노트)과의 경계 — 이 축의 핵심

### 3.1 앱에 쓴 글은 유언이 아닙니다

§1.3의 결론입니다. **06은 "유언"이 아니라 "유언 메시지(비법정)"를 다룹니다.**

| | Domain 06 엔딩노트 | Domain 02 변호사 |
| :--- | :--- | :--- |
| 산출물 | **마음·정보 전달** (편지, 계좌 위치, 연명의료 의향) | **법적 효력 있는 유언장** |
| 효력 | 법적 효력 **없음** | 민법 §1065~1072 요건 충족 |
| 다루는 것 | *"이걸 알아둬라"* | *"재산을 이렇게 나눠라"* |

**둘은 대체재가 아니라 보완재입니다.** 06이 02를 대신할 수 없고, 02가 06을 대신할 수도 없습니다
(변호사가 자녀에게 남길 편지를 써주지는 않습니다). 06 쪽 상세(유언 5방식 중 현실적인 2개 · A+C 권고)는 `06-02` §4.

### 3.2 ✅ 그래서 06 → 02 연결이 **선택이 아니라 필수**입니다

> **✅ 원칙: 06에서 재산 처분 의사가 감지되면 02로 안내합니다.**

- 엔딩노트 작성 화면에 **"법적 효력 안내"를 상시 노출**합니다 — `TaxSimulatorModal` 수준의 면책
  (§1.3)이 **최소선**입니다.
- *"재산을 누구에게 얼마나"* 에 해당하는 입력에는 **"법적 유언장이 따로 필요합니다 → 상속 변호사
  상담"** 을 붙입니다.
- 새 API를 만들지 않고 기존 `POST /api/experts/:id/consult-requests`를 씁니다(`02-03` §5.2).
  `content`에 맥락을 프리필하면 전문가가 바로 파악합니다 — **`04-01` §3.4·`07-01` §6과 동일한 패턴**입니다.

> 🔴 **지금 상태(10-08)**: 첫째 줄(법적 효력 안내)은 ✅ 구현(§1.3 표). 둘째 줄(*"법적 유언장이 따로 필요합니다 → 상속 변호사 상담"* 안내·링크)은 **미구현** —
> 엔딩노트 화면(`EndingNotePage.tsx`·`components/endingNote/`)에 전문가 상담으로 가는 연결이 없습니다. 미결 `02-03` §10.1 #2.

> 🔵 **이 연결은 `00-12` §7.2의 승계 원칙과 충돌하지 않습니다.** §7.2가 금지한 것은 *"02가 고인의
> 상담 이력을 유족에게 승계하는 것"* 입니다. 여기서는 **살아 있는 본인이 스스로 02로 가는 것**이라
> 승계가 아닙니다. 방향이 반대입니다.

### 3.3 반대 방향 — 02 → 06

변호사와 유언장을 만든 사람에게 **"유언장에 담지 못한 이야기는 엔딩노트에"** 를 안내합니다.
법적 유언장은 형식이 엄격해서 **감정·설명·비밀번호 같은 것을 담을 수 없습니다.** 자리가 다릅니다.

> 🟡 **10-08 4단계 — 미구현**(10-01 코드 대조 불일치: `CounselingPage` 등 02 화면에 06 안내 0건). 이 안내가 놓일 자리는
> *"변호사와 유언장을 만든 뒤"* 인데, 지금 이어봄 화면은 **상담 신청까지만** 있고 상담이 끝난 뒤의 화면이 없다.
> → **상담 이후 화면(상담 완료·후기 등)을 만들 때 같이 넣는다.** 그 전에 신청 화면에 미리 붙이지 않는다 — 아직 유언장을 만들지 않은 사람에게 "담지 못한 이야기"를 말하게 된다.

## 🤝 4. ✅ 04(정산)와의 경계 — `00-12` §2.4 ②가 기댈 자리

`00-12` §2.4는 생전 위임의 처리 방식 ②를 **"행정사 처리 — `02-01` 기존 검토 활용"** 이라고 적었습니다.
**그런데 그 "기존 검토"는 사후 관점뿐입니다**(§1.1) — 생전에 본인이 행정사에게 위임하는 흐름이
02 문서에 없습니다. **②가 기댈 자리가 비어 있었습니다.**

| | 사후 위임(현행 `04-01` §3.4) | **생전 위임(②) — 이 문서가 채움** |
| :--- | :--- | :--- |
| 누가 | 유족이 사후에 의뢰 | **본인이 생전에 지정** |
| 법적 무게 | 유족의 자격 증명 필요 | **본인 의사가 직접 남아 있음** |
| 02의 역할 | 상담 연결 | **위임 의사 문서화 + 수임 행정사 지정** |

> ✅ **생전 위임의 문서화 형식 — 2026-08-14 `04-02`가 답함.** 요지: **법정 서식은 없고**, 민법 §690(위임인 사망 시 종료)은
> 특약으로 바꿀 수 있으며, **문제는 형식이 아니라 "그릇"**(위임은 재산 처분에 못 미침 — `04-02` §1·§2). 남은 유료 검토는 `04-02` §7.
> 처음 🔴 박스(법률 검토 대상 · `00-12` §8-1에 묶기 권고)는 부록 §4.

## 🗄️ 5. 🟡 데이터 모델 — `ConsultRequest`에 맥락 축 추가

현행 `ConsultRequest`(`02-03` §4.1)는 **생전/사후를 구분하지 않습니다.** `categorySnapshot`은
직역만 담습니다.

**그래서 전문가는 "상속세 신고 문의"인지 "사전 증여 설계 문의"인지 모른 채 신청을 받습니다.**
준비할 자료도, 상담 시간도, 가격대도 완전히 다릅니다.

```prisma
model ConsultRequest {
  // ... 기존 필드 (02-03 §4.1)
  contextType String @default("POST_DEATH")  // PRE_DEATH | POST_DEATH — 02-04 §5
}
```

- **기본값을 `POST_DEATH`로** 두어 기존 데이터·기존 흐름이 그대로 유효합니다(마이그레이션 무해).
- 전문가 대시보드(`BizDashboard`) 목록에 **뱃지로 표시**합니다.
- 🔵 **이 필드는 `00-12` §6.2 모드 판정의 재료도 됩니다** — 생전 상담을 신청했다는 것은
  "이 사람은 지금 WellDying 모드"라는 강한 신호입니다.

**과금 필드는 여전히 만들지 않습니다** — `02-03` §3.2-1 가드레일은 이 축에서도 그대로입니다.

## 💰 6. 🟡 수익 구조 — 생전 축이 사후보다 유리합니다

| | 생전 | 사후 |
| :--- | :--- | :--- |
| Tier 2 반복 구매 | ⭕ 유언 갱신·증여 설계 조정 | ❌ 대체로 1회 |
| **Tier 4 전환**(`02-01` §3.4) | ⭕ **사전 증여 설계 = 수천만원대 절세와 직결** | 🟡 상속세 신고 대행 |
| 가격 저항 | 낮음 | 높음(경황 없는 지출) |
| 전문가 만족도 | 높음(예약 가능한 일정) | 낮음(긴급·야간) |

### 6.1 그리고 생전 고객은 미래의 유족 고객을 데려옵니다

생전 회원이 **지정 유족을 등록해두면**(`00-12` §2.3), 그 사람이 사후에 플랫폼으로 들어옵니다.
**`00-12` §7.3이 미결로 남긴 "발견" 문제의 유일한 자연 해법이 이것입니다** — 02 생전 상담이
지정 유족 등록의 실질적 계기가 될 수 있습니다.

> 🟡 다만 **Tier 2~4는 전부 PG 연동이 필요해 사장님 승인 대상**입니다(`02-03` §2.2).
> 이 문서도 **Stage 1(무과금 루프) 범위 안에서만** 착수합니다.

## ⚖️ 7. ✅ 변호사법 가드레일 — 생전에도 그대로입니다

**새로 만들 것이 없습니다.** 유언장 작성 상담도 변호사 업무이므로 `02-03` §3의 4개 조치가 동일하게
적용됩니다 — 과금 필드 미생성, 과금 테이블 분리, 월정액과 건수 무관, 성과 표현 금지.
**법무사도 같게 적용합니다** — 법무사법 확인 전까지 변호사와 동일 취급(`02-05` §3.2).

§1.2의 "공증 법무사" 문구 경고는 문구가 화면에서 사라져 닫혔습니다(부록 §7).
