## 🔍 2. 원인 — 실측

### 2.1 인라인 스타일이 3배 많습니다

```
eobom/frontend/src/**/*.tsx
  style={{  …………………………………  982곳
  className= ……………………………  361곳
```

**미디어쿼리는 스타일시트에만 존재할 수 있습니다.** 인라인 `style` 속성에는 `@media`를 넣을
문법 자체가 없습니다. 즉 지금 화면 요소의 **약 3/4은 폭이 좁아져도 반응할 방법이 없습니다.**

`index.css`에 미디어쿼리가 **9개** 있지만, 이들이 손댈 수 있는 건 `className`을 가진 나머지
1/4뿐입니다. 그래서 *"고쳤는데도 여전히 안 보인다"* 가 반복됩니다 — 고칠 수 있는 부분만
고쳐 왔기 때문입니다.

### 2.2 좁은 폭을 직접 깨뜨리는 값들

인라인으로 **고정 픽셀·고정 단수**를 박아둔 곳이 20개 파일 35곳입니다.

| 패턴 | 무슨 일이 나나 | 대표 위치 |
| :--- | :--- | :--- |
| `minmax(300px, 1fr)` | 375px 화면에서 좌우 여백을 빼면 300px가 안 나와 **가로 스크롤** | `MemorialPage.tsx:80` · `CounselingPage` · `EndingNotePage` |
| `gridTemplateColumns: 'repeat(3, 1fr)'` | 3칸이 그대로 유지돼 숫자·라벨이 **한 글자씩 세로로** 쪼개짐 | `MyPage.tsx:169`(예약중/상담내역/보관문서 카운터) |
| `fontSize: '2rem'` 페이지 제목 | 32px 제목 + 아이콘 32px가 한 줄을 다 먹음 | `CareGuidePage` · `MemorialPage` 등 페이지 헤더 공통 |
| `width: '84px'` 등 고정 | 프로필·아이콘 블록이 안 줄어 옆 텍스트를 밀어냄 | `MyPage.tsx` 프로필 카드 |

### 2.3 🔵 이미 잘 돼 있는 것 — 여기는 손대지 않습니다

**`ObituaryLandingPage.tsx`(조문객이 카톡으로 여는 화면)는 모바일 우선으로 작성돼 있습니다.**
`maxWidth: 360~480px` 중앙 정렬 카드 구조라, 넓은 화면에서 카드가 가운데 놓일 뿐 좁은 화면에서
깨지지 않습니다(08-21 `부고장페이지_최적화` 커밋 반영분 포함).

> ✅ **이게 중요한 근거입니다.** 이 프로젝트가 모바일을 못 하는 게 아니라, **모바일을 전제로 쓴
> 화면만 모바일에서 멀쩡합니다.** 나머지는 데스크톱을 보며 인라인으로 쌓아 올렸습니다.

## 📲 4. "웹앱(PWA)"에 대한 정직한 답

실제로 주는 것과 지금 아쉬운 것이 겹치지 않습니다.

| PWA가 주는 것 | 지금 문제와 관계 |

| 홈 화면 아이콘 설치 | ❌ 무관 |

## 🛠️ 6. 전환 방식 — 세 단계

### 6.1 1단계 · 반응형 프리미티브를 `index.css`에 만든다 (선행 1회)

페이지를 고치기 전에, **페이지들이 공통으로 반복하는 4가지 패턴**을 클래스로 뽑습니다.
이게 없으면 페이지마다 다른 브레이크포인트를 쓰게 되고, 그게 지금 상태의 재생산입니다.

| 클래스 | 대체하는 인라인 패턴 | 동작 |
| :--- | :--- | :--- |
| `.page-title` | `fontSize:'2rem'` 페이지 헤더 | `clamp(1.4rem, 5vw, 2rem)` |
| `.auto-grid` | `minmax(300px,1fr)` | `minmax(min(280px, 100%), 1fr)` — **100% 폴백이 가로 스크롤을 막는 핵심** |
| `.stat-row` | `repeat(3,1fr)` 카운터 | ≤480px에서 3열 유지하되 숫자/라벨 축소, ≤360px 1열 |
| `.stack-sm` | `display:flex` 가로 배치 카드 | ≤640px에서 `flex-direction: column` |

> ⚠️ **브레이크포인트를 새로 만들지 않습니다.** `index.css`가 이미 쓰는 **480 / 640 / 768**
> 세 개만 씁니다(현재 9개 미디어쿼리가 이 값들을 씁니다). 네 번째 값을 도입하는 순간
> 어디서 접히는지 아무도 예측 못 하게 됩니다.

### 6.2 2단계 · 페이지별 이관 (§5 순서대로)

**한 페이지를 통째로 다시 쓰지 않습니다.** 그 페이지에서 §2.2 표에 걸리는 인라인 값만
1단계 클래스로 바꿉니다. 나머지 인라인(색·여백·정렬)은 그대로 둡니다 — 좁은 폭에서
깨지지 않는 값들이기 때문입니다.

> ✅ **판정 기준을 하나로 둡니다: `375px`에서 가로 스크롤이 생기지 않고 본문 글자가 15px 이상.**
> (375px = iPhone SE/미니 계열 실폭. 이보다 좁은 기기는 대응 대상에서 제외합니다.)

### 6.3 3단계 · 새 코드 규칙 — 다시 쌓이지 않게

🔴 **이관보다 이 규칙이 중요합니다.** 규칙이 없으면 §5를 다 끝낸 다음 달에 같은 상태가 됩니다.

> **새로 쓰는 코드에서 §2.2의 4개 패턴(고정 px 폭 · `minmax(≥300px)` · `repeat(n,1fr)` 고정 ·
> `fontSize ≥ 1.5rem`)은 인라인으로 쓰지 않는다. 1단계 클래스를 쓴다.**
> 색·여백 등 나머지 인라인 스타일은 계속 허용합니다 — **전면 금지는 지키지 못할 규칙입니다.**
