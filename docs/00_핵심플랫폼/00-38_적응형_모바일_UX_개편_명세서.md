## 📐 3. 5대 원칙 — ✅ 확정 (재검토 없음)

사용자 확인이 끝난 항목이다. **각 원칙에 측정 가능한 값을 붙여** DoD(§11)로 이어붙인다.

### 3.1 원칙 1 — 360px 최저선 · **헤더와 본문의 여백을 분리한다**

| | 값 | 근거 |
| :--- | :---: | :--- |
| 최저 기준폭 | **360px** | `00-29` §8 #3이 정한 375px에서 **하향**. Galaxy S 계열·안드로이드 보급기의 실폭 |
| 본문 좌우(`.container`) | **28px** | 360 − 56 = **본문 폭 304px** ≈ 한글 16px에서 **줄당 19자** — 국문 가독 적정대(18~25자) 안 |
| 헤더·크롬 좌우 | **16px** | 헤더는 읽는 면이 아니라 **잡는 면**이다. 28px를 주면 로고+모드+프로필이 328px에 안 들어간다 |
| ≤359px 안전판 | 본문 **20px** | 320px(구형 SE)은 지원 대상이 아니나(`00-29` §8 #3) **깨지지는 않게** 둔다 |

> 🔴 **"헤더 ≠ 본문"이 이 원칙의 핵심이다.** 지금은 `.container` 하나가 둘 다 맡고 있어,
> 본문을 넓히면 헤더가 깨지고 헤더를 맞추면 본문이 좁아진다. **토큰을 둘로 나눈다**(§4.1).

### 3.2 원칙 2 — 🔴 **모바일 18px 기준선 폐기 → 본문 16px 표준**

`00-09` §2.3이 *"협상 대상이 아님"* 으로 못박은 `--base-font-size: 18px`를 **폐기한다.**

| | |
| :--- | :--- |
| **폐기하는 것** | `@media (max-width:768px) { html { font-size: 18px } }` — `00-29` §12 **조치 A** (`index.css:274~278`) |
| **폐기 이유** | 🔴 **값이 아니라 전파 방식이 틀렸다.** 루트를 올리면 `fontSize` 377곳뿐 아니라 **`padding`/`margin`/`gap` 869곳이 같이 12.5% 커진다**(`00-29` §12.2 실측). 360px에서 이 12.5%가 곧 좌우 여백이다 — **글자를 키우려다 여백을 잃었다** |
| **대신 하는 것** | 루트는 **16px 고정**. 본문은 `--fs-body: 1rem`(=**16px**)로 **절대값을 못박는다**. 여백은 `px` 토큰(§4.1) |
| **행간** | 본문 **1.8** · 몰입 리더 **1.9** (`00-09` §2.3의 `1.7`을 개정) |

> 🔴 **시니어 접근성이 후퇴하는가 — 정직하게 적는다.**
> `00-29` §11이 실측한 대로, **18px 기준선은 화면에 한 번도 적용된 적이 없다.** 조치 A 이전 실제 본문은
> **12~13.6px**였고, 조치 A 이후(2026-08-25~) 약 17.1px다. **16px는 프로젝트 전 기간 대비 개선이고,
> 최근 2주 대비로는 1.1px 후퇴다.** 그 1.1px과 맞바꾸는 것이 **좌우 28px 여백 · 행간 1.8 · 1열 몰입 리더**다.
> 🔵 **글자를 더 키우고 싶은 사용자의 경로는 막히지 않는다** — 타입이 전부 `rem`이라 브라우저 확대와
> OS 글꼴 크기 설정이 정상 동작한다. 루트를 고정한다는 것은 **우리가 임의로 올리지 않는다**는 뜻이지
> 사용자가 못 올린다는 뜻이 아니다.
> 🔴 **`--min-touch-target: 56px`는 유지한다** — §2.3의 3개 토큰 중 이것만 남는다.

### 3.3 원칙 3 — 탈박스화 · 위계는 **간격으로만**

| 🔴 금지 | ✅ 대신 |
| :--- | :--- |
| 회색 테두리 박스 안의 박스(**박스-in-박스**) | 섹션 사이 **≥40px** 마진 + 필요하면 **1px 구분선** |
| 그림자 표면의 중첩 | 그림자는 **한 화면에 1단계만**(`00-09` §6.3 #3 재확인) |
| 카테고리 박스 > 항목 박스 3중 중첩 | 카테고리는 **텍스트 헤더 또는 칩**, 항목은 **행(row)** |

### 3.4 원칙 4 — 상단 크롬 감량

- 🔴 **배지·설명·경고배너가 4~5단으로 쌓이지 않는다.** 첫 화면에서 **콘텐츠 첫 줄까지 ≤1스크롤**.
- ✅ **법적 고지·면책은 최하단 또는 모달**로 내린다. *"차단 배너"* 형태를 쓰지 않는다.
- 🟡 예외: **되돌릴 수 없음 경고**(`07-04` §4.3 상단 고정 배너)는 **1개까지** 상단에 남는다.

### 3.5 원칙 5 — 2단계 노출 (목록 → 몰입 리더)

```
[목록]  날짜 + 한 줄 제목 …… 그게 전부다
   └ 탭 → [전체화면 몰입형 리더]  본문·행간 1.9·좌우 28px·닫기만
```

- ✅ 적용 대상: **읽을 본문이 있는 것**(엔딩노트 섹션·유족 메시지·법적 고지).
- 🔴 **적용하지 않는 것**: `CareGuidePage` 체크리스트 — `07-04` §8-8이 **펼칠 상세를 이미 없앴다.**
  카드 2줄이 곧 전체다. **감출 것이 없는 목록에 2단계를 씌우면 클릭만 늘어난다**(§9).

## 🎛️ 4. 전역 CSS 토큰 — 개정본

🔴 **단위 규칙은 `00-09` §6.2를 그대로 계승한다: 타입은 `rem`, 간격은 `px`.**
이번 개정은 그 규칙을 **루트까지 밀어붙인 것**이다.

### 4.1 🆕 여백 토큰 — 신설 5개

```css
:root {
  /* 간격 — 00-09 §6.2의 6칸을 유지하고 2칸을 잇는다. 규칙: --sp-N = N × 4px */
  --sp-10: 40px;   /* 🆕 섹션 사이 최소 간격 (원칙 3) */
  --sp-14: 56px;   /* 🆕 화면 단위 구분 · 리더 상하 여백 */

  /* 🆕 적응형 거터 — 헤더와 본문을 분리한다 (원칙 1) */
  --gutter-page:   28px;  /* 본문 .container 좌우 (모바일) */
  --gutter-chrome: 16px;  /* 헤더·드로어·바텀시트 손잡이 좌우 */
  --gutter-page-sm: 20px; /* ≤359px 안전판 */
}
```

**`.container` 개정** — 현재 `index.css:251~270`을 대체한다.

| 구간 | 현재 | ✅ 개정 |
| :--- | :--- | :--- |
| 기본(데스크톱) | `padding: 120px` | **변경 없음** |
| ≤768px | `32px 24px` | **`var(--sp-10) var(--gutter-page)`** = `40px 28px` |
| ≤480px | `28px 20px` | *(구간 삭제 — 위 구간이 흡수)* |
| ≤359px | — | 🆕 `padding-left/right: var(--gutter-page-sm)` |

🔴 **헤더·`Sidebar`·`.mobile-drawer-panel`·바텀시트는 `--gutter-chrome`(16px)을 쓴다.**
`.container`의 거터를 상속받지 않게 **명시**한다 — 이 분리가 원칙 1의 전부다.

### 4.2 ✅ 타입 스케일 — `00-09` §6.2 개정 (루트 16px 기준)

```css
:root {
  --fs-caption: 0.875rem;                      /* 14px — 보조 하한. 이보다 작게 쓰지 않는다 */
  --fs-body:    1rem;                          /* 16px — 본문 표준 */
  --fs-lead:    1.125rem;                      /* 18px — 리드문·리더 본문 */
  --fs-section: 1.25rem;                       /* 20px — 섹션 제목 */
  --fs-title:   clamp(1.375rem, 4.5vw, 1.75rem);  /* 22 → 28px */
  --fs-display: clamp(1.625rem, 6vw, 2.25rem);    /* 26 → 36px */
}
```

| 토큰 | 기존(루트 18px) | 개정(루트 16px) | 360px 실효 | 판정 |
| :--- | :---: | :---: | :---: | :---: |
| `--fs-caption` | 0.85rem = 15.3px | **0.875rem** | **14px** | 🟡 −1.3px (보조 텍스트만) |
| `--fs-body` | 0.95rem = 17.1px | **1rem** | **16px** | 🟡 −1.1px (§3.2에서 감수) |
| `--fs-lead` | 1.05rem = 18.9px | **1.125rem** | **18px** | ≈ |
| `--fs-section` | 1.3rem = 23.4px | **1.25rem** | **20px** | 🟡 −3.4px |
| `--fs-title` | 27~34px | clamp | **22 → 28px** | ✅ 의도 — 원칙 4(크롬 감량) |
| `--fs-display` | 34~47px | clamp | **26 → 36px** | ✅ 의도 |

### 4.3 🆕 행간 토큰 — 신설 3개

```css
:root {
  --lh-tight:  1.35;  /* 제목 */
  --lh-body:   1.8;   /* 본문 기본 — 00-09 §2.3의 1.7을 개정 */
  --lh-reader: 1.9;   /* 몰입 리더·긴 글 (원칙 5) */
}

```

### 4.4 🔴 폐기·정정 목록 — `index.css`

| # | 대상 | 조치 |
| :---: | :--- | :--- |
| 1 | `--base-font-size: 18px` (`:22`) | 🔴 **폐기** — 선언 삭제 |
| 2 | `@media (max-width:768px){ html{font-size:var(--base-font-size)} }` (`:274~278`) | 🔴 **블록 삭제** = `00-29` §12 조치 A 철회 |
| 3 | `body { font-size: var(--base-font-size) }` (`:103`) | → `font-size: var(--fs-body)` |
| 4 | `body { line-height: 1.7 }` (`:104`) | → `var(--lh-body)` |
| 5 | `--min-touch-target: 56px` (`:22`) | ✅ **유지** |
| 6 | `.container` ≤480px 구간 (`:265~270`) | 🔴 삭제 (§4.1이 흡수) |

### 4.5 🔴 차단 리스크 — 소형 `rem` 리터럴 **441곳**

루트를 16px로 되돌리면 코드에 남은 `0.85rem` 이하 리터럴이 **전부 11% 더 작아진다.**
`0.85rem` → **13.6px**, `0.8rem` → **12.8px**. `00-29` §11이 잡아낸 문제가 **그대로 재발한다.**

🔴 **따라서 §4.4 #2(조치 A 철회)와 아래 치환은 같은 커밋이어야 한다.** 나눠서 배포하지 않는다.

#### ✅ 치환 규칙 — **기계적이고, 어떤 값도 작아지지 않는다**

| 기존 리터럴 | → | 실효 변화 |
| :--- | :--- | :--- |
| `0.85rem` · `0.8rem` | **`var(--fs-body)`** | 15.3 / 14.4 → **16px** (↑) |
| `0.78rem` · `0.75rem` · `0.7rem` | **`var(--fs-caption)`** | 14.0 / 13.5 / 12.6 → **14px** (=·↑) |

- **판단이 필요 없다** — 값만 보고 바꾼다. 모든 결과가 기존 이상이므로 화면별 검수 부담이 낮다.
- 🔴 **제외**: `AdminPage.tsx`(80) · `BizDashboard.tsx`(37) · `PartnerPortalPage.tsx`(6) = **123곳**.
  `00-09` §2.5 밀도 우선 예외이며, **조치 A가 ≤768px에만 걸려 있었으므로 이 세 화면은 영향이 없다.**
- 대상은 나머지 **약 318곳 / 38개 파일**.
- 🟡 `1.1rem`·`1.3rem` 등 큰 값은 이번에 건드리지 않는다 — 11% 줄어도 `--fs-section`(20px) 위다.

## 🪝 5. `useIsMobile` 훅 명세

### 5.1 시그니처

```ts
// eobom/frontend/src/hooks/useIsMobile.ts
export function useIsMobile(maxWidth: number = 768): boolean;
```

| 항목 | 스펙 |
| :--- | :--- |
| **인자** | `maxWidth` — **모바일로 간주할 최대 폭(inclusive)**. 기본 **768** |
| **질의** | `window.matchMedia(\`(max-width: ${maxWidth}px)\`)` |
| **왜 inclusive 768인가** | `index.css`의 지배적 브레이크포인트가 `@media (max-width: 768px)`다. 여기에 맞춰야 **768px 정확히에서 JS와 CSS가 어긋나지 않는다** |
| **초기값** | 🔴 **lazy initializer로 즉시 평가**한다(`useState(() => mql.matches)`). `useEffect`에서 처음 계산하면 **데스크톱 뷰가 한 프레임 그려졌다 바뀐다** |
| **SSR** | 없다(Vite SPA). `typeof window` 가드는 넣지 않는다 — 죽은 코드다 |
| **구독** | `addEventListener('change', …)` + cleanup. 🟡 **`addListener` 폴백을 둔다** — 주 페르소나가 6070이라 구형 iOS Safari(≤13) 비중을 0으로 볼 수 없다 |
| **의존성** | `[maxWidth]`. 🔴 호출부는 **리터럴만** 넘긴다 — 계산식을 넘기면 매 렌더 재구독된다 |

### 5.2 🔴 기존 `matchMedia` 호출부 — 훅으로 통일하되 **값은 바꾸지 않는다**

| 위치 | 현재 | 조치 |
| :--- | :--- | :--- |

## 🧩 6. 적응형 뷰 분리 패턴

### 6.1 구조

```
pages/XxxPage.tsx  ← 라우트가 가리키는 곳. URL 그대로.
 ├── 데이터 로딩 · API 호출 · 상태(useState) · 핸들러 …… 🔴 여기 1벌만
 ├── const isMobile = useIsMobile();
 └── return isMobile ? <XxxMobileView {...vm} /> : <XxxDesktopView {...vm} />

components/<domain>/XxxDesktopView.tsx   ← 표현만. 상태 없음.
components/<domain>/XxxMobileView.tsx    ← 표현만. 상태 없음.
```

- **파일 위치**: `components/<domain>/` — `00-35` §4.1이 세운 관례(`components/endingNote/`·`facility/`·`home/`)를 따른다. **barrel(`index.ts`) 만들지 않는다.**
- **`vm`(뷰모델)**: 두 뷰가 **같은 props 타입**을 받는다. 타입은 `components/<domain>/types.ts`에 둔다.

### 6.2 🔴 지켜야 할 것 — 4개

| # | 규칙 | 왜 |
| :---: | :--- | :--- |
| **1** | 🔴 **상태·입력값은 부모에만 둔다. 뷰는 controlled.** | 조건부 렌더는 **형제 교체**라 폭이 바뀌면 자식이 언마운트된다. 뷰가 값을 들고 있으면 **회전·창 크기 변경에 입력이 사라진다** — `00-35` §9 C와 같은 위험 |
| **2** | 🔴 **`fetch`/`useEffect`를 뷰에 두지 않는다.** | 두 벌이 되면 전환 시 **재요청**이 뜬다 |
| **3** | 🔴 **뷰 컴포넌트를 부모 함수 안에 정의하지 않는다.** | `00-35` §6.1 기존 규칙. 매 렌더 새 타입 = 전체 재마운트 |
| **4** | 🟡 **`XxxDesktopView`는 기존 JSX를 그대로 옮긴다.** | 데스크톱 회귀 0이 DoD다(§11 #8). 옮기면서 고치지 않는다 |

### 6.3 ❌ 하지 않는 것

- ❌ **URL 분리** (`/m/...` 없음) — 라우팅·`00-13` 공유링크·SEO에 영향 0이어야 한다.
- ❌ **UA 스니핑** — 폭으로만 판정한다.
- ❌ **전 페이지 일괄 분리** — 분리는 **비용**이다. §8이 지정한 페이지만 나눈다.
- ❌ **모바일 전용 동선·기능** — `00-29` §3 ②의 판단(하지 않음)을 유지한다. **같은 데이터·다른 배치**까지다.

### 6.4 ✅ 허용되는 가로 스크롤 — `00-29`의 "가로 스크롤 0"과 충돌하지 않는다

`06-04` §6.1-1 ③이 *"탭 9~10개는 가로 스크롤이라 `00-29`를 정면으로 깬다"* 고 적었다. **둘은 다른 것이다.**

| | 판정 |
| :--- | :--- |
| 🔴 **문서(`body`) 가로 오버플로** | **금지.** DoD #1. `00-29` §10.1이 확보한 것이 이것이다 |
| ✅ **명시적 `overflow-x:auto` 트랙** (카테고리 칩 등) | **허용.** 아래 3조건 전부 충족 시 |

1. 트랙 우측에서 **다음 항목이 잘려 보이거나** 페이드가 걸려 *"더 있다"* 가 드러날 것.
2. 🔴 **그 트랙이 유일한 도달 경로가 아닐 것** — 칩은 **필터·점프**이고, 스크롤만으로도 전체에 닿는다.
3. 트랙 자신이 화면 폭을 넘기지 않을 것(`width:100%; overflow-x:auto`).

> 🔵 **탭이 금지된 이유는 가로 스크롤이 아니라 조건 2였다** — 탭은 *"안 열어본 탭"* 을 만든다.
> 칩은 목록을 감추지 않으므로 `06-04` §6.1-1의 ①(빠짐없이)을 깨지 않는다.

## ✅ 9. 상중행정가이드 체크리스트 — 인터랙션 모델 **확정**

> 요청: *"체크박스를 유지할지, 탭=완료이고 상세는 별도 진입인지 등 대안 검토. 목업의 임시 수정은
> 최소 패치일 뿐 최종 패턴 판단 필요."*

### 9.1 대안 4개와 판정

| 안 | 내용 | 판정 |
| :---: | :--- | :--- |
| A | 체크박스 유지 · 체크박스만 히트 영역 (**현행**) | ❌ **15px 히트 영역**은 `--min-touch-target`(56px) 정면 위반. 목업의 15px 축소는 폭 확보가 목적이었으나 **터치 정확도를 대가로 냈다** |
| B | **탭 = 완료** · 상세는 별도 진입(원칙 5 적용) | ❌ 🔴 **감출 상세가 없다.** `07-04` §8-8이 아코디언을 없애 카드는 이미 2줄이고, 11개는 펼쳐도 빈 서랍이었다. **2단계를 다시 씌우면 §8-8이 되돌아온다** |
| C | 체크박스 없이 **탭 = 완료**, 완료는 색·취소선으로 | ❌ `00-23` §8.7 **색만으로 구분 금지**. 완료 상태의 시각 어포던스가 사라져 *"눌리는 것인지"* 를 6070이 판단할 근거가 없다 |
| **D** | ✅ **체크박스 유지 · 히트 영역을 행 전체로** · 액션은 별도 버튼 | ✅ **채택** |

### 9.2 ✅ 채택안 D — 스펙

```
┌─────────────────────────────────────────┐
│ ☐  한정승인 또는 상속포기   [3개월] ⭐되돌릴 수 없음  │  ← 행 전체가 토글 (≥56px)
│    지나면 빚을 그대로 물려받습니다                │
│                            [전문가 상담 →]     │  ← 별도 히트 영역
└─────────────────────────────────────────┘
 ▎← 좌측 3px 색선 (CRITICAL만)
```

| 항목 | 값 |
| :--- | :--- |
| 체크박스 **시각** 크기 | **20px** (목업 15px에서 **정정**) |
| **히트 영역** | 🔴 **행 전체**, 최소 높이 `var(--min-touch-target)` = **56px** |
| 행 탭 동작 | **완료 토글** |
| 액션 링크(6개 항목) | 🔴 **별도 `<button>`**, `stopPropagation`. 자체 히트 영역 ≥44px |
| 행 사이 | 구분선 1px, 상하 패딩 `var(--sp-3)`(12px) |
| 항목 좌우 | `var(--gutter-page)`(28px) — 체크박스 포함 |
| 텍스트 폭 | 360 − 28×2 − (20 + 12) = **272px** |
| 중복 화살표 | 🔴 **제거**(목업 결정 유지) — 행 자체가 탭 대상이므로 화살표는 거짓 신호다 |

> 🔵 **목업의 15px를 20px로 되돌려도 텍스트 폭은 잃지 않는다.** 폭 손실의 원인은 체크박스 크기가 아니라
> **중복 화살표와 3중 박스 패딩**이었고, 그 둘이 사라진다. 20 vs 15px의 차이는 272px 중 **5px(1.8%)** 다.
> 대신 얻는 것이 **히트 영역 15px → 56px**이다. 🔴 **작은 것을 지키려고 큰 것을 내주지 않는다.**

### 9.3 🔴 CRITICAL 표기 — `07-04` §5.1 정정

목업의 *"좌측 3px 색선 + 별 하나"* 는 **글자 배지를 뺐다.** `00-23` §8.7과 `07-04` §5.1이
*"색만으로 구분하지 않는다 — ⭐ + 글자 + 테두리 3중"* 을 이미 정해 두었다.

✅ **모바일 확정형**: **⭐ + `되돌릴 수 없음` 글자 + 좌측 3px 색선** — 셋 다 남기되,
글자 배지를 **박스형 배지에서 인라인 텍스트로** 바꿔 기한 배지와 **한 줄에** 둔다(원칙 3 탈박스화).
🔵 *"굵은 테두리 → 3px 색선"* 은 채택한다. 줄인 것은 **테두리 굵기이지 정보가 아니다.**

### 9.4 ⏸ 저장(F단계)과의 관계

체크 상태 저장(`07-04` §3.4·§8-7-4 F단계)은 **`00-19` 제4조 확정에 막혀 있다.**
🔵 **이 인터랙션 모델은 F단계와 독립이다** — 프론트 전용이므로 **먼저 가도 된다**(`07-04` §8-8-5).
🔴 다만 저장이 붙기 전까지는 *"체크했는데 없어졌다"* 가 남는다는 사실이 바뀌지 않는다.
**완료 개수를 성과처럼 강조하지 않는다**(§8-8-3 ③ 분모 변경은 F단계 뒤로).
