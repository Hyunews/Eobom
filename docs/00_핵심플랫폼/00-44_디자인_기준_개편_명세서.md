## 📐 5. 레이아웃 — 확정값

### 5-1. 폭과 여백

| | 데스크톱 | 모바일 |
| :--- | :---: | :---: |
| 시안 판 크기(가정) | 1280 × 800 | 390 × 844 |
| **본문 최대 폭** | **1120px**, 가운데 | 화면 폭 − 좌우 여백 |
| 좌우 여백 | 1280 화면에서 **80px**(= (1280 − 1120) ÷ 2) · 창이 좁아지면 줄어 **최소 40px** | **24px** |
| 읽기 폭(긴 글 문단) | **764px** 상한 | 화면 폭 − 여백 |
| 누를 수 있는 가장 작은 크기 | **44 × 44px** | 같음 |

- 🔴 **큰 화면 규칙(2026-10-15 개발자, A안)**: 본문 최대 폭을 **1120px로 고정하고 가운데** 둔다. 큰 화면에서는 양옆 여백만 늘고, 안쪽 칸(2단 화면 포함)은 늘어나지 않는다. 기각 = 화면 폭 따라 늘리기 · 구현 때 판단.
- 🔴 **높이는 내용만큼**이다. 화면 높이를 꽉 채우는 것은 **랜딩 첫 화면 하나뿐**이다(🔵 예외 = 랜딩의 소개 구간, 10-21 — 정본 `00-45` §2·§6-1). 빈 칸·목록을 아래로 늘리지 않는다.
- 🔴 **구현 확인은 1280·1920 두 폭**으로 시안과 대조한다.
- 지금 코드의 폭(`index.css` `.container` 최대 1440·여백 120 → 본문 최대 1200, `00-39` §5의 본문 상자 1048)은 새 디자인에서 이 표로 바뀐다.

### 5-2. 창이 좁아질 때

- 🔴 **이용자·조문객·사업자 화면은 좌우 스크롤을 만들지 않는다.** 창이 좁아지면 여백 → 본문 순으로 줄고, 모바일 배치로 넘어간다. 최소폭(`min-width`)으로 화면을 붙잡지 않는다(`00-39` §5-0의 기준을 그대로 잇는다).
- 모바일 배치로 넘어가는 폭은 지금 코드 기준(**767px 이하**)을 그대로 쓴다.
- 🔵 **운영자 화면(`/admin`)만 예외 — 데스크톱 전용, 최소폭 1200px**(좁으면 좌우 스크롤, 상단 바도 같은 틀). 표가 많아 줄이면 더 못 읽는다. 🔄 **로그인 화면은 예외의 예외** — 운영자 로그인은 휴대폰 폭에 맞춘다(6단계 확정 ① "로그인만 한 쌍", 판 6-13). 즉 **로그인 전 화면만 좁은 폭에 맞추고, 로그인 뒤는 최소폭 1200 그대로**다. 이 줄이 `00-39` §5-0-1 "로그인 화면에서도 상단 바 1200 유지"(10-13)를 새 디자인에서 바꾼다.
- 사업자 화면(`/partner`)은 🔄 **6단계 시안으로 바뀌었다**(2026-10-21 캔버스 대조 — 처음 적은 *"입구 560 · 대시보드 720"* 은 `00-39` §5-0-2 옛 값): **입구** = 데스크톱 두 칸(왼쪽 안내 460 + 오른쪽 카드 최대 600, 사이 60) · 모바일 한 열 / **대시보드** = **왼쪽 메뉴 260 + 본문**(나머지 폭) · 모바일은 메뉴를 머리 아래 한 줄 탭으로. 운영자 대시보드도 왼쪽 메뉴 260(최소폭 1200은 위 줄). 사업자는 최소폭 없음(`00-39` §5-0-2와 같음). 화면 정본 = `01-05` §14 · `02-03` §7.3-1 · `00-37` §4.1.

### 5-3. 본문 폭 안의 2단

2단은 본문 폭(1120) **안에서** 나눈다. 큰 화면에서도 칸이 늘지 않는다(§5-1). 767px 이하에서는 **1단**이다.

| 화면 | 데스크톱 2단 | 모바일 |
| :--- | :--- | :--- |
| 쓰는 화면 `입력 | 미리보기`(부고장 만들기) | 입력 열 **560px** + 오른쪽 미리보기(스크롤을 따라옴) | 1단, 미리보기는 폼 안(확인 사항 앞) |
| 업체 자세히 보기(`/facility/:id`) | 왼쪽 나머지 + 오른쪽 **360px**(위치·[상담], 스크롤을 따라옴) | 1단, [상담]은 바닥 고정 줄 |

- 미리보기가 없는 폼도 입력 열은 560px에 두고 왼쪽 정렬한다. 입력칸을 본문 폭으로 늘리지 않는다.
- 두 열 사이 간격 등 세부 치수는 각 화면 캔버스 판의 값을 따른다(기능 문서가 판을 가리킨다).

## 🧩 6. 규칙

각 규칙은 시안 0~6단계에서 정해진 것이다. 괄호 안은 출처나 이유다. **`00-39` §6에서 그대로 이어받은 규칙**은 "(`00-39` 규칙 N)"으로 적고, **새 디자인에서 바뀐 규칙**은 🔄로 적는다.
🔵 번호(6-N-M)는 다른 문서가 `00-44 §6-4-3`처럼 가리킨다. 지운 번호는 비워 두고 다시 쓰지 않는다.

### 6-1. 화면 종류부터 고른다

목록이라고 다 같은 목록이 아니다. 아래 셋 중 어디에 속하는지에 따라 §6-2·§6-5 규칙이 갈린다(`00-39` §6 머리 표).

| 종류 | 하는 일 | 새 디자인 생김새 | 예시 판 |
| :--- | :--- | :--- | :--- |
| **훑는 목록** | 위에서 아래로 훑고 체크한다 | 카드 없음. 위 먹색 실선 + 줄 사이 점선(§7-2 목록 줄·체크리스트 줄) | 2-1 상중 행정 가이드 |
| **고르는 목록** | 여럿을 비교해 하나를 고른다 | **평 카드** 묶음(§7-2 카드) 또는 목록 줄 | 2-6 장사시설 · 2-4 유품 정리 |
| **쓰는 화면** | 값을 넣는다 | §8 | 2-12·2-13 부고장 만들기 |

### 6-2. 구조

1. **훑는 목록에는 카드와 그림자를 쓰지 않는다.** 구분은 선과 여백으로 한다(`00-39` 규칙 1).
2. **고르는 목록은 카드를 쓴다.** 🔄 카드 겉모양은 §3의 **두 가지뿐**(평 카드 · 종이 카드)이다. `00-39` 규칙 1-1의 "그림자·호버는 화면마다 고른다"는 새 디자인에서 닫는다 — 목록 카드는 평 카드이고, 그림자는 강조할 칸에만(화면당 1~2개) 준다.
3. **면 안에 면을 두지 않는다.** 테두리나 그림자가 있는 칸 안에 같은 것을 또 두지 않는다(`00-39` 규칙 1-1 "중첩 표면 0").
4. **같은 목록을 한 화면에서 두 번 보여 주지 않는다**(개편 §4-1, 랜딩의 바로 보기 ↔ 차례 중복).
5. **경고·안내는 한 화면에 겹쳐 두지 않는다.** 해당하는 곳(탭·구간)에 하나씩 둔다(개편 §4-1).
6. **상태 화면을 처음부터 같이 만든다** — 로그인 전 · 빈 화면 · 불러오는 중 · 실패 · 완료(§7-7). 시안이 그렸는데 코드에 없는 상태는 구현 때 만든다.

### 6-3. 글과 문구

1. **목록 한 줄 = 제목 + 정보 한 줄.** 정보 줄에는 기한·상태·개수 같은 **사실**만 둔다. 설명문은 두지 않고, 필요하면 제목을 눌러 창으로 본다(`00-39` 규칙 6-1 · 9).
2. **평가하는 말을 쓰지 않는다**("AI 어투 금지", `00-39` 규칙 6-2). 화면은 무엇이 나오는지·언제까지인지만 적는다. 강조는 자리·굵기·위험 색으로 하고 형용사로 하지 않는다.
3. 🆕 **화면 글에 대시(—)를 쓰지 않는다**(2026-10-15 개발자, AI 투). 대시가 있으면 빼고 문장·괄호·쌍점으로 나눈다. 예: "링크로만 공개(주소를 아는 사람만)" · "3개월 : 상속개시·채무초과를 안 날부터". 정본 예시 = `04-01` §0.2.
4. **안내 문구는 한 줄이 원칙이다.** 길면 줄바꿈하지 않고 문구를 줄인다(개편 §4-1).
5. **줄바꿈을 코드에 박지 않는다**(`00-39` 규칙 13). 데스크톱 제목 한 줄 규칙은 §4.
6. **버튼 글자는 하는 일로 쓴다** — 저장하기 · 보내기 · 삭제하기. 확인 창도 "확인/취소" 대신 "그대로 두기 / 요청 취소"처럼 쓴다. 버튼 하나짜리 알림 창의 [확인]만 예외(0단계 02·07).
7. 🆕 **로그인 안내는 한 틀이다**(2026-10-15 개발자, 모든 가림막·로그인 요구 창): 제목 **"로그인이 필요합니다"** + **"[화면 이름]은(는) 로그인 후 이용 가능합니다."** + [로그인]. 지금 코드 `LoginGate`("로그인이 필요한 회원 전용 서비스입니다." · [로그인 / 회원가입 하러가기])와 `00-34` §2.4 문구는 구현 때 이 틀로 바꾼다.
8. **보조 표시는 최소한이다.** 쪽번호·단계 이름처럼 같은 정보가 다른 곳에 있으면 뺀다(개편 §4-1).
9. **기능 설명은 실제 코드에 있는 기능만, 쉬운 말로** 쓴다(OCR → "사진의 글자를 읽어 옮김").
10. 🆕 **이용자에게 보이는 글에 "섹션"을 쓰지 않는다** — "구간"·"항목" 등 화면에 맞는 말로(4단계 묶음 1 점검). 남은 곳 4종은 8단계 코드 목록으로 넘긴다(`이어봄_디자인_4단계_목록.md` 묶음 1 점검). ✅ 10-22 묶음 4: 엔딩노트 공개 수 한 줄·가족 없음 안내 끝. ✅ 10-23 묶음 8: 탈퇴 창 "엔딩노트 항목 N개" 끝. 남은 것 = 서버 오류 글 "알 수 없는 섹션입니다."(`endingNoteController.ts`, 10단계).
11. 🆕 **날짜와 시각은 "10월 13일 15:20"으로 쓴다**(24시 · 쌍점, 2026-10-23 묶음 8 편차 ① — 시안 4-13 "15:20 접수"·저장 줄 "마지막 저장 10월 14일 15:20"과 같게). 지금 코드 함수 `formatKstMonthDayTime`의 "15시 20분"은 새 화면에서 쓰지 않는다(옛 화면은 교체 때 함께 사라진다).

### 6-4. 긴급도와 상태 표시

1. 🔄 **딱지는 두 가지다**(0단계 06 "표시 딱지"). **테두리 딱지 = 상태**(공개 중 · 닫힘 · 작성 중 · 되돌릴 수 없음) · **채운 딱지 = 기한 임박(위험 색)과 "예시"만**. `00-39` 규칙 5("긴급도를 색 배지로 만들지 않는다, 12px 붉은 글자 한 줄")를 바꾼다. 옛 규칙이 막으려던 것(모든 항목에 배지가 붙어 위계가 사라짐)은 **채운 딱지를 두 경우로만 묶어서** 막는다. 🆕 끝난 상태(추모관 *종료됨* · 상담 *종료*)는 **회색 테두리 딱지**(작은 글자색 · 선 색 · 보통 굵기) — `RdBadge`의 종류로 둔다(10-22 묶음 7 편차 ⑦, `00-36` §4.8-1 "종료됨 = 회색").
2. **색만으로 구분하지 않는다.** 위험·완료 색을 쓰면 글로도 적는다(예: 위험 색 D-12 + "기한이 12일 남았습니다").
3. **기한 자리**: 데스크톱 = 줄의 오른쪽 끝(`00-39` 규칙 6) · 모바일 = 제목 아래 줄.
4. **위험 색은 지우기·탈퇴·기한 임박에만** 쓴다. 완료 색은 저장됨·끝냄·공개 중에만.
5. **이모지를 쓰지 않는다**(📍 ⚠ ✅ 🚧 등, 1·2단계 확정). 위치는 갈색 선 그림 핀(§7-5), 주의는 △ 선 그림.

### 6-5. 조작

1. 🔄 **동작은 버튼, 다른 화면으로 가는 것은 글 링크**(밑줄 + 화살표)다. `00-39` 규칙 7("버튼은 밑줄이 아니라 테두리")을 잇되, 이동은 글 링크로 가른다.
2. **주 버튼은 한 구역에 하나**다.
3. **버튼·링크는 오른쪽 정렬이 기본**이다(개편 §4-1, 10-14 댓글). 버튼이 둘이면 **[보조][주]** 순서로 주 버튼이 오른쪽 끝에 온다. 🔵 0단계 02 판 ①("화면 안 · 왼쪽 정렬")의 표기는 이 규칙으로 읽는다(아래 ✅). 머리 글줄 바로 아래 한 줄 링크처럼 글과 붙어 있는 링크는 화면 판이 정한다(4-6-1).
   ✅ **개발자 확정(2026-10-20, 가안)** — 판 02 ①의 캡션 "왼쪽 정렬"이 아니라 개편 §4-1 "오른쪽 정렬이 기본"(10-14 댓글, 5단계 홈 링크도 이를 따름)을 정본으로 한다. 기각 = 판 02 캡션대로 왼쪽 정렬.
4. **위험 버튼은 바로 지우지 않고 위험 확인 창**(§7-6 ③)을 거친다.
5. **사용 불가 버튼은 옆이나 아래에 이유를 한 줄** 적는다. 글 링크는 사용 불가 상태가 없다 — 숨긴다.
6. **훑는 목록의 체크는 상자를 눌러야만 된다. 제목·›를 누르면 안내 창이 열린다**(`00-39` 규칙 8 · 9). 0단계 03 "체크리스트 줄" 판은 상자와 글을 한 `label`로 묶어 그렸지만, 누르는 범위는 이 규칙을 따른다(2-1 항목 줄에 › 있음).
7. **고르는 목록은 줄·카드 전체가 누르는 자리**다. 카드 위 지름길 버튼은 둘 수 있고 줄 누름과 겹치지 않게 한다(`00-39` 규칙 8-1).
8. **폼의 체크는 글자까지 누르는 자리**다(`00-39` 규칙 18 — 폼에는 경쟁하는 동작이 없다).
9. **브라우저 기본 창(`alert`·`confirm`·`prompt`)을 쓰지 않는다** → §7-6. 🔵 예외 1건: 개봉 요청 취소 확인("개봉 요청을 취소하시겠습니까?")은 브라우저 기본 창을 그대로 둔다(4단계 묶음 3, 개발자).
10. **스스로 넘어가는 것에는 멈춤 버튼**을 둔다(WCAG 2.2.2, 랜딩 바로 보기 자동 넘김). 마우스·키보드가 그 칸 안에 있으면 멈춘다.
11. **초점 표시**: 갈색 `#7A5634` 2px 바깥선, 3px 띄움(글 링크·아이콘 버튼은 2px). 위험 버튼은 위험 색 바깥선(0단계 02).

- **창 안의 규칙은 그 창 안에서만 맞으면 된다.** 창끼리 여백·구조를 맞추지 않는다(개편 §4-1, 개발자 "다른 식구").
- 창 크기는 §5-1 표 밖이다 — 입력 창 560 · 그 밖 420이 기본이고, 화면 판이 다른 값을 쓰면 그 판을 따른다.

- 🆕 **모바일 창 버튼이 셋**일 때(사진 읽기 [취소][뒤에 붙이기][바꾸기])는 한 줄 1 : 1 : 1. 360 폭에서 글자가 접히면 세로로 쌓는다(주 위, [취소] 맨 아래) — 실기동에서 확인(10-22 묶음 4).

### 7-7. 상태 화면 (판 08)

**다섯 가지 모두 같은 틀**: 선 그림 하나 → 제목(명조 21, 모바일 19) → 한 줄 설명 → 다음에 할 버튼. 가운데 정렬, 종이 칸 안. 모바일은 버튼을 가득 폭 52로 쌓는다.

| 상태 | 예시 문구 | 버튼 | 지금 코드 |
| :--- | :--- | :--- | :--- |
| ① 빈 화면 | "아직 남긴 메시지가 없습니다" | 주 [첫 메시지 쓰기] | `v2-empty`(25곳) |
| ② 처리 중 | "사진의 글자를 읽고 있습니다" + "사진 3장 · 30초쯤 걸립니다. 이 화면을 닫지 마세요." | 없음 · 진행 막대(폭 280 · 높이 4 · 갈색) + "2 / 3장째" | `v2-working` · `HeavyWork` |
| ③ 연결 실패 | "서버에 연결하지 못했습니다" + "쓰던 내용은 이 기기에 남아 있습니다." | 주 [다시 시도] | `ConnectionFailed` |
| ④ 오류 | "화면을 불러오지 못했습니다" + "계속되면 카카오톡으로 알려 주세요." | [홈으로][새로 고침] (모바일은 [새로 고침]이 위) | `ErrorBoundary` |
| ⑤ 완료(새로 정함) | "부고장을 만들었습니다" | [링크 복사][카카오톡으로 보내기] + 글 링크 | 없음 — 만들기·보내기·저장이 끝난 자리 |

- 완료만 **강조 카드**(어긋난 그림자 8 / 6 · 제목 24 / 21)다.
- 🆕 **선 그림 더하기**(10-22 묶음 6): 3단계가 새로 그린 그림 3개 — 거절됨 = 원 + 가로선 · 만료 = 시계 · 연장 불가 = 원 + 느낌표(회색 선) — 는 `RdState`의 그림 선택으로 부품에 넣는다(화면에서 따로 조립하지 않음). 크기는 다른 상태 그림과 같은 부품 규칙 — **데스크톱 48 · 모바일 40**(판 08, 🔄 10-22 편차 ③ — "40"으로 적었던 것은 모바일 값). 연장됨·수락됨은 기존 완료 그림(원 + 체크).
  - 🔄 **찾을 수 없음 = 네 번째 그림 `missing`**(10-22 편차 ①): 링크가 지워졌거나 잘못된 부고장·추모관·초대 링크는 **문서 + 줄**(회색 선, 묶음 6 조문객 화면이 쓰던 그림)을 `RdState`에 더해 쓴다. 봉투(① 빈 화면)는 "아직 없음"이라 뜻이 다르고, 오류 그림(문서 + 붉은 ×)은 조문객에게 고장처럼 읽힌다.
  - 상태 화면은 `role="alert"`을 달지 않는다(10-22 편차 ② — 연결 실패 포함). 화면 자체가 상태로 바뀐 것이라 끊어 읽힐 일이 아니다(§7-5 띠 알림 `role="status"`와 같은 이유). 처리 중만 `role="status"` + `aria-busy`.

### 8-3. 규칙

1. 🔄 **필수는 칸 이름 끝의 "필수" 딱지**다 — 갈색 테두리 · 12 · 굵게 · 폭 40(동의 문장 끝은 34). 별표(`*`)를 쓰지 않는다. 선택 항목은 강조가 필요한 곳에만 표시하고 나머지는 아무것도 붙이지 않는다. 🆕 표시할 때는 **"선택" 딱지** — 필수 딱지와 같은 자리·크기, 회색(작은 글자색) — 를 `RdField`의 선택으로 둔다(10-22 묶음 7 편차 ⑤: 부고장 만들기·추모관 만들기·조문객 방명록 세 화면이 각자 만들어 둔 것을 합침). `00-39` 규칙 16(12px **붉은** 글자)을 바꾼다 — 위험 색을 지우기·기한에만 쓰기 위해서다(§6-4-4).
2. **오류는 칸마다 붙인다.** 브라우저 기본 검증(`required` 말풍선)을 쓰지 않는다(`00-39` 규칙 17). 제출에 실패하면 네 가지가 같이 일어난다.

   | | 무엇 | 값 |
   | :---: | :--- | :--- |
   | ① | 칸 아래 오류 글 | 도움말 자리를 **대신한다**(같이 쌓지 않는다) · `role="alert"` |
   | ② | 칸 테두리 | 2px 위험 색 |
   | ③ | 요약 한 줄 | 🔄 **"확인이 필요한 항목이 N개 있습니다."** — 뒷문장("붉게 표시된 곳을 확인해 주세요.")은 뺀다(2026-10-16 개발자, 모든 폼). 🔄 자리 = **저장 줄 안**: 데스크톱 버튼 왼쪽(14 · 위험 색 + 아이콘), 모바일 아래 고정 줄의 버튼 바로 위(2-13). `00-39`의 "폼 위 요약"을 바꾼다 |
   | ④ | 초점 | 화면 위에서 첫 번째 오류 칸으로 |

   - **오류 글은 "무엇을 하라"로 쓴다** — "번호를 끝까지 적어 주세요"(`필수 항목입니다` ✗). 동의 줄처럼 할 일이 하나뿐인 칸과 코드에 칸 오류 글이 없는 칸은 **"확인이 필요한 항목입니다."**로 쓴다(4단계 묶음 3).
   - **고친 칸은 바로 푼다** — 값을 고치면 그 칸의 오류만 사라진다.
3. **체크는 한 가지 모양**이다(먹색 `accent-color`). 동의·토글·선택을 서로 다르게 그리지 않는다(`00-39` 규칙 18).
4. **저장 상태는 버튼이 말한다.** 누르는 순간 버튼을 잠그고(`disabled` + `aria-busy`) 글자를 바꾼다 — "부고장 만들기" → "처리 중…", 주 버튼은 돌림 그림을 붙인다(§7-1). 스피너·토스트·별도 안내 줄을 만들지 않는다(`00-39` 규칙 19). 저장 실패처럼 버튼이 말할 수 없는 결과는 짧은 알림(§7-6 ④)으로 알린다(2단계 확정 ⑫).
5. **미리보기에는 설명문을 붙이지 않는다.** 데스크톱은 오른쪽 열(스크롤을 따라옴), 모바일은 폼 안 확인 사항 바로 앞(§5-3, `00-39` 규칙 20). 카카오톡 카드 미리보기는 카카오톡 화면을 그린 그림이라 이 문서의 색을 입히지 않는다.
6. **입력 열은 560**이다. 미리보기가 없는 폼도 560에 두고 왼쪽 정렬한다(§5-3).

1. **시안 판이 정본이다.** 이 문서는 공통 값과 규칙이고, 화면 하나의 배치·문구는 각 기능 문서가 가리키는 판을 따른다. 시안과 문서가 다르면 구현하지 말고 `[Claude:Opus]`에게 묻는다(`roles.md` §2-1 편차 처리).
