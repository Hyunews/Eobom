## 🔴 5. 정본 경계 — **`reports/style.css`는 디자인 정본이 아닙니다** (2026-08-19 신설)

**디자인 정본은 `00-39`**(2026-09-18~)이고, 구현 정본은 `eobomDev/frontend/src/styles/design-v2.css`입니다(옛 토큰은 `index.css`에 남아 있음 — 설명은 `00-38` §4). 이 절의 규칙 — *"`reports/`의 스타일은 제품 디자인 정본이 아니다"* — 은 효력정지와 무관하게 **지금도 유효**합니다.

### 5.2 원인 — 두 파일은 목적이 다릅니다

`reports/`는 **`docs/` 마크다운을 HTML로 시각화한 문서 뷰어**이고(`generate_all_reports.js` 생성), `style.css`는 그 **보고서를 읽기 위한 스타일**입니다. 제품 화면 시안이 아닙니다. 목적이 다르니 자연히 갈라지는데, **어느 쪽이 정본인지 문서에 적혀 있지 않아 혼선이 났습니다.**

### 5.3 규칙

| | 내용 |
| :--- | :--- |
| ✅ **정본** | 색·서체·여백·접근성 기준 → **`00-39`** / 구현 → `styles/design-v2.css` |
| ❌ **정본 아님** | `reports/style.css`, `reports/**/*.html`의 인라인 스타일 |
| 🔵 **소유권** | `reports/`는 **`[Gemini]` 소유**이며 Claude에게 **읽기 전용**입니다(`CLAUDE.md`). 드리프트가 보이면 고치지 말고 `context.md`에 `[Gemini]` 요청으로 남깁니다 |

> 🟡 **`reports/style.css`의 처분은 `[Gemini]` 판단**입니다 — ①`00-39` 기준에 맞춰 갱신하거나 ②보고서 전용임을 파일 상단 주석에 명시하거나 ③삭제합니다. **어느 쪽이든 "제품 디자인 시안"으로 오해될 여지를 없애는 것이 목적**이고, 문서 가독성 자체는 보고서의 요구라 무조건 `index.css`와 같아질 필요는 없습니다.
