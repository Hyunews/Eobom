# 🏠 00-45. 랜딩(개편) — 명세서

> **문서 성격**: 명세서 · **2026-10 디자인 개편(새 디자인)의 첫 화면(`/`) 배치·문구 정본**. `[Claude:Opus]` 작성(2026-10-20, 7단계 문서 묶음 3).
> **지금 코드(옛 디자인)의 랜딩 정본은 그대로 [`00-40`](./00-40_홈_랜딩_재설계_계획서.md)이다.** 새 랜딩은 새 브랜치의 별도 폴더·미리보기 주소로 만들고, 전 화면과 함께 한 번에 바꾼다([`00-44`](./00-44_디자인_기준_개편_명세서.md) §9-1).
> **근거**: 랜딩 캔버스(Claude Design, 개발자 소유) https://claude.ai/artifact/BVhybr7ij2hmP8mupWeEvD — 판 4장: 랜딩 데스크톱 · 랜딩 모바일 · 메뉴 펼침 데스크톱 · 메뉴 펼침 모바일. 결정 경위 원본 = 개발자 바탕화면 `이어봄_디자인개편.md` §3·§4-1(git 밖).
> **색·글자·폭·부품은 `00-44`를 따른다.** 이 문서는 랜딩에만 쓰는 배치·문구·값만 적는다.

## 📌 1. 결론 먼저

- **C안 배치**(2026-10-14 개발자 선택, `00-44` §1): 첫 화면 = 큰 명조 제목 한 줄 + **두 갈래 버튼** + **필요한 것만 바로 보기**. 그 아래 **서비스 소개 제1부 · 제2부**.
- 두 갈래 버튼은 **다른 화면으로 넘기지 않고 랜딩 안 아래로** 내려간다 — *"가족을 떠나보냈어요"* → 제2부, *"미리 준비하려고 해요"* → 제1부(10-14 개발자: *"바로 넘어간다면 소개글 만들 이유가 없었음"*).
- 옛 랜딩의 **차례(메뉴 목록)는 없앤다.** 바로 보기와 같은 목록이 두 번 나오기 때문이다(`00-44` §6-2-4).
- 🔴 **데스크톱과 모바일은 한 쌍**이다. 구간 순서는 같고, 넘기는 방식만 다르다(§2).
- 파트너 로그인은 랜딩 본문이 아니라 **데스크톱 바닥글 · 모바일 메뉴 판**에 둔다(§10).

- **데스크톱 = 보통 스크롤.** 화면 높이를 채우는 것은 ① 하나뿐이고, 제1부·제2부는 내용만큼이다(`00-44` §5-1). 옛 랜딩의 "휠 한 번 = 한 칸"(`00-40` W-1)은 쓰지 않는다.
- **모바일 = 세로 풀페이지.** ①~④가 각각 화면 높이(헤더 제외, `svh` — `00-40` M-7과 같은 이유)를 채우고 세로로 한 칸씩 넘어간다. **④가 마지막 칸**이다(모바일은 바닥글이 없다, §7). 🔵 화면 높이를 채우는 것이 첫 화면 하나뿐이라는 `00-44` §5-1의 예외는 **모바일 랜딩의 ②~④뿐**이다(랜딩 정본 = 이 문서). 옛 랜딩의 **가로 넘김**(`00-40` M-1)은 쓰지 않는다.
- 모바일 칸 아래 가운데에 **반투명 ⌄**(다음 칸으로, 44 × 44, 불투명도 45%) — ①②③에만 둔다. **④ 아래에는 두지 않는다**(10-14 개발자). 데스크톱은 ① 아래 가운데에만 ⌄(44 × 44, `aria-label="아래로 이어서 보기"`)를 두고 제1부로 내려간다.
- 시안 판 높이: 데스크톱 1280 × 800 가정에서 ① 최소 높이 703(800 − 헤더), 모바일 390 × 844에서 칸 788(844 − 헤더 56). 실제 높이는 구현에서 화면 높이로 맞춘다.

## 🔎 5. 필요한 것만 바로 보기

**11칸**(10-14 개발자). 넣지 않은 것 = 파트너 로그인 · 마이페이지 계열 · 전화 문의 · "나에게 공유된 것"(로그인 뒤 내 정보에 그대로 둔다).

| 묶음(데스크톱) | 칸 |
| :---: | :--- |
| 1 / 3 | 장사시설 검색 · 모바일 부고장 · 유품 정리 업체 · 전문가 상담 |
| 2 / 3 | 디지털 엔딩노트 · 유족 메시지 보관함 · 상중 행정 가이드 · 디지털 추모관 |
| 3 / 3 | 디지털 정산 · 카카오톡 문의 · 추모관 링크로 입장 |

모바일은 같은 순서로 11칸을 **한 화면에 2열**로 다 보인다.

| :--- | :--- | :--- |

- 🔴 **자동 넘김에는 멈춤 버튼이 있어야 한다**(WCAG 2.2.2, `00-44` §6-5-10). 마우스가 칸 위에 있거나 키보드 초점이 칸 안에 있으면 넘기지 않는다. 멈춤 버튼 이름은 상태에 따라 **"자동 넘김 멈추기" / "자동 넘김 다시 켜기"**.
- 🔄 시안의 묶음 넘김 버튼 세 개는 36 × 36이다 → 구현은 **44 × 44**(`00-44` §5-1 누를 수 있는 가장 작은 크기). 아이콘 크기는 그대로.
- 🔵 사용자가 동작 줄이기(`prefers-reduced-motion`)를 켰으면 자동 넘김을 처음부터 멈춤으로 둔다.
- **칸을 누르면 가는 곳**:
  - 기능 9칸 → 그 기능 화면(헤더 메뉴와 같은 곳). 로그인이 필요한 화면은 그 화면의 로그인 안내가 맡는다(`00-44` §6-3).
  - **카카오톡 문의** → [카카오톡으로 문의하기](데스크톱 바닥글 · 모바일 메뉴 판)와 같은 곳.
  - **추모관 링크로 입장** → 🔄 **이어봄 입력 창**(`00-44` §7-6)을 연다. 칸 하나에 추모관 링크(또는 주소)를 붙여 넣고 [입장]. 링크를 읽는 방식은 지금 코드 그대로(`HomeDesktop`·`HomeMobile`의 `handleMemorialLinkEnter`). 지금은 홈 안에서 입력칸이 펼쳐지지만, 새 랜딩의 바로 보기 칸에는 펼칠 자리가 없어 창으로 옮긴다. 시안에는 이 창이 없다 — 0단계 판 07 입력 창 모양을 그대로 쓴다.

## 📖 6. 서비스 소개 — 제1부 · 제2부

### 6-1. 구조

| | 데스크톱 | 모바일 |
| :--- | :--- | :--- |
| 구간 머리 | 윗글 **"제1부"** / **"제2부"**(14 갈색 자간 2) → 제목 명조 40 → 소개 한 줄 17 | 윗글 13 → 제목 명조 27 · 소개 한 줄 없음 |
| 바탕 | 제1부 = 종이색 + 위아래 실선 · 제2부 = 바탕색 | 같음 |
| 본체 | **왼쪽 목록**(340) + **오른쪽 상세**(나머지), 사이 56 | **카드 한 장**을 좌우로 밀어 넘김 + 아래 [‹] [바로 가기] [›] |
| 목록 줄 | 번호 13 + 이름 17 · 최소 높이 48 · 점선 · 고른 줄 = 먹색 채움 + 바탕색 글자(`aria-pressed`) · 제2부는 단계 이름(장례 기간 · 장례 후 · 정리와 기억)을 묶음 머리로 | — |
| 상세 / 카드 | 이미지(16:10, 흰 테두리 12) → 이름 명조 30 + 오른쪽 **"01 / 03"** → 한 줄 설명 17 → 점선 → 기능 설명 목록 16 → 밑줄 화살표 링크(바로 가기) | 이미지(높이 220, 흰 테두리 10) → 이름 명조 23 + 오른쪽 **"1 / 3"** → 한 줄 설명 15 → 기능 설명 15 |
| 바로 가기 | 밑줄 화살표 링크 16(`00-44` §7-1) | 먹색 채움 52 · 가운데, 양옆 [이전 기능] [다음 기능] 테두리 52 × 52 |
| 위아래 여백 | 위 96 · 아래 104 | 위 32 · 아래 68(⌄ 자리) |

- 🔴 **쪽번호는 "01 / 07"만** 적는다. 앞에 단계 이름을 붙이지 않는다(개편 기록 3절 — 같은 정보가 목록에 있음).
- 🔵 모바일 카드 번호("1 / 3")는 시안 그대로 둔다. 개편 기록 3절의 "모바일은 쪽번호 표시 없음"은 **칸(화면) 번호**를 말한다(옛 랜딩 `00-40` M-4의 `1 / 4`). 카드 번호는 바뀔 때 화면낭독에 알린다(`aria-live="polite"`).
- 모바일 밀어 넘김: 가로로 40px 넘게 밀면 다음/이전 카드. 세로 스크롤은 막지 않는다(`touch-action: pan-y`). 끝에서 다시 처음으로 돈다.
- 바로 가기를 누르면 그 기능 화면으로 가고 **그 부로 모드를 맞춘다**(§3과 같음).
- 🔵 기능 설명 목록 앞의 "—"는 화면낭독에 읽히지 않는 **장식 표시**(`aria-hidden`)라 문구의 대시 금지(`04-01` §0.2)와 별개로 시안대로 둔다. 개발자가 바꾸라 하면 갈색 점(·)으로 바꾼다.

## ♿ 8. 접근성 · 동작

1. 구간마다 제목(`h2`)에 `id`를 두고 구간은 `aria-labelledby`로 잇는다(갈래 버튼이 그 `id`로 내려간다).
2. 자동 넘김: §5 · 멈춤 버튼 · 마우스/초점이 있으면 멈춤 · 동작 줄이기면 처음부터 멈춤.
3. 데스크톱 소개 목록은 진짜 `button` + `aria-pressed`. 모바일 [이전 기능]·[다음 기능]도 `button`.
4. 모바일 칸 넘김의 ⌄는 진짜 링크/버튼(44 × 44), 장식 그림은 `aria-hidden`.
5. 키보드로 칸·카드를 넘기는 키 처리는 **그 영역에 초점이 있을 때만** 한다(전역 키 처리 금지, `00-40` M-8을 잇는다).
6. 🔵 옛 주소 `/prep`·`/bereaved`는 지금처럼 랜딩으로 돌려보내되, 새 랜딩에서는 **`/prep` → 제1부 · `/bereaved` → 제2부**로 내려간다(`00-40` C6·M-9를 잇는다).

## 🖼️ 9. 이미지

- 소개 이미지 = **실제 화면 캡처**(10-14 개발자). 🔴 캡처는 **새 디자인으로 구현된 화면**에서 뜬다(`00-44` §9-1 9단계). 그때까지는 시안처럼 빈 박스(`[○○ 화면 이미지]`).
- 데스크톱 상세엔 **데스크톱 캡처**(16:10), 모바일 카드엔 **모바일 캡처**(높이 220 칸에 맞춤).
- 🔴 캡처 속 이름·연락처·글은 **예시 데이터만**(실제 회원 정보 금지).
