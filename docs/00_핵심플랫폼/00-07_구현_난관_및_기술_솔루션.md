### 2. 공공 시설 데이터 확보 — 공공 API 대신 CSV 시딩
* **문제**: e하늘 장례정보 API는 세부 단가 데이터가 없고, 신청 절차에 위치기반서비스 사업자 신고가 요구됐습니다.
* **해법**: **보건복지부 CSV 파싱 시딩 + 카카오 로컬 REST API(`query=장례식장`) 보강**으로 전국 시설 데이터를 확보했습니다.
* 🔴 **이 해법이 위치정보법 신고를 없애 주지는 않습니다.** 내 위치 기반 검색(현위치 거리순)을 서비스로 내보내는 것 자체가 신고 대상이라, **위치정보 사업 신고(`00-22` B-1)가 지금 유일한 게시·오픈 블로커**입니다. 데이터를 어디서 가져왔는지와 별개입니다.

### 3. PostgreSQL 포트 충돌 (기본 5432 포트)
* **문제**: 개발자 로컬 PC의 타 프로젝트 PostgreSQL(5432 포트)과 포트 충돌 발생.
* **해법**: Docker 컨테이너 호스트 포트를 `5433`으로 우회 매핑(`5433:5432`)하여 타 서비스와의 충돌을 완전 예방.

### B. §4 로컬 IP 테스트 시 Geolocation 보안 컨텍스트 제한 — `mkcert` 도입 (지금 미사용)

> 지금 `vite.config.ts`·`server.ts`에는 https·pem 설정이 없습니다. 아래는 한때 쓴 방법의 기록입니다.

* **문제**:
  * 브라우저의 Geolocation API(`navigator.geolocation`)는 보안 정책상 **보안 컨텍스트(`https://` 또는 `localhost`)**에서만 동작함.
  * 개발 중 사설 LAN IP(`http://192.168.x.x:5173`)로 접속하면 `http://`로 판정되어 위치 자동 감지가 항상 실패하고 하드코딩 폴백(서울 서초 좌표)으로 무조건 떨어지는 문제 발생.
* **대안 검토 결과**:
  * `Certbot`: Let's Encrypt는 공인 도메인 전용으로 사설 IP/localhost 발급 불가.
  * `OpenSSL 자체 서명`: 브라우저 레드 스크린 경고 발생 및 최신 크롬 SAN(Subject Alternative Name) 설정 작성 까다로움.
  * `Cloudflare Tunnel`: 테스트 범위를 넘어 진짜 인터넷에 개발 서버가 노출되는 위험 존재.
* **해법 (당시)**: 로컬 전용 CA(인증기관) 래퍼 도구인 **`mkcert`**를 채택하여 신뢰할 수 있는 개발용 SSL/TLS 인증서 자동 발급 및 적용.

#### 1) `mkcert` 설치 및 로컬 CA 등록 (윈도우)
```powershell
# Chocolatey 사용 시
choco install mkcert

# Scoop 사용 시
scoop install mkcert

# 윈도우 신뢰 인증서 저장소에 로컬 CA 등록
mkcert -install
```

#### 2) 인증서 발급 (`eobomDev/` 디렉토리)
```powershell
# localhost, 127.0.0.1 및 내부 사설 IP용 인증서 통합 발급
mkcert localhost 127.0.0.1 192.168.0.111
# 생성 파일: localhost+2.pem (인증서), localhost+2-key.pem (개인키)
```

#### 3) 프론트엔드/백엔드 SSL 적용 (지금은 제거됨)
* **Vite (`vite.config.ts`)**: `https: { key: fs.readFileSync(...), cert: fs.readFileSync(...) }` 세팅.
* **Express (`server.ts`)**: `https.createServer({ key, cert }, app)`을 통해 5000번 포트를 HTTPS로 구동.

#### 4) 복원 (Uninstall)
```powershell
mkcert -uninstall
```
