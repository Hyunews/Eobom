## 🔴 3. 왜 `keyVersion` 하나로 안 되는가 — 잠금이 두 종류다

### 3.1 암호문 — **섞여 있어도 됩니다**

복호화는 **행 하나만 보면 되는 작업**입니다. 그 행이 v1이면 v1 키로, v2면 v2 키로 열면 끝입니다.
**다른 행이 어느 버전인지 알 필요가 없습니다.** → 한 건씩 천천히 옮겨도 안전합니다.

### 3.2 🔴 결정적 해시 — **섞이면 불변식이 죽습니다**

`phoneHash`는 **비교당하기 위해 존재**합니다.

```prisma
@@unique([userId, phoneHash])   // 같은 사람을 두 번 지정하지 못하게
```

키가 바뀌면 **같은 전화번호에서 다른 해시가 나옵니다.**

```
어머니  010-1234-5678
  v1 해시  a3f9c2e8…   ← 이미 등록된 행
  v2 해시  7b1e5d09…   ← 지금 등록하려는 행

  DB 판정: 두 값이 다름 → 중복 아님 → 통과
```

> 🔴 **같은 사람이 두 번 등록됩니다. 예외도, 로그도 남지 않습니다.**
> `@@unique`는 **값 두 개를 글자 그대로 비교할 뿐**이며, *"둘은 사실 같은 사람인데 키가 달랐다"*
> 를 알 방법이 원리적으로 없습니다. **`00-27` §5의 불변식이 조용히 무효화됩니다.**

| | 암호문 | 결정적 해시 |
| :--- | :---: | :---: |
| 판단 단위 | 행 하나 | **행 전체의 집합** |
| 버전 혼재 | ✅ 허용 | 🔴 **금지** |
| 전환 방식 | **점진**(한 건씩) | 🔴 **원자적**(전부 한 번에) |
| 실패 시 증상 | 그 행만 안 열림 — **즉시 발견** | 🔴 **중복 통과 — 발견 안 됨** |

**성격이 다르므로 해법도 달라야 합니다.** `keyVersion` 컬럼은 3.1만 푸는 도구입니다.

### 3.3 ✅ 그래도 해시를 되돌릴 수 있는 이유 — `phoneEnc`가 있어서

해시는 단방향이라 해시값에서 전화번호를 복원할 수 없습니다. **재해시가 가능한 유일한 이유는
같은 행에 `phoneEnc`(암호문)가 함께 있기 때문**입니다 — 복호화 → 재해시가 됩니다.

> 🔴 **이 사실을 스펙에 박아둡니다: 결정적 해시 컬럼은 반드시 대응하는 암호문 컬럼과 짝으로만
> 만듭니다.** 해시만 있는 컬럼을 만들면 **그 값은 영원히 교체 불가**가 됩니다.

## 🔑 4. 1층 — `hashField` 재구성 (🔴 최우선)

### 4.1 지금 구조와 그 대가

```ts
// utils/crypto.ts — 현재
const raw = process.env.SETTLEMENT_ENCRYPTION_KEY;          // 🔴 정산 키
const hmacKey = crypto.createHash('sha256').update(`${raw}:${domain}`).digest();
```

`00-27` §4.1이 이 설계를 정한 근거는 명시돼 있습니다 —
*"**새 환경변수를 추가하지 않으면서** 암호화 키와 인덱스 키를 분리합니다
(env를 늘리면 `render.yaml`·Render 대시보드가 같이 늘어납니다)."*

**절약의 대가가 도메인 결합입니다:**

```
01(정산 계좌) 키 교체  →  00-27(가족 지정) 중복방지 무효화
```

**두 도메인이 env var 하나로 묶여 있고, 그 사실이 코드에도 문서에도 적혀 있지 않습니다.**
정산 키를 교체하는 사람은 가족지정이 깨질 것을 알 수 없습니다.

### 4.2 ✅ 확정 — `00-27` §4.1의 "새 env를 추가하지 않는다"를 **철회합니다**

| | 옛 결정(`00-27` §4.1) | ✅ 새 결정(이 문서) |
| :--- | :--- | :--- |
| 해시 키 | `sha256(SETTLEMENT_ENCRYPTION_KEY + ':' + domain)` | **`HASH_INDEX_KEY`** 전용 환경변수 |
| 근거 | env 개수 절약 | **교체 독립성** — 정산 키와 생사를 같이하지 않음 |
| `domain` 인자 | 유지 | ✅ **유지**(용도 구분은 여전히 유효) |

> 🔵 **철회 사유를 분명히 합니다**: 옛 결정이 틀렸다기보다 **교체 시나리오를 고려하지 않았던
> 것**입니다. env 1개가 느는 비용(`render.yaml` 1줄 + 대시보드 1건)은 실재하지만, **도메인
> 결합을 푸는 값에 비하면 작습니다.** `roles.md` §2-1에 따라 `00-27` §4.1에 갱신 사유를 남깁니다.

### 4.3 전환 절차 — 🔴 **원자적**

1. `.env`·`render.yaml`에 `HASH_INDEX_KEY` 추가(**32바이트 랜덤**, §7.2).
2. `hashField`가 `HASH_INDEX_KEY`를 읽도록 변경.
3. 🔴 **재해시 스크립트** — `FamilyDesignation` 전 행에 대해 `phoneEnc` 복호화 → 새 키로 재해시.
   - **반드시 단일 트랜잭션.** 중간에 멈추면 §3.2의 혼재 상태가 됩니다.
   - **`db-safety.md` 전 과정 적용** — 사람 승인 → 백업 → **파일 확인** → 실행(§5).
4. **검증**: `phoneHash NOT LIKE 'v2:%'` 가 **0건**인지 확인(§4.4).

### 4.4 🟡 해시에도 버전 프리픽스를 붙입니다 — **탐지용**

```
지금:  a3f9c2e8b1d4…
이후:  v2:a3f9c2e8b1d4…
```

⚠️ **오해 금지: 프리픽스가 §3.2를 해결하지 않습니다.** 혼재는 여전히 사고입니다.
**프리픽스의 목적은 "혼재가 일어났는지 한 줄로 확인할 수 있게" 하는 것**입니다 —
백업 절차가 *"돌렸다"* 가 아니라 *"파일이 있다"* 를 통과 조건으로 삼는 것(`db-safety.md` §2-2)과
같은 원칙입니다. **눈으로 확인 가능한 상태를 만듭니다.**

## 📦 5. 2층 — 암호문 버전 프리픽스

### 5.1 ✅ 형식

```
지금:      k9Fj2m : x8Qp1z : aBcD3fG7hK…
이후:  v2 : k9Fj2m : x8Qp1z : aBcD3fG7hK…
```

- **복호화**: 첫 토막이 `v`로 시작하면 그 버전 키로, **없으면 v1으로 간주**(하위호환).
- **암호화**: 항상 현행 버전 프리픽스를 붙여 저장.
- ✅ **기존 데이터를 건드리지 않아도 됩니다** — 읽을 때 자동 판별, 쓸 때 자연히 v2가 됩니다.

### 5.2 🔵 왜 `keyVersion` 컬럼이 아닌가 *(초안 권고 정정)*

| | `keyVersion` 컬럼 | ✅ 버전 프리픽스 |
| :--- | :--- | :--- |
| 스키마 변경 | 🔴 **필요** → 마이그레이션 = `db-safety.md` 대상 | ✅ **불필요** |
| 한 행에 암호 컬럼이 복수일 때 | 🔴 **불가** — `FamilyDesignation`은 `phoneEnc`+`emailEnc` 2개인데 컬럼 하나로는 따로 굴리지 못함 | ✅ **컬럼별 독립** |
| 복호화 시 | 컬럼을 함께 읽어야 함 | ✅ **문자열만으로 자기 판별** |
| 백업 호환 | 옛 dump에 컬럼이 없음 | ✅ 문자열이라 그대로 |

🔵 **DB 유실 2회(`db-safety.md` §7) 프로젝트에서 "스키마 변경이 필요 없다"만으로도 충분한 근거입니다.**

### 5.3 전환 방식 — **점진, 강제 재암호화 없음**

평상시에는 **아무것도 안 합니다.** 각 행은 수정될 때 자연히 v2가 됩니다.
🔴 **유출로 인한 긴급 교체 시에만** 전량 재암호화 스크립트를 돌립니다(§6.2) —
그때도 **§3.1대로 점진이 허용**되므로 배치로 나눠 돌릴 수 있습니다.

## 🛠 6. 3층 — 로테이션 도구와 정책

### 6.1 ✅ 선행 — 스키마 주석 오류 수정 (**비용 0 · 즉시**)

```prisma
model FarewellMessage {
  bodyEnc String  // ❌ 현재: "…(utils/crypto.ts encryptField)"
                  // ✅ 수정: "…(utils/crypto.ts encryptNoteField, ENDING_NOTE_ENCRYPTION_KEY)"
}
```

실제 코드는 `encryptNoteField`입니다(`farewellMessageController.ts:149·191`).
08-27 키 분리 때 주석만 갱신되지 않았습니다.

> 🔴 **로테이션 스크립트를 이 주석 기준으로 짜면 정산 키로 복호화를 시도합니다.**
> AES-GCM은 `authTag` 불일치로 예외를 던지므로 **조용한 파손은 아니지만**, 전량 작업 중간에
> 터지면 **어디까지 처리됐는지 모르는 상태로 멈춥니다.** 유실 2회 프로젝트에서 가장 나쁜 상태입니다.

### 6.2 로테이션 스크립트 요건

| 요건 | 내용 |
| :--- | :--- |
| 위치 | `eobom/backend/prisma/rotate-keys.ts` — 🔴 **`00-15` §5.2 0단계에 따라 실행 후 지우지 않습니다** |
| 대상 | 키 소스별로 분리 실행(`SETTLEMENT` 5컬럼 / `ENDING_NOTE` 2컬럼 / `HASH_INDEX` 1컬럼) |
| 🔴 사전 | **`db-safety.md` 전 과정** — 승인 → 백업 → **파일 존재 확인** → 실행 |
| 🔴 건수 | 실행 전 `count`를 출력하고 **사람이 확인**(`db-safety.md` §3) |
| 멱등성 | 이미 v2인 행은 건너뜀 — 중단 후 재실행이 안전해야 함 |
| 트랜잭션 | 암호문 = 배치 허용 / 🔴 **해시 = 단일 트랜잭션 필수**(§3.2) |
| 검증 | 종료 후 `NOT LIKE 'v2:%'` 잔여 건수 **0** 확인 |

### 6.3 🔴 옛 키 보관 — **정책으로 정합니다**(확정 필요)

백업 dump에는 **옛 키로 잠긴 데이터**가 들어 있습니다. 옛 키를 폐기하면 **그 백업은 영구히
복원 불가**입니다. 그런데 **유출 대응으로 교체하는 경우, 옛 키를 계속 보관하는 것은 교체의
의미를 반감**시킵니다.

> 🔴 **기술로 풀 수 없는 트레이드오프입니다.** 문서에 적지 않으면 사고가 납니다.
> 🟡 **권고**: 옛 키는 `.env`에 `*_KEY_V1` 형태로 **백업 보존기간(`00-20`)만큼만** 보관하고
> 그 후 폐기. 보존기간이 지난 백업과 함께 사라지므로 앞뒤가 맞습니다.

## ❌ 7. 하지 않는 것

### 7.1 KMS·Vault 도입 — **기각**

외부 리뷰가 권한 AWS KMS / HashiCorp Vault는 **도입하지 않습니다.**
`00-11` §3.3이 확인한 팀 여건은 **전담 인프라·보안 인력 0명**이고, `00-11` §8(사업자 확정)이
아직 미결이라 **어느 클라우드의 KMS인지조차 정할 수 없습니다.** 이 문서의 3층 구조로
**교체 가능성이라는 목적은 달성**되며, KMS는 그 위에 나중에 얹을 수 있습니다.

### 7.2 🟡 다만 키 강도 검증은 넣습니다

```ts
return crypto.createHash('sha256').update(raw).digest();  // 임의 길이 허용
```

주석은 *"운영자가 임의 길이 문자열을 넣어도 안전하도록"* 이라 하지만, **sha256은 길이를 맞출 뿐
엔트로피를 만들지 못합니다.** `eobom1234`를 넣으면 여전히 약한 키입니다.
🟡 **부팅 시 검증**: 32자 미만이면 **서버가 뜨지 않게** 합니다(운영 환경에 한함 — 로컬은 경고).

### 7.3 알고리즘 변경 — 없음

AES-256-GCM·HMAC-SHA256을 그대로 씁니다. **이 문서는 "키를 바꿀 수 있게" 만드는 것이 전부**이며,
암호 자체는 문제가 없습니다.

### 8.4 🔴 완료 후에도 남는 것 — **솔직히 적습니다**

- **키는 여전히 `.env` 평문**입니다. KMS를 안 쓰기로 했으므로(§7.1) **서버가 뚫리면 키도 같이
  나갑니다.** 이 문서가 막는 것은 *"유출 후 복구 불가"* 이지 *"유출 그 자체"* 가 아닙니다.
- **`00-11` §8 미결이라 운영 환경의 키 저장 방식은 확정할 수 없습니다.** 사업자가 정해지면
  그 플랫폼의 시크릿 관리로 옮기는 것이 다음 단계입니다.
- **재암호화 중 장애가 나면 여전히 사람이 판단**해야 합니다. 멱등성·프리픽스로 **재개는 안전**해지지만
  자동 복구는 아닙니다.
