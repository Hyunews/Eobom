# 00-40 홈(랜딩) 재설계 계획서 — 그룹⑤ `home`

> **[계획서·2026-09-28]** `00-39` §9.1 그룹⑤의 대표 화면 `home`을 **분기(라운드)로 나눠** 다시 그린다.
> 🔴 **이 화면만은 기존 구현을 억지로 지키지 않는다**(2026-09-28 사람 지시). 확정되면 `00-39` §6.7에 결과를 올리고,
> `00-23`(메인화면 진입구조)의 레이아웃 규정 중 겹치는 부분은 **이 문서가 대체**한다.
> 색·글자·여백 확정값은 `00-39` §3~§5를 그대로 따른다.

## 1. 출발점 — 사람 피드백 원문 (2026-09-28)

지금 홈은 **3칸 풀페이지 스냅**이다(`HomePage.tsx`): 섹션1 히어로 → 섹션2 진입 4박스(`EntryBoxes.tsx`, 좌우 캐러셀) → 섹션3 에필로그 + 푸터.

| | 데스크톱 | 모바일 |
| :--- | :--- | :--- |
| **섹션1** 히어로 *"장례가 끝이 아니었습니다"* | ✅ 마음에 듬. **단 `장례 준비`·`미리 준비` 버튼 위치 변경 필요** | ❌ 위 이미지와 글이 **분리된 것처럼** 보이고, 글이 **화면 아래쪽에 치우침**. 🔴 **주소창이 있다가 스크롤하면 사라지는 것**을 고려하지 않음 |
| **섹션2** 진입 박스 | ❌ **가장 마음에 안 드는 부분.** *"너무 초보적인 페이지의 느낌"*, 전하려는 것을 제대로 전하는지 의문 | ❌ 좁은 창에서 **엔트리 박스를 고집**해 디자인·공간 효율 모두 문제 |
| **섹션3 + 푸터** | ✅ 마음에 듬. **단 `이어봄과 함께하는 존엄하고 따뜻한 준비` 배지 제거** | ✅ 같음. 배지 제거 |

**모바일 추가 고려**
1. 풀페이지 방식이 별로라면 **다른 페이지 넘김 방식**도 검토.
2. 섹션2는 **페이지 전체를 엔트리 카드 하나로** 만들거나, **엔트리마다 섹션으로 나누는** 방법도 있다 — *시안에서 다양하게.*
3. 🔴 **상단 메뉴바를 다시 살린다**(전에 없앴음). 메뉴에서 **미리 준비·장례 준비를 한 번에** 볼 수 있게.

**작업 방식**: 수정이 많고 시안도 여러 종류가 필요하니 **분기를 나눠** 진행. 🔴 **디자인이 AI스럽지 않을 것.**

## 2. 원칙

### 2.1 🔴 "AI스럽다"로 읽히는 것 — 쓰지 않는다

지금 홈에 실제로 있는 것들이다. 시안에서 **하나도 가져가지 않는다.**

| 신호 | 지금 홈의 예 |
| :--- | :--- |
| 반짝이(✨) 아이콘 + 알약 배지로 여는 문구 | `✨ 디지털 엔딩 & 웰다잉 토탈 케어 이어봄 (Eobom)` · `✨ 이어봄과 함께하는 존엄하고 따뜻한 준비` |
| 같은 모양 카드 4개를 아이콘 동그라미 + 제목 + 설명으로 나란히 | 진입 4박스 |
| 옅은 그라데이션 틴트 카드 · 호버하면 펼쳐지는 칩 | `--box-tint-*` · `.entry-box-reveal` |
| 기능을 굵은 글씨로 나열하는 문장 | *"평온한 생전 준비부터 장사시설 매칭, 복잡한 사후 행정…"* |
| 좋은 말로 마무리하는 문장 | *"이어봄이 곁에서 함께합니다"* 류 |

🔵 대신 — **실제 내용**(무엇을, 언제까지, 몇 개)으로 말하고, 위계는 **크기·자리·여백**으로 만든다(`00-39` §6-2 "평가하는 말 금지"와 같은 결).
🔵 이미 있는 좋은 것: 섹션1의 사진과 큰 명조 한 문장, 섹션3의 *"삶의 모든 봄날을 응원합니다"*.

### 2.2 지키는 것

- 색·글자·여백: `00-39` §3~§5. 제목 명조 · 본문 산세리프.
- 진입의 **목적지**는 그대로 — 박스① `생전 준비`(→ `/prep`) · 박스② `임종 및 사후 정리`(→ `/bereaved`) ·
  박스③ `추모관 링크로 입장` · 박스④ `파트너 로그인`. 🟡 ③④를 홈에 계속 둘지는 분기 1에서 정한다.
- 메뉴 구성은 `modeNav.ts`가 정본(`00-39` 규칙 3).

**왜 넘치나(코드 읽기)**: 칸 안이 전부 **고정 px의 합**이다. ③ = 헤더 50 + 위 여백 48 + 라벨·제목 약 68 + 24 + **줄 52px × 7** + 추모관 줄 약 40 + 아래 72 = **약 666px** → 흔한 폰(390×664, 주소창 보임)에서도 넘치고 iPhone SE(약 548)에서는 크게 넘친다. ②·④도 폰이 작으면 같은 이유로 넘친다. M-1의 *"넘치면 그 칸만 세로 스크롤"* 이 실제로 켜진 것.

🔴 **해결 방식 = 구조로 맞춘다**(픽셀 맞춤·실측 반복 금지). 칸을 **세로 flex 100%** 로 두고, **남는/모자라는 높이를 줄 간격이 흡수**하게 한다 — 화면이 작아지면 줄이 44px까지 줄고, 크면 52px까지 늘어난다.

| # | 내용 |
| :---: | :--- |
| H-1 | **목표**: 칸 ②·③·④는 **375×548(iPhone SE, 주소창 보임) 이상에서 세로 스크롤 0**. 그보다 낮은 화면만 M-1 안전망(그 칸만 스크롤)을 남긴다 — `overflow-y: auto`는 **지우지 않는다** |
| H-2 | **②·③ 칸 구조**: 칸 = 세로 flex, 높이 100%(헤더 50px 포함, M-10). 위→아래 = 위 여백 → 라벨·제목 → 메뉴 목록 → 아래 여백. **메뉴 목록만 `flex: 1 1 auto`**, 각 줄은 `flex: 1 1 0` + **`min-height: 44px` · `max-height: 52px`**. 목록이 줄 최대치로도 남는 높이는 목록 **아래**로 간다(줄이 52px보다 커지지 않음) |
| H-3 | **②·③ 여백 줄임**: 위 여백 48 → **`clamp(16px, 4svh, 48px)`** · 라벨→제목 10 → **6** · 제목→목록 24 → **`clamp(12px, 3svh, 24px)`** · 아래 **72 유지**(M-4 넘김 표시 자리 = 버튼 44 + 바닥 24). 글자 크기(라벨 12 · 제목 27 · 줄 16)는 **그대로** |
| H-4 | **추모관 링크로 입장 · 파트너 로그인 줄을 ③ → ④로 옮긴다** — M-6의 *"③이 넘치면 ④ 칸 위쪽으로 옮긴다"* 를 발동한다. ④의 **섹션3 문구 바로 아래, 푸터 위**에 같은 모양(14px 한 줄, 위 1px 선, 누르는 높이 44px)으로. 링크 입력창(눌렀을 때 뜨는 상자)도 같이 옮긴다 |
| H-5 | **③ 예산 확인**(가장 빡빡한 칸, 548 기준): 50 + 16 + 20 + 6 + 38 + 12 + **44 × 7 = 308** + 72 = **522 ≤ 548** ✓. 664에서는 줄이 약 52px 가까이 늘어난다 |
| H-6 | **④ 칸 구조**: 세로 flex 100%. 섹션3 문구 덩어리만 `flex: 1 1 auto`(가운데 정렬 유지, 위아래 여백 `2.4rem` → **`clamp(12px, 3svh, 2.4rem)`**) → 추모관 줄(H-4) → 푸터(`FooterMobile`, **접힌 상태** 기준). 푸터 아래 **48px 비움**(마지막 칸의 `4 / 4` 숫자가 저작권 줄과 겹치지 않게). 🔴 `FooterMobile` 자체는 고치지 않는다(전 페이지 공용) |
| H-7 | 🟡 **허용하는 스크롤**: ④에서 사람이 푸터 **`약관 · 대표번호 안내 보기`를 펼쳤을 때**만 넘쳐도 된다(그 칸만 스크롤, H-1 안전망) |

🔵 **실측으로 값을 찾지 않는다**(메모리 방침 — 레이아웃 값은 구조로 맞춘다). 위 숫자는 **최소·최대 한계**일 뿐, 실제 줄 높이는 flex가 화면마다 정한다. 사람 실화면은 **"스크롤이 생기는가" 한 가지만** 본다.

### 3.1 기술 메모 (분기 2에서 쓴다)

- **주소창**: 모바일 브라우저는 주소창이 접히며 보이는 높이가 바뀐다. `100vh`는 **주소창이 접힌 높이** 기준이라 처음엔 아래가 잘린다.
  → 첫 화면은 `100svh`(주소창이 **보일 때** 높이, 가장 작은 값) 기준으로 짜면 처음부터 다 보이고, 접혀도 빈틈만 조금 생긴다. `dvh`는 스크롤 중 높이가 계속 바뀌어 스냅과 함께 쓰면 흔들린다.
- **지금 스냅**: 휠 한 번 = 한 칸(`HomePage.tsx` 238행 직접 구현) · 640px 이하는 스냅 없음(`00-23` §5.4-1).
