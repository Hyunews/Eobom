# 🔑 09. 소셜 로그인 및 계정 통합 명세서

> **문서 목적**: 카카오, 네이버, 구글 3사 OAuth 2.0 연동 및 1인 1계정 멀티 소셜 계정 통합(`User 1:N SocialAccount`) 프로세스를 정의합니다.

---

## 📌 핵심 계정 통합 처리 로직

1. **단독 로그인**: 동일 이메일이 없을 경우 즉시 `User` + `SocialAccount` 생성 후 JWT 발급.
2. **이메일 중복 감지 (SocialLinkModal)**:
   * 타 소셜로 이미 가입된 이메일로 로그인 시, 10분 임시 서명 토큰 발급 후 `#socialLinkPrompt` 모달 오픈.
   * **`MERGE` (계정 통합)**: 기존 유저에 새 소셜 계정 추가 연동.
   * **`CREATE_NEW` (독립 가입)**: `User.email`을 `null`로 두고 `SocialAccount.email`에 보존하여 유니크 제약 충돌 방지.
3. **마이페이지 연동 관리 (`MyPageAuthSettings.tsx`)**:
   * 소셜 계정 추가 연동 (`GET /api/auth/:provider/link`) 및 연동 해제 (`DELETE /api/auth/unlink-provider`). 최소 1개 소셜 계정 보존 조건 적용.

## 🔐 세션 보관 위치 — `sessionStorage` (2026-08-21 개발자 확정)

> 개발자 판단: *"브라우저를 모두 닫고 다시 접속했을 때 로그인이 되어 있음 — **보안에 문제 있다고 판단**."*

| | 값 |
| :--- | :--- |
| 보관 위치 | **`sessionStorage`** (`k_ending_current_user` · `k_ending_token` — 키 상수는 `lib/storage.ts`) |
| 수명 | **브라우저 종료 시 소멸** |
| 탭 사이 | **열린 탭끼리 나눕니다**(2026-09-29 개발자 결정) — 새 탭에 로그인 정보가 없으면 이미 로그인된 다른 탭에게 넘겨받고(`BroadcastChannel`, `lib/storage.ts`), 로그아웃도 모든 탭에 전파. 정본 `00-34` §2.2 |

- 관리자·사업자 토큰은 `localStorage`입니다 — 계정군마다 다른 것은 의도된 차이입니다(`00-34` §2.2).

- ✅ **공용 PC·가족 공용 기기를 생각하면 이 도메인에서 특히 타당합니다.** 상중에는 가족이
  한 기기를 돌려 쓰는 일이 흔하고, 엔딩노트(06)·정산(04)처럼 **민감도가 높은 도메인**이 붙어 있습니다.
- ⚠️ **남는 비대칭 1건**: 진입 모드는 여전히 `localStorage`에 남습니다(`00-26` §4.3 — *"유족 행정
  절차는 여러 날에 걸침"*). 즉 **모드는 기억하는데 로그인은 안 합니다.** 의도된 절충이며,
  모드는 개인정보가 아니고 로그인은 개인정보 접근권이라 **보호 대상이 다릅니다.**
- 🟡 **권고(지금 조치 아님)**: 유족이 며칠에 걸쳐 쓰는 흐름(`07-02`)을 감안해 **"로그인 유지"
  체크박스**를 두면, 기본은 안전하게 두고 **선택한 사람만** `localStorage`를 쓰게 할 수 있습니다.
  🔴 결정 대기 — 미구현.
