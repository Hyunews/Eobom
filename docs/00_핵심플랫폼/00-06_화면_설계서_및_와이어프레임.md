## 🚪 7. 회원 유형 진입 동선 — **2026-08-14 개발자 확정**

> **이 절이 답하는 질문**: 처음 온 사람이 *"나는 어느 문으로 들어가야 하나"* 를 알 수 있는가.
> §1~3은 화면이 **존재하는지**를 적는 대장이고, 이 절은 그 화면에 **닿을 수 있는지**를 적습니다.
> 신규 화면 ID는 발생하지 않습니다 — 기존 SCR-001·SCR-008 사이의 **연결**만 다룹니다.

### 7.1 원칙 — 역할은 나누고, 모드는 나누지 않는다

| 구분 | 진입 시점에 나누는가 | 근거 |
| :--- | :---: | :--- |
| **역할** — *당신은 누구인가* (일반회원 / 사업자 / 전문가 / 운영자) | ⭕ **나눈다** | 인증 체계가 물리적으로 다릅니다. `User`(소셜) vs `Partner`·`Expert`(이메일+비번, 승인제) vs `Admin`(시드 생성) → `01-05` §3.1, `02-02` §1 |
| **모드** — *당신은 지금 어떤 상황인가* (생전 준비 / 유족) | ❌ **묻지 않는다** | `00-12` §6.2가 **A안(계정 유형 분리 가입)을 기각**했습니다 — *"한 사람이 둘 다 필요합니다. 내 엔딩노트도 쓰고 아버지 상도 치릅니다."* 권고는 C안(`Deceased` 등록으로 자동 판정) |

**이 경계를 문서에 박아두는 이유**: *"회원 유형을 나누자"* 는 말이 두 가지로 읽히기 때문입니다.
역할 분기는 지금 확정해도 뒤집히지 않지만, **모드 분기는 지금 만들면 반드시 뒤집힙니다** — `00-12` §6은 아직 🟡 미확정이고, 판정 근거인 `Deceased` 엔티티가 구현되기 전엔 자동 분기의 입력값 자체가 없습니다.

### 7.2 현황 실측 (2026-08-14, 코드 기준)

| 지점 | 파트너 진입로 | 실측값 |
| :--- | :---: | :--- |
| `Footer.tsx:136` | ⭕ 1건 | `<Link to="/partner">장사시설·전문가 파트너이신가요?</Link>` — **카피라이트 줄에 `·`로 이어붙음**. `0.82rem`(≈13px) / `#6B7280` |
| `LoginModal.tsx` | ❌ 0건 | 소셜 3종 + 데모 버튼만. 잘못 들어온 사업자에게 **출구가 없음** |
| `Header.tsx` | ❌ 0건 | 로고 · 로그인 · 계정설정 · 로그아웃 |
| `App.tsx:178-187` | 🔴 **역류** | `Header`·`Sidebar`가 `<Routes>` **바깥**에 있어 `/partner`·`/admin`에서도 렌더됩니다 |

**두 가지 결함이 있습니다.**

1. **유일한 진입로가 13px입니다.** `00-09` §2.3이 *"협상 대상이 아님"* 으로 못 박은 본문 `18px` 기준의 72% 미달이고, 위치도 사용자가 스캔에서 제외하는 **법적 고지 줄**입니다. 홈에서는 풀페이지 스냅 7섹션 중 **마지막 섹션**(`HomePage.tsx:536·601`)까지 내려야 나옵니다.
2. **잘못된 문이 포털 안까지 따라 들어옵니다.** 사업자가 `/partner`에 도착해도 상단엔 B2C `로그인` 버튼이, 좌측엔 소비자 6개 메뉴(`Sidebar.tsx:15-22`)가 그대로 있습니다. 여기서 `로그인`을 누르면 **소셜 로그인 모달이 열립니다** — 자기 계정 체계가 아닌 곳으로 되돌아가는 순환입니다.

### 7.3 진입 지점 스펙

| # | 위치 | 문구 | 이동 | 왜 여기인가 |
| :---: | :--- | :--- | :--- | :--- |

* ①은 **데모 버튼 위**에 둡니다. 데모 블록은 개발용이라 오픈 시 제거될 것이고, 그때 실제 링크가 같이 사라지면 안 됩니다.

### 7.4 포털 쪽 크롬 분리 (7.2-2 해결)

`/partner`·`/admin`에서는 **B2C 크롬을 렌더하지 않습니다.**

| | `/` `/facility` … (B2C) | `/partner` `/admin` |
| :--- | :---: | :---: |
| `Header` (로그인 버튼 포함) | ⭕ | ❌ |
| `Sidebar` (소비자 6메뉴) | ⭕ | ❌ |

로고는 클릭 가능하게 두어 역진입(파트너 → B2C 홈)을 막지 않습니다. 사업자 담당자도 개인으로는 소비자입니다.

### 7.5 이번 범위에서 하지 않는 것

* **생전 준비 / 유족 모드 분기** — `00-12` §6 확정 및 `Deceased` 구현 이후. 여기서 손대지 않습니다.
* **가입 유형 선택 화면 신설** — `PartnerPortalPage`가 이미 `AccountType = 'FACILITY' | 'EXPERT'` 탭으로 분기합니다(`PartnerPortalPage.tsx:14`). 앞단에 화면을 하나 더 두면 클릭만 늘어납니다.
* **`Admin` 진입로 노출** — §3 결정 유지.

### 7.6 부수 정리

`LoginModal.tsx:11` 주석이 경로를 `/#partner`·`/#admin`으로 적고 있습니다. `00-10` HistoryRouter 전환 이후 실제 경로는 `/partner`·`/admin`이며, 주석만 갱신되지 않았습니다. ① 작업 시 같이 고칩니다.
