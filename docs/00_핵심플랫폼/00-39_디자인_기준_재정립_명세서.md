## 🧩 6. 규칙

각 규칙은 기준 화면에서 실제로 정해진 것이고, 괄호 안은 그렇게 정한 이유다.
🔵 **번호를 제목에 세지 않는다** — §9.3대로 화면을 하나씩 구현하면서 **여기 계속 추가**되기 때문이다.
지운 번호는 비워 둔다(다른 문서가 `§6-14`처럼 참조한다).

🔴 **규칙을 읽기 전에 화면 종류부터 고른다** (2026-09-18 신설 — 근거는 아래 🔵).
**목록이라고 다 같은 목록이 아니다.** 아래 셋 중 어디에 속하는지가 규칙 1·8의 적용을 가른다.

| 종류 | 하는 일 | 기준 화면 | 생김새 |
| :--- | :--- | :--- | :--- |
| **훑는 목록**(체크리스트·문서형) | 위에서 아래로 **훑고 체크**한다. 고르지 않는다 | `care-guide` | 카드 없음. **1px 구분선 행** |

| **쓰는 화면**(폼·입력) | 값을 **넣는다** | 🔴 **`obituary`** | **§6.8**(2026-09-21 확장) |

🔵 **왜 갈랐나** — 규칙 1·8은 `care-guide` **한 화면에서** 나왔는데, 문자 그대로 읽으면 사람이

(2026-09-18). 규칙이 틀린 게 아니라 **적용 범위를 안 적었던 것**이다.

### 6.1 구조

1. 🔴 **훑는 목록에는 카드와 그림자를 쓰지 않는다.** 구분은 **1px 선과 여백**으로 한다.
   (카드 안에 카드, 그 안에 칩 트랙 — 상자가 3겹이었다)
   🔴 **적용 범위는 훑는 목록·문서형 화면까지다**(2026-09-18 정정). 고르는 목록은 규칙 1-1.

### 6.2 활자와 위계

4. 🔴 **제목은 명조, 본문은 산세리프.** (§4)
5. 🔴 **긴급도를 색 배지로 만들지 않는다.** *되돌릴 수 없음* 을 **12px 붉은 글자 한 줄**로
   제목 위에 둔다. (회색 알약 배지가 모든 항목에 붙어 위계가 사라져 있었다)
6. 🔴 **기한은 오른쪽 끝 열에 회색으로 정렬**한다. 제목 옆에 붙이지 않는다.
   (제목 길이에 따라 배지가 다음 줄로 밀려 레이아웃이 흔들렸다)

6-1. 🔴 **목록에는 설명문을 두지 않는다 — 웹·모바일 공통** (2026-09-18 사람 결정).
   한 줄은 **제목 + 기한**이 전부다. 설명이 필요하면 **제목을 눌러 모달**로 본다(규칙 9).
   🔵 처음에는 *"넓은 화면은 읽을 여유가 있으니 웹에는 남기자"* 고 했으나, **같은 문장이 모달에서는
   빠지고 목록에는 남는** 상태가 되어 규칙 11과 어긋났다. 목록은 **훑는 곳**이지 읽는 곳이 아니다.

6-2. 🆕 🔴 **평가하는 말을 쓰지 않는다 — "AI 어투 금지"** (2026-09-22 사람 지시로 등재).
   *"실무상 가장 강력한 경로입니다"* · *"가장 확실한 방법"* · *"놓치지 마세요"* 처럼 **우리가 대신
   판단해 준 말**을 화면에 두지 않는다. 화면은 **무엇이 나오는지·언제까지인지**만 적고,
   **무엇이 중요한지는 읽는 사람이 정한다.**
   🔵 사실을 적는 것은 평가가 아니다 — *"구독 이름은 여기서 나옵니다"* 는 남고,
   *"— 실무상 가장 강력합니다"* 는 뺀다. 같은 줄에서 뒷부분만 떼면 된다.
   🔴 **강조가 필요하면 자리로 한다** — 위에 두거나 굵게 하거나 붉은 한 줄(규칙 5)을 쓴다.
   **형용사로 하지 않는다.**

### 6.3 조작

7. 🔴 **버튼은 밑줄이 아니라 테두리**로 만든다. (`내용 보기` · `전문가 상담` · `장사시설 찾기`)
8. 🔴 **체크는 체크박스를 눌러야만 된다.** 행 전체를 클릭 영역으로 삼지 않는다.
   🔴 **훑는 목록에만 해당**(2026-09-18 정정) — 체크와 열람이 **다른 동작**이라 가른 것이다.
8-1. 🔴 **고르는 목록은 행·카드 전체가 클릭 영역이다.** 동작이 *"고른다"* 하나뿐이라 가를 게 없다.
   (구현: `counseling` 행 `role="button"` · `facility` 카드 · `pickup` 카드 제목)
   🔵 카드 면의 CTA(`견적 신청`)처럼 **모달을 건너뛰는 지름길 버튼**은 둘 수 있다 — 대신
   `stopPropagation`으로 행 클릭과 겹치지 않게 한다(`00-38` §8.2와 같은 처리).
9. 🔴 **항목 제목을 누르면 안내가 열린다.** 체크와 안내는 다른 동작이다.

### 6.4 안내(모달)

10. 🔴 **모달은 세 줄뿐이다** — **제목 · 기한 · 근거**. 그 이상 넣지 않는다.
    🔵 *근거*와 *기관*을 따로 두지 않는다 — **근거 줄 자체가 링크**다(§6-14). 기관이 특정되는
    3건만 그 자리에 기관명이 오고, 나머지는 법령명과 조문이 온다.
11. 🔴 **해설하거나 조언하는 문장을 넣지 않는다.** 모달은 **사실만** 준다.
    (2026-09-18 사람 결정 — *"화장 후에는 부검·재확인이 불가능합니다"*, *"'언제까지'가 아니라
    '언제 이후에' 가능한지의 문제입니다"* 같은 문구를 뺐다. 해석은 사용자 몫이고, 더 필요하면
    전문가 상담으로 보낸다.)
    🔵 **모달에 완료 버튼을 두지 않는다** — 체크 경로가 둘이 되면 규칙 8과 어긋난다.

### 6.5 모바일

12. 🔴 **간소화하고 줄글을 최소로 한다.** (2026-09-18 사람 지시)
    🔵 목록에서 설명문을 빼는 것은 이제 **웹도 같다**(규칙 6-1). 아래는 **모바일에만** 해당한다.
    - *"가장 급한 것"* 같은 **상단 요약 블록을 두지 않는다**
    - 부제를 두지 않는다 (제목이 이미 말하고 있다)
    - 각 행 오른쪽에 **꺾쇠(›)** 로 "누르면 더 있다"를 표시한다
    - 모달은 **바텀시트**로 열고, 닫기는 X 아이콘이 아니라 **하단 버튼**으로 둔다
    - 모달 안에서도 더 줄인다 — 근거를 `장사법 제6조`까지만(웹은 `감염병 등 예외`도 표시)

### 6.8 폼·입력 — **그룹② 착수 전 선행 확정** (2026-09-18)

🔴 **아직 그룹②(폼) 시안은 없다.** 그런데 상속세 계산기 모달을 먼저 고치기로 해서, **거기서
나오는 입력 규칙이 그룹②의 씨앗**이 된다. 그래서 임시 인라인으로 줄이지 않고 **클래스로 만들어
여기 적는다** — `obituary`가 그대로 물려받는다(§9.2가 말한 *"§6에 폼 규칙이 없다"* 의 첫 칸).

15. 🔴 **입력 칸은 `.v2-field` / `.v2-input` / `.v2-field-hint`** 로 만든다. 옛 `.form-input`
    (`index.css:619`, 높이 52px)을 그대로 쓰지 않는다.

| 무엇 | 옛 `.form-input` | 🔴 확정값 | 근거 |
| :--- | :--- | :--- | :--- |
| 높이 | 52px | **44px**(데스크톱) · **48px**(모바일) | `00-38` §11 DoD #5 — 손으로 찍는 면의 하한이 44px |
| 글자 | 16px | 🔴 **16px 그대로 — 내리지 않는다** | iOS Safari는 **16px 미만 입력에 포커스하면 화면을 자동 확대**한다(돌아올 때 레이아웃이 틀어짐). `00-38` §3.2 본문 16px 표준과도 같다 |
| 좌우 패딩 | `0 1rem` | **0 14px** | |
| 라벨 | 16px | **13px** `--v2-fs-label` | |
| 보조문구(`* 약 3.00억원 …`) | 16px 본문색 | **13px** `--v2-fs-label` + `--v2-text-muted` | 🔵 **화면을 무겁게 만든 진짜 원인이 여기다** — 입력마다 본문 크기 문장이 한 줄씩 붙어 있었다 |

🔵 **"입력 칸을 줄여달라"를 높이만으로 읽지 않는다** — 높이는 44px가 하한이라 8px밖에 못 줄인다.
실제로 줄어드는 양은 **라벨·보조문구·간격**에서 나온다.

#### 6.8-1 🆕 **그룹② 대표 `obituary`에서 확정된 것** (2026-09-21 등재)

> 위 15번은 **계산기 모달에서 나온 씨앗**이었고, 여기부터는 **폼 대표 화면을 실제로 구현하면서**
> 나온 것이다. 🔵 `mypage` 등 남은 그룹② 화면은 **이걸 그대로 물려받는다** — 다시 정하지 않는다.

16. 🔴 **필수는 라벨 옆 12px 붉은 글자 `필수`** 로 표시한다. **별표(`*`)도 배지도 아니다** —
    긴급도를 배지로 만들지 않는 **규칙 5와 같은 결**이다. 강조가 필요한 선택 항목만 같은 자리에
    흐린 `선택`(`.v2-opt`)을 붙이고, **나머지 선택 항목에는 아무 표시도 하지 않는다**(표시가
    모든 줄에 붙으면 표시가 아니다).

17. 🔴 **오류는 폼 전체가 아니라 칸마다 붙인다.** 브라우저 기본 검증(`required` 속성)을 쓰지
    않는다 — 기본 말풍선은 **한 번에 한 칸만** 알려주고 우리 활자·색을 따르지 않는다.
    제출에 실패하면 **네 가지가 동시에** 일어난다.

    | | 무엇 | 값 |
    | :---: | :--- | :--- |
    | ① | 칸 아래 붉은 문장 | `.v2-error-text` — 보조문구 자리를 **대체**한다(같이 쌓지 않는다) |
    | ② | 칸 테두리 | `aria-invalid="true"` → **1.5px 붉은 테두리** |
    | ③ | 폼 위 요약 한 줄 | *"확인이 필요한 항목이 **N개** 있습니다. 붉게 표시된 곳을 확인해 주세요."* (`role="alert"`) |
    | ④ | 포커스 | **화면 위에서 첫 번째** 오류 칸으로 옮긴다 |

    🔴 **오류 문구는 "무엇을 하라"로 쓴다** — *"고인 성함을 입력해 주세요."* (`필수 항목입니다` ✗).
    🔵 **고친 칸은 즉시 푼다** — 값을 한 글자 고치면 **그 칸의 오류만** 사라진다(제출을 다시
    기다리지 않는다). 나머지 칸은 그대로 둔다.

18. 🔴 **체크는 한 가지 모양뿐이다**(`.v2-check`) — 동의·토글·선택을 서로 다르게 그리지 않는다.
    상자 **20px** · 행 최소 높이 **44px**(터치 하한, `00-38` §11 DoD #5) · 글자 16px ·
    부연은 아래 줄에 13px(`.v2-check-sub`).
    🔴 **폼의 체크는 라벨 전체가 클릭 영역이다**(`<label for>`) — **규칙 8의 예외**다.
    규칙 8이 상자만 누르게 한 이유는 훑는 목록에서 *"체크"* 와 *"안내 열기"* 가 **경쟁**하기
    때문인데(규칙 9), 폼에는 그 경쟁 동작이 없다. **규칙 8-1과 같은 논리**다.

19. 🔴 **저장 상태는 버튼이 말한다.** 스피너·토스트·별도 안내 줄을 만들지 않는다.
    누르는 순간 **버튼을 잠그고**(`disabled` + `aria-busy`) **글자를 바꾼다** —
    `부고장 만들기` → `처리 중…` / `수정 사항 저장` → `저장 중…`.
    🔵 **잠그는 것이 중복 제출 방지의 본체다** — 안내는 그 사실을 말할 뿐이다.

20. 🔴 **미리보기에는 설명문을 붙이지 않는다.** 웹은 오른쪽 열(`sticky`), 모바일은 폼 안
    확인 사항 **바로 앞**에 둔다(§5-1). *"입력하신 내용이 이렇게 보입니다"* 같은 줄은 두지
    않는다 — **보면 아는 것**이고, 규칙 12(줄글 최소)에 걸린다.
    🔵 **카톡 카드 미리보기는 이 문서의 색·그림자 규칙 밖이다** — 그건 **우리 화면의 면이
    아니라 카카오톡 화면을 그린 그림**이다(바깥 면 `#DCE3E8`, 카드에 그림자 있음). 🔴 그래서
    **여기 색을 우리 토큰으로 바꾸지 않는다** — 실제와 달라지면 미리보기가 거짓말이 된다.

21. 🔴 **수정은 새 화면이 아니라 모달**이다(`.v2-modal.is-form`, **560px** · 안쪽 여백 32px).
    **규칙 10(모달은 세 줄)은 안내 모달의 규칙**이고, 폼 모달은 거기 해당하지 않는다.
    - 모달 안에서는 **구간 제목과 구분선을 빼고** 필드만 **16px 간격**으로 나열한다(`.is-plain`).
    - 🔴 **닫기는 `X`가 아니라 하단 `[취소]` 버튼**이다 — 폼은 **쓰다 만 값이 사라지는** 곳이라
      닫기가 눈에 띄어야 한다.
    - 모바일은 **바텀시트**(규칙 6-5와 같음) · 버튼 높이 52px · `[취소] 1 : [저장] 2` 비율.

## ✅ 7. 웹과 모바일의 관계

🔴 **같은 화면이지만 밀도를 다르게 가져간다.** 기존 구현은 웹과 모바일이 **같은 카드 구조를
공유**해서 어느 쪽에도 맞지 않는 중간 형태가 됐다.

| | 웹 | 모바일 |
| :--- | :--- | :--- |
| 설명문 | 🔵 **둘 다 모달로 보낸다**(규칙 6-1) | ← 같음 |
| 상단 요약 | *가장 급한 것* 블록 있음 | **없음** |
| 기한 | 오른쪽 끝 열 | 제목 아래 한 줄 |
| 구간 이동 | 좌측 목차(세로) | 상단 탭(가로 스크롤) |
| 모달 | 가운데 540px · 근거에 부연 표시 | 바텀시트 · 근거는 조문까지만 |

🔵 **차이는 밀도가 아니라 배치다.** 규칙 6-1로 설명문이 양쪽에서 빠지면서, 웹과 모바일의 차이는
*"무엇을 보여주는가"* 가 아니라 *"어디에 놓는가"* 로 줄었다. 기존 구현이 **같은 카드 구조를 공유해**

### 9.3 각 화면에서 하는 일

1. **구현** — 🔴 **인라인이 아니라 클래스로.** `index.css`(100KB)에 넣지 말고 분리한다.
2. **패턴 추가** — 새로 나온 공통 클래스를 이 문서 §6에 등재. 다음 화면이 그걸 쓴다.
3. **확인** — 실기동은 사람. 🔵 수치 확인이 필요하면 `00-38` §11.2의 360px iframe 방식을 쓴다
   (창 리사이즈는 Chrome 최소폭에 걸려 500px까지밖에 안 줄어든다).

🔴 **하지 않는 것**: 화면을 순회하며 **수치 위반 목록을 만드는 일**. 그게 §2의 반복이었다.
