## ✅ 2. 이 제안이 해결하는 것

### 2.1 `00-12` §6.2의 미결을 푼다 — **B안의 유일한 약점을 구조로 없앱니다**

`00-12` §6.2는 모드 전환 방식을 3안으로 비교하고 **개발자 확정 대기**로 남겨뒀습니다(§8 #5, *막는 것: **"프론트 전반"***).

| 안 | 방식 | `00-12`의 평가 |
| :--- | :--- | :--- |
| A | 계정 유형 분리 | ❌ 한 사람이 둘 다 필요합니다 |
| B | **수동 모드 전환** | 🟡 단순하지만 **전환 존재를 모르면 무용** |
| C | 컨텍스트 자동 + 수동 | ✅ 권고 — `Deceased` 등록으로 자동 판정 |

🔵 **개발자 제안은 B안이되, 기각 사유가 성립하지 않습니다.** B안이 밀린 유일한 이유가 *"전환 존재를 모르면 무용"* 인데, **4박스가 첫 화면이면 전환 존재를 모를 수가 없습니다** — 선택이 곧 진입이기 때문입니다. **화면 구조가 B안의 약점을 제거합니다.**

### 2.2 🔵 `Deceased` 의존을 끊는다 — **이것이 가장 큰 실익입니다**

C안 권고의 자동 판정은 **`Deceased` 등록**(추모관 개설·정산 실행)을 신호로 씁니다. 그런데 **`Deceased`는 현재 04·05·07을 전부 묶고 있는 블로커**입니다(`context.md` "지금 막고 있는 것", `00-13` §4.5-3).

> 🔵 **즉 C안은 "블로커가 풀려야 만들 수 있는" 안이었습니다.**
> 개발자 제안은 **데이터로 추론하는 대신 사용자가 직접 고르게** 하므로 **지금 만들 수 있습니다.**
> ⚠️ 다만 이건 **C안의 폐기가 아니라 선후 배치**입니다 — `Deceased`가 확정되면 자동 판정을 **덧붙일** 수 있고, 그때 수동 선택은 그대로 남습니다(= C안의 "수동" 부분).

### 2.3 홈의 경로 이중화가 해소된다

`00-23` §5.3이 지적한 문제 — **같은 목적지로 가는 경로가 홈에 2개**(4박스 / 사이드바) — 가 사라집니다. 홈에서 메뉴를 걷어내면 **4박스가 유일한 진입점**이 됩니다.

## 🔴 4. 고쳐야 할 설계

### 4.1 🔴 "각각 로그인"은 **4개 중 1.5개만 맞습니다**

`00-23` §4.1이 2026-08-18에 확정한 원칙과 정면으로 부딪힙니다 — *"막을 것은 **쓰기**이지 **보기**가 아니다."*

| 박스 | 진입 시 로그인 강제하면 | 판정 |
| :--- | :--- | :---: |
| ① 생전 준비 | 06은 맞지만 **02 전문가 목록 조회까지 막힙니다**(`GET /api/experts` 인증 불필요) | 🟡 절반 |
| ② 유가족 | 🔴 **사별 직후 유족에게 로그인 벽.** `07-02`의 *"한 줄이라도 남으려면 최상단"* 이 무너집니다 | ❌ |
| ③ Guest | 🔴 **대상이 비회원 조문객입니다.** `00-23` §2.2가 *"어느 문서에도 없던 경로"* 라 부른 그 분기가 **다시 막힙니다** | ❌ |

### 4.2 🟡 대안 — 진입 조건을 **"모드 선택"** 으로

```
박스 클릭  →  모드 확정 + 맞춤 메뉴 등장      ← 개발자가 원한 결과

```

| | 개발자 원안 | 🟡 권고안 |
| :--- | :--- | :--- |
| 맞춤 메뉴 | ✅ | ✅ **동일** |
| 홈 메뉴 제거 | ✅ | ✅ **동일** |

### 4.2-1 ✅ **확정: 절충안** — ①④만 로그인 (2026-08-19)

### 4.3 🔴 재방문자 — 홈에서 메뉴를 없애면 **매번 4박스를 거칩니다**

`00-23` §5.3이 사이드바 유지에 동의한 이유가 *"재방문 사용자는 사이드바로 바로 간다"* 였습니다. 홈의 메뉴를 걷으면 그 경로가 사라집니다.

> 🟡 **권고: 모드를 기억합니다**(`00-23` §6 #7 *"모드 전환을 기억할지"* 가 여기서 닫힙니다).
> `sessionStorage`가 아니라 **`localStorage`** 를 권고합니다 — 유족의 행정 절차는 **여러 날에 걸칩니다**(`07-02` 법정기한 최장 6개월). 브라우저를 닫았다고 모드가 풀리면 매번 다시 고르게 됩니다.
> ⚠️ **단, 홈으로 돌아오면 4박스는 항상 보여야 합니다** — 기억한 모드로 *자동 이동*시키면 다른 모드로 갈 방법이 사라집니다. **기억은 "메뉴 상태"에만 적용하고 진입 화면은 건드리지 않습니다.**

### 4.4 🔴 모드 전환 경로가 없으면 **갇힙니다**

유가족 모드로 들어간 사람이 자기 엔딩노트를 쓰려면 어떻게 합니까?

| 안 | 방식 | 평가 |
| :--- | :--- | :--- |
| **A** | 🟡 **헤더에 모드 칩**(*"유가족 모드 ▾"*) → 클릭 시 전환 | 🟡 **권고** — 항상 보이고 현재 모드도 알려줍니다 |
| B | 사이드바 최하단에 *"다른 도움 찾기"* | 🟡 가능하나 스크롤 끝이라 발견성이 낮음 |
| C | 홈 로고 클릭 → 4박스 | ⚠️ **최소한 이건 반드시 동작해야 합니다**(A·B와 무관하게) |

⚠️ **헤더 공간 주의**: `Header.tsx`는 좌측 로고 · 우측 로그인/프로필 구조라 중앙이 비어 있어 자리는 있습니다. **다만 walkthrough (34)가 375px에서 헤더 가로 오버플로를 이미 보고**했으므로, 칩을 추가하면 **모바일에서 악화됩니다.** 모바일은 아이콘만 노출하거나 사이드바로 내리십시오.
