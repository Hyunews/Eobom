# 🏠 00-23. 메인화면 진입구조 개편 — 검토서

> **문서 성격**: 검토서 · **개발자 구상안에 대한 검토**. `[Claude:Opus]` 작성(2026-08-18).
> **계기**: 개발자 제안(2026-08-18) — *"메뉴는 일단 그대로 두되, 메인 화면에서 **생전 / 임종 /
> 게스트 / 파트너** 이런식으로 버튼을 통해 접근하는게 어떨까 해서. **Main에 박스 형태로 각각 노출**
> (메뉴바의 순서 및 내용은 그대로 두는게.. 좋을듯)"*
> **정본 관계**: IA 정본은 `00-02` §3 · `00_DOCS_INDEX` 도메인 번호 체계. 화면 대장은 `00-06`.
> 이 문서는 **메인화면 진입 구조 하나**만 다룹니다.
> **표기**: ✅ 확정 / 🟡 권고 / 🔴 확정 필요 / 🔵 개발자 확정
>
> 🔄 **2026-10-12 정리 — 홈 레이아웃의 정본은 `00-40`입니다.** 이 문서의 4박스(`EntryBoxes`)·박스 오버레이·풀페이지 스냅·`/prep`·`/bereaved` 페이지(`DomainOverviewPage`)는 **전부 삭제·대체**됐습니다(`00-40` 머리 "레이아웃은 이 문서가 대체"). 메뉴 구성의 정본은 `00-26` §3(현행 값 = `modeNav`).

## ✅ 2. 이 제안이 해결하는 것

### 2.2 🔵 Guest — **어느 문서에도 없던 경로입니다**

`00-13`이 공유 링크를 다섯 개 안까지 비교하며 길게 다뤘지만, **전부 "링크를 누르고 들어온 사람"만
가정**했습니다. **링크를 잃어버렸거나, 카톡을 지웠거나, 이어봄을 검색해서 들어온 조문객**은
지금 홈에서 **갈 곳이 없습니다.**

> 🔵 **이건 개발자가 찾은 진짜 공백입니다.** `00-13` §8에 미결로도 안 올라와 있었습니다.
> 🔴 다만 구현 방식에 보안 논점이 있습니다 — §4.4.
>
> ✅ **지금(10-12)**: 홈 섹션2 하단 **"추모관 링크로 입장"** 줄로 존속합니다(`HomeDesktop`·`HomeMobile`, `00-40` W-6).

## 🔴 4. 고쳐야 할 설계 4가지

### 4.4 🔴 Guest 링크 입력창 — **`00-13` §6.1과 충돌할 수 있습니다**

`Memorial.slug`는 **추측 불가 토큰**이고, `00-13` §6.1은 **PRIVATE·닫힌 추모관은 404로 존재
자체를 숨긴다**고 정했습니다. 지금은 URL을 직접 입력해야 해서 자동화가 어렵지만,
**메인에 입력창을 두면 스크립트로 돌릴 수 있는 표면이 생깁니다.**

| 방식 | 평가 |
| :--- | :--- |
| **토큰만 입력** (`slug` 직접) | 🔴 **brute-force 표면.** 권고하지 않음 |
| **🟡 받은 링크 전체 붙여넣기**(권고) | ✅ 사실상 URL 이동과 동일해 **표면이 늘지 않습니다.** 링크를 가진 사람만 통과 |
| 안내 문구만(입력 없음) | 🟡 가장 안전하나 **링크를 잃은 사람은 여전히 갈 곳이 없음** — 이 분기를 만든 이유가 사라짐 |

> 🔴 **어느 방식이든 지켜야 할 것 2가지**: ①**실패 메시지를 하나로 통일**해야 합니다
> (*"없는 링크"* 와 *"비공개 링크"* 를 구분해 알려주면 §6.1의 존재 은닉이 깨집니다)
> ②**시도 횟수 제한**.
>
> 🔵 **지금 상태(10-12 코드 대조)**: ✅ ② 요청 횟수 제한 있음(`middleware/rateLimit` — 전체 분당 300 · 공개 쓰기 분당 10) · ✅ ① 서버 응답은 없음·비공개·닫힘·숨김 모두 **같은 404·같은 문구**(`memorialController`). 홈 입력창은 링크 형식 검사 문구만 따로 냅니다(존재 여부를 알려주지 않음).
> 🟡 다만 입력창 해석기 `parseMemorialLink`(`memorialLink`)는 **slug만 넣어도 받습니다** — 위 표의 "토큰만 입력"과 같은 동작입니다. 횟수 제한이 있어 표면은 작지만, "링크 전체만" 받을지는 공개 전에 정할 일입니다(결정 대기).

## 🟡 5. 수정 제안

### 5.1 ✅ "준비 중"을 숨기지 않고 명시한다 — **이미 확정된 패턴입니다**

`00-14` §2.2에서 개발자가 확정한 원칙을 그대로 적용합니다.

> *"**지우면 회의에서 보여줄 화면이 없어지고, 두면 거짓말입니다. 목업임을 화면에 명시**하면
> 둘 다 해결됩니다."*

🟡 **박스 안 항목을 세 상태로 표시**합니다.

| 표시 | 대상 | 동작 |
| :--- | :--- | :--- |
| **(표시 없음)** | 01 · 02 · 07 · 파트너 | 바로 진입 |
| 🟡 **"미리보기"** | 04 · 06 | 진입은 되지만 **목업임을 화면에 명시** |
| ⬜ **"준비 중"** | 03 · 05 · Guest | **비활성.** 눌러도 이동하지 않음 |

> ✅ **이러면 지금 만들 수 있고, 구현이 끝날 때마다 표시만 떼면 됩니다.**
> 🔵 **그리고 이 표가 곧 로드맵이 됩니다** — 사장님께 *"지금 어디까지 왔나"* 를 한 화면으로 보여줍니다.
>
> 🔵 **지금(10-12)**: 표기 장치는 남아 있습니다(`modeNav`의 `NavStatus` · `Badge`). 다만 메뉴 전 항목이 열려(`active`) **배지가 붙는 항목은 0개**입니다. 위 표의 "대상" 칸은 08-18 당시 값입니다.
