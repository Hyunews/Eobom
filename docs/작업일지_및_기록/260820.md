### 6. [사용자] *"발인 일시 넣자..!"* — 필수 4개 확정

- ✅ **필수 = 고인 성함 · 상주 성함 · 빈소 위치 · 발인 일시.** `funeralAt`을 non-null로 바꾸고
  개설 검증에 추가. **별세 일시는 승인 대상이 아니었으므로 선택(접어둠)으로 내림** — 없어도
  `故 ○○○`로 성립한다.
- 🔵 **발인이 필수가 되면서 §10 #4(부고장 수명) 권고가 바뀌었다** → `07-03` **§6.2-4 신설**.
  - §6.2-3이 *"연락처·계좌 노출의 실효 완화는 부고장 종료 하나뿐"* 이라 했는데, **수동 종료만
    두면 유족이 잊었을 때 연락처와 계좌가 실린 페이지가 무기한 살아남는다.** 사별 직후에
    *"부고장을 닫아야지"* 를 기억할 유족은 많지 않다.
  - 이전엔 발인이 선택이라 자동 계산이 불가능했다. **이제 기준이 항상 존재한다.**
  - → **발인 + N일 자동 종료 + 유족의 수동 조기 종료.** 🔴 **N값은 미정**(발인 직후 끊으면 늦게

  - ⚠️ **`00-13` §4.3의 phase 전환 트리거 문제를 다시 여는 것이 아니다** — 거기서 문제였던 건
    한 레코드가 성격을 바꾸는 사건이고 E안은 레코드를 둘로 나눠 그걸 없앴다. 여기 것은
    **부고장 레코드 하나의 만료**일 뿐이고 **추모관은 계속 산다.**
  - ⚠️ 구현은 **배치가 아니라 조회 시점 판정**(`funeralAt + N < now()`) — 스케줄러를 새로
