### 1. Domain01 — LAN IP 환경 소셜 로그인 리다이렉트 동적 처리

- 프론트 `config.ts`: `BACKEND_URL`을 접속 호스트 기준으로 자동 계산 (localhost/LAN IP 모두 대응), `VITE_BACKEND_URL` override 지원.
- 백엔드: 로그인 시작 시점 Referer로 프론트 오리진을 캡처해 OAuth `state`에 실어 콜백까지 전달 → 성공/실패 리다이렉트 모두 LAN IP 대응.
- 보안: Referer 무조건 신뢰 시 외부 사이트가 로그인 토큰을 탈취할 수 있는 오픈 리다이렉트 위험 발견 → 사설 대역(10.x / 172.16–31.x / 192.168.x) + localhost + 5173 포트로만 신뢰 범위 제한.
- 상세: `에이전트_기록/walkthrough.md` 2026-08-07 항목.

### 2. Domain01 — 위치 오탐지 · 카카오 지도 미작동 조사

- **위치 오탐지**: 코드 버그가 아니라 브라우저 Geolocation API의 보안 컨텍스트 제약(HTTPS/localhost만 허용)이 원인. 하드코딩 폴백(서울 서초)이 조용히 적용되던 것을 "⚠ 실제 위치 아님(기본값)" 배지로 노출하도록 수정.
- **카카오 지도**: 컴포넌트 코드는 정상. 카카오 디벨로퍼 콘솔의 등록 도메인에 로컬 LAN IP가 빠져 있던 것이 원인 — 사용자가 IP 추가 후 정상 렌더링 확인. 실패 시 무한 스피너만 돌던 코드 결함은 명확한 에러 UI로 교체.

### 3. mkcert 기반 로컬 HTTPS 구축 ✅

- `certbot`(공인 도메인 전용이라 사설 IP 불가) · `openssl`(브라우저 경고 + SAN 설정 번거로움) 검토 후 **mkcert** 채택. Gemini 교차검토 승인 후 진행.
- 로컬 CA를 Windows 신뢰 저장소에 설치, `localhost` / `127.0.0.1` / `192.168.0.111` 인증서 발급 (`eobom/.certs/`, gitignore 대상).
- Vite · Express 둘 다 인증서 존재 여부로 HTTPS/HTTP 자동 판단 → 인증서 없는 배포 환경에서는 그대로 HTTP 폴백.
- **사용자 실브라우저 검증 완료**: 위치 권한 프롬프트 정상 노출 / 실제 위치 감지 / 폴백 배지 미노출 3항목 모두 확인.
- 주의: 주소창에 `https://`를 반드시 명시해야 함(생략 시 브라우저가 http로 시도 → 서버가 거부). 정상 동작이며 버그 아님.
