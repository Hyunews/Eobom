### 1. 처음 진단 — 소비자 쪽이 통째로 목업 (2026-08-11 착수 전)

`02-02`로 **전문가 B2B 계정 체계는 완성**됐지만, **소비자(B2C) 쪽이 통째로 목업**입니다.

| 영역 | 상태 |
| :--- | :--- |
| `Expert` 스키마 · 가입/로그인/refresh/내정보 API | ✅ 구축 완료 |
| 운영자 승인 API (`/api/admin/experts`) | ✅ 구축 완료 |
| 전문가 본인 대시보드(프로필·승인상태) | ✅ 구축 완료 |
| **승인된 전문가를 소비자에게 노출** | ❌ **없음** — `CounselingPage`는 `mockData/experts.json` 4건 하드코딩 |
| **상담 신청 접수** | ❌ **없음** — 예약 모달이 `alert()`만 띄우고 저장 안 됨 |
| **전문가가 자기 상담 신청을 확인** | ❌ **없음** |

즉 지금은 **전문가가 가입해도 아무 일도 일어나지 않습니다.** 가입을 받아놓고 들어오는 문의가 없으면
B2B 영업 자체가 성립하지 않으므로, 이번 단계의 목표는 **"가입 → 노출 → 문의 도착"의 최소 루프를 닫는 것**입니다.

→ ❌ 3건 모두 08-11 구현(§9).

### 8. 09-29 확정 당시 서술 — `maskedAt` 미사용 · 가리기와 파기 (2026-09-29 · 10-06 구현)

- 🔄 **연락처 가리기 — 응답 시점에 가린다(2026-09-29 개발자 확정).** DB 원본은 고치지 않는다(`Lead`와 같은 방식 — `leadController.ts` `maskPhone`).
  - `maskedAt` 컬럼은 이번에 쓰지 않는다 — 실제 파기(DB에서 지우기) 때 쓴다.
  - 🔴 **이건 "가리기"이지 "파기"가 아니다.** 동의 문구의 *"목적 달성 후 파기"*(`consultService.ts` `retention`)를 지키려면 DB에서 지우는 배치가 필요하다 — **공개 전 과제**(`.harness/memory/backlog.md` ㉒, `Lead`와 함께).
    ✅ **10-06 구현**(`dbf9ce8`·`retentionPurgeService.ts`) — 끝난 날부터 90일 지나면 DB 원본의 이름·연락처를 마스킹하고 `maskedAt`을 채운다(`00-19` 제4조·제8조). 실행은 파기 스크립트(`npm run purge` = 미리보기, `--confirm`은 사람만). backlog ㉒는 10-07 종결(`backlog_아카이브_2610.md`).

→ 10-06 구현은 이름·연락처에 더해 상담 내용(`content`)도 지웁니다(본문 §8 ②).

### 9. 구현 순서표 · 08-11 검증 기록

| 단계 | 상태 | 내용 | 산출물 |
| :---: | :---: | :--- | :--- |
| **1** | ✅ | `ConsultRequest`·`ConsultNumberCounter` 스키마 + `Expert.isPublished` 마이그레이션 | `schema.prisma` |
| **2** | ✅ | 공개 API `GET /api/experts`, `/:id` (**필드 화이트리스트 주의**) | `expertPublicController.ts` |
| **3** | ✅ | 상담 신청 `POST /api/experts/:id/consult-requests` + `EC-` 발번 서비스 | `consultService.ts` |
| **4** | ✅ | 전문가 본인 신청 조회/상태변경 (소유권 검증) | `expertController.ts` 확장 |
| **5** | ✅ | 운영자 `isPublished` 토글 + 전체 신청 조회 | `adminController.ts` 확장 |
| **6** | ✅ | `CounselingPage` 목업 제거 + 실연동, `ConsultRequestModal` 신설 | 프론트 |
| **7** | ✅ | `BizDashboard` "받은 상담 신청" 탭, `AdminPage` 공개 토글 | 프론트 |

**1~5는 백엔드만이라 curl로 전부 검증 가능합니다.** 6~7은 브라우저 확인이 필요합니다.

> **2026-08-11 Stage 1 전 단계 완료** (구현: walkthrough `2026-08-11 (6)`). 1~5단계는 **17단계 curl 전수 검증 통과** — 승인/공개 두 축 분리, 민감 필드 미유출, 동의 없음 400, 미승인 전문가 404, `EC-` 발번, 소유권 검증까지 확인했습니다. **6~7단계의 브라우저 클릭 E2E는 아직 미검증**입니다.
>
> 공개 가능한 전문가는 현재도 **0명**이라 `CounselingPage`는 빈 상태 UI만 노출됩니다. Stage 1 루프가 실제로 도는지는 전문가 계정이 최소 1건 승인·공개된 뒤에야 확인됩니다.

→ 10-08 기준 공개 전문가 수는 확인하지 않았습니다(클라우드 세션은 DB를 보지 않음). 지금 운영자 전체 신청 조회 함수는 `moderationController.ts` `listConsultRequestsForAdmin`에 있습니다.
