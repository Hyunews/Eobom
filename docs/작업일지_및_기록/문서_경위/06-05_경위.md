### 🔴 4. 가장 위험한 지점 — STT 초안(⑨)과 음성 메시지의 혼동

**`06-04` §6.4-2가 세운 원칙**: 말로 남기는 유언장 **초안(⑨)은 본인 전용이고, 사후에도 유족에게
전달하지 않습니다.** 유족이 받으면 ***"이게 아버지 유언장인가"*** 로 읽기 때문입니다.

**그런데 이제 유족에게 실제로 전달되는 음성이 생깁니다.** 같은 마이크, 같은 녹음 버튼입니다.

| 혼동 방향 | 결과 |
| :--- | :--- |
| 보관함에 **유언 내용**을 말함 | 🔴 `06-02` §4.3이 기각한 **녹음유언이 이어봄을 통해 유족에게 배달**됩니다. 형제 분쟁 시 *"아버지가 이렇게 말했다"* 의 증거로 쓰입니다 |
| 엔딩노트 ⑨에 **작별 인사**를 말함 | 🟡 유족에게 영영 가지 않습니다. 사용자는 남겼다고 믿습니다 |

> 2026-08-26 정정(§4.2)으로 ⑨에서 음성이 빠져 두 번째 줄의 전제는 사라짐. 첫 줄 위험은 본문 §4 표에 남김.

### 5.1 🔴 지금 넣지 못하는 이유

`.harness/systems.md` §5 실측:

> 업로드 사진이 백엔드 **로컬 디스크(`eobomDev/backend/uploads/`)**에 저장된다.

> **추모관 오픈 금지**(`05-01` §2.6).

| 사진과 음성 메시지의 차이 | |
| :--- | :--- |
| 추모관 사진 | 소실되면 다시 올릴 수 있습니다 |
| **유족 메시지 음성** | 🔴 **소실 시점에 본인이 이미 없습니다.** 다시 올릴 사람이 없습니다 |

> 🔴 **이 도메인의 음성은 "수십 년 뒤 사후 전달"이 전제**라 **로컬 디스크가 원리적으로 불가**합니다.
> 사진보다 **더 엄격한** 선행 조건입니다.

> 2026-09-03 R2 확정으로 음성은 해소. 추모관 사진은 여전히 로컬 디스크(본문 §5.1).

#### 5.5-1 🔴 지금 구조로는 "옵션 추가"가 안 됩니다

현행 Ⓑ는 **Web Speech API**입니다(`VoiceToTextInput.tsx:35~59`). 브라우저가 마이크를 자체적으로
잡고 **글자만 돌려주는** 물건이라 **여기서 오디오를 꺼낼 수 없습니다.** 통역만 해주고 녹음은
안 하는 통역사입니다. 녹음하려면 `getUserMedia` + `MediaRecorder`를 **따로 물려야** 합니다.

⚠️ 마이크를 둘이 동시에 잡으면 브라우저·OS에 따라 충돌하거나 인식률이 떨어질 수 있고,
**iOS Safari는 Web Speech API 지원이 원래 불안정**합니다.

#### 5.5-2 ✅ 설계 — 녹음이 본체, 실시간 자막은 보조

> 🔄 **2026-10-07 개발자 결정 — Web Speech(실시간 자막)를 뺍니다. 녹음 글 변환은 항상 CLOVA입니다** → §5.6-9.
> 근거: 실측(10-07, 마이크) — 말을 쉬었다 이어가면 앞말이 사라졌고, 10분 가까운 녹음일수록 불안정합니다.
> 유언 편지에서 **녹음과 글이 어긋나는 것**이 비용보다 큰 문제라고 판단했습니다. 아래 그림은 경위로 남깁니다.

```
[마이크 버튼] → getUserMedia 스트림
   ├─ MediaRecorder → 오디오 blob        ← ✅ 본체(저장 대상)
   └─ Web Speech API 병행 → 실시간 자막   ← 되면 좋고, 안 되면 생략
[녹음 종료]
   ├─ Web Speech 결과 있음 → 그대로 사용
   └─ 없음·실패(iOS 등) → blob을 Ⓐ 경로(Clova)로 보내 변환   ← 폴백
[사용자 편집 → 저장]
   ├─ 텍스트 → DB (encryptNoteField)
   └─ blob → 앱단 암호화 → R2 → mediaKey 기록
```

| 얻는 것 | |
| :--- | :--- |
| **iOS에서도 완결** | Web Speech가 없어도 녹음 + 서버 STT로 끝납니다 |
| **Ⓐ·Ⓑ 종착점 통일** | 저장 로직이 하나입니다(암호화 → R2 → `mediaKey`) |
| **인식 실패해도 음성이 남음** | 🔴 지금은 인식이 실패하면 **아무것도 안 남습니다** |

> ⚠️ **감수할 것**: 폴백이 돌면 Clova 변환 건수가 늘어 **무료 15분/월 한도를 더 빨리 태웁니다**
> (`06-04` §6.4-11-6-2). 유료 전환 시점이 앞당겨집니다. 〔2026-10-08: 무료 한도는 월 20분으로 확정〕

#### 5.5-4 🔴 포맷 — 허용 목록을 넓혀야 합니다

`MediaRecorder` 출력이 브라우저마다 다릅니다 — Chrome `audio/webm;codecs=opus` ·
Safari `audio/mp4`. **`config/uploadAudio.ts`의 허용 목록에 `webm`이 없어 지금은 거절됩니다.**
목록 확장 + 기존 `audioConvert`(ffmpeg)로 표준화합니다. **파이프라인은 이미 있습니다.**

> 2026-10-12: `webm` 허용 목록 반영됨(`config/uploadAudio.ts`).

### 5.6-5 ✅ 업로드 시점 = **확인 모달의 "저장"** (2026-09-04 개발자 확정)

> 🔄 **2026-10-07 대체 → §5.6-9.** 업로드·녹음은 **글 변환까지만**, R2·DB는 **편지의 `저장` 버튼에서만**.
> 아래 "모달의 저장 = STT → R2 → 메시지 기록 한 흐름"은 더 이상 쓰지 않습니다. 경위로 남깁니다.

> 🔄 **스펙갱신**(`roles.md` §2-1). D-3 구현은 **녹음을 멈추는 즉시** R2에 올립니다(확인 없음).
> 개발자가 흐름을 다시 정리하면서 **중지와 업로드 사이에 확인 모달**을 넣기로 했습니다.
> 🔵 **§5.6-5의 "고아 객체 확정 필요"가 이것으로 닫힙니다** — 취소하면 R2에 아무것도 안 갑니다.

**🔴 저장을 누르기 전에는 어디에도 쓰지 않습니다.** 녹음이 끝난 blob은 **브라우저 메모리에만**
있습니다. STT·R2·DB 셋 다 "저장" 이후에 일어납니다.

| | 취소 | 저장 |
| :--- | :--- | :--- |
| STT 변환 | ❌ | ✅ |
| R2 업로드 | ❌ **아무것도 안 올라감** | ✅ |
| DB 기록 | ❌ | ✅ |
| 남는 것 | **없음** — blob 폐기 + `revokeObjectURL` | 저장된 메시지 |

🔵 **이 한 가지 변경이 §5.6-5의 원래 문제를 없앱니다.** *"올려놓고 저장 안 하고 나가는"* 구간이
**존재하지 않게** 됩니다. 취소 버튼이 그 자리를 대신합니다.

**🔴 "저장"은 메시지 저장까지 한 번에 끝냅니다.** R2에만 올리고 메시지 저장을 따로 남겨두면
*"올렸는데 저장 안 함"* 구간이 그대로 돌아옵니다. 모달의 저장은 **STT → R2 → 메시지 기록**까지
한 흐름입니다. 본문 다듬기는 그 뒤 **수정**으로 합니다(카드가 이미 지원).

⚠️ **완전히 0이 되지는 않습니다** — R2 업로드는 됐는데 **메시지 기록이 실패**하면 1건이 남습니다
(네트워크 끊김 등). 🟡 **그때를 위한 수거 배치는 남겨둡니다**(D-6 #29) — R2 키 목록 ↔ DB
`mediaKey` 대조 후 **참조 없고 N일 지난 것**만 사람 승인으로 정리. `00-11` §5.4-5-2-2의
*"참조 확인 후 정리"* 가 그대로 절차입니다. ⏸ 구현은 급하지 않습니다 — 이제 **예외 상황에서만**
생기고, 비용은 0에 가깝습니다.

### 5.6-6 ✅ 화면 흐름 (2026-09-04 개발자 확정)

> 🔄 **2026-10-07 대체 → §5.6-9-2.** 아래 흐름은 경위로 남깁니다.

**Ⓑ 직접 녹음**

```
① "음성으로 말하기" 클릭 → 녹음 시작
② "녹음 중지" 클릭
③ 확인 모달 — "텍스트로 변환해서 저장할까요?"
④ [저장] → STT + R2 + DB     ┆     [취소] → 전부 폐기, 아무 데도 안 감
⑤ 듣기 · 삭제 버튼 활성화
```

**Ⓐ 파일 업로드**

```
① "파일 선택" → 파일 지정
② "업로드" → STT + R2 + DB
③ 듣기 · 삭제 버튼 활성화
```

🔵 **Ⓐ에는 별도 확인 모달을 두지 않습니다** — "업로드" 버튼 자체가 확인입니다. Ⓑ에 모달이 필요한
이유는 **중지가 곧 확정이 되어버리기 때문**이고, Ⓐ는 파일을 고르는 행위와 올리는 행위가 이미
나뉘어 있습니다.

🟡 **권고 — 모달 안에 "먼저 들어보기"를 넣습니다.** blob이 손에 있으니 **서버를 안 타고**
바로 재생됩니다(§5.6-2). 들어보지 않고 저장 여부를 정하라는 건 무리한 요구이고, 잘못 녹음된
