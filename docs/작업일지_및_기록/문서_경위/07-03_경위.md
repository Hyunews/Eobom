### 3.3-3 처음 서술 — `window.location.origin` 구현 (2026-08-20)

현재 구현은 `OBITUARY_CARD_IMAGE_URL = ${window.location.origin}/...` 입니다. **이러면 로컬에서

```ts

export const OBITUARY_CARD_IMAGE_URL = `${window.location.origin}/eobom-logo-hd.png`;

// ✅ 고정 공개 URL — 어느 환경에서 보내든 같은 이미지이므로 고정이 맞다
export const OBITUARY_CARD_IMAGE_URL = 'https://eobom.vercel.app/obituary-card.png';
```

### 6.4 ⓒ·ⓓ — 조회수 가드 누수와 고지 둘째 줄 (2026-09-09 · 09-21)

#### ⓒ 🔴 함께 고칠 것 — **조회수 가드는 지금도 새고 있습니다**

`obituaryController.ts`가 `isOwner`를 계산해 놓고(`:237`) **404 판정에만 씁니다.** 주석(`:243`)은
*"종료된 뒤 개설자 본인이 확인하러 들어온 방문은 세지 않는다"* 라고 의도를 적었는데, **활성 중
본인 방문은 그대로 셉니다** — 유족이 자기 링크를 눌러 확인할 때마다 `viewCount`가 +1입니다.

```ts
// as-is
if (!closed) { …increment… }
// to-be
if (!closed && !isOwner) { …increment… }
```

> 🔵 **이 모달은 fetch를 안 하므로 위 버그와 직접 연결되지는 않습니다.** 다만 §8 #8이 세기로 한 것은
> **조문객 조회수**이고 지금 값은 그게 아니므로, **같은 작업에 묶어 닫는 것이 맞습니다.**
> 🔴 **DB 쓰기가 아니라 조건 한 줄**이므로 백업 대상이 아닙니다(`db-safety.md` 범위 밖).


🔵 그 뒤: 수정됨 — `getObituaryBySlug`가 종료 아님 **그리고** 본인 아님일 때만 센다(본문 §6.4).

##### 🔴 2026-09-21 확인 — **두 번째 줄이 구현에서 빠졌습니다**(복구 대상)

`obituary` 재구현(커밋 `1abc82f`, `00-39` §6.8 확장)에서 이 고지가 **첫 줄만 남았습니다.**

| 위 코드블록의 문구 | 현재 구현 | 판정 |
| :--- | :---: | :---: |
| `조문객에게 보이는 화면입니다.` | 남음 | — |
| `수정하면 이 화면은 바로 바뀌지만, 이미 보낸 카카오톡 카드는 바뀌지 않습니다.` | 🔴 **없음** | **복구** |

🔴 **이 줄은 설명문이 아니라 고지입니다.** `00-39` 규칙 12(줄글 최소)·규칙 6-1(목록 설명문 제거)의
대상이 아닙니다 — 그 규칙들은 **보면 아는 것을 글로 또 쓰지 말라**는 것이고, 이 문장은 **보아서는
알 수 없는 사실**(이미 보낸 카드는 안 바뀐다)을 말합니다. §5.4-2가 *"이어봄의 책임은 알려주는
데까지"* 라고 정한 **그 알림의 실체**가 이 한 줄입니다.

🔴 **빠지면 대체할 자리가 없습니다.** `cardFieldsUpdatedAt` 경고는 **수정한 뒤에만** 뜨므로,
*"제대로 나갔나"* 를 확인하러 미리보기를 연 유족은 **어디에서도 이 사실을 듣지 못합니다** —
바로 위 🔵가 이 모달을 만든 이유입니다. 🔵 **줄 수가 문제라면** 두 문장을 한 줄로 합치는 것까지는
됩니다(*"조문객에게 보이는 화면입니다. 수정해도 이미 보낸 카카오톡 카드는 바뀌지 않습니다."*).
**사실을 빼는 것만 안 됩니다.**

✅ **같이 확인한 것 — `ObituaryView` 꼬리 문구 삭제는 스펙 범위 안입니다.** 랜딩의
`최종 수정: {시각} · 정보는 유족이 언제든 바꿀 수 있습니다.` 에서 뒷문장이 빠졌는데, §5.4-2가
**시스템이 하는 일 #2**로 정한 것은 *"랜딩에 최종 수정 시각을 표시한다"* 까지이고 **시각은 남아
있습니다.** 뒷문장은 그 시각이 뜻하는 바를 되풀이한 줄글이라 규칙 12에 해당합니다. **복구 불필요.**
