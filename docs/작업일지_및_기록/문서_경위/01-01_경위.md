### 2.3 [항목 3] 견적 비교 및 예상 기본 비용 (Estimate & Detailed Pricing)
* **기획 최종 판단**: **`[폐기]`** (2026-08-11 변경 — 종전 `[유지]`)
* **변경 사유**: 개발자·사장님 논의 결과 **이어봄의 수익은 견적 비교가 아니라 업체 문의(리드) 수수료에서 나온다**는 결론.
  견적 비교는 그 자체로 과금 지점이 없어 리드 전환의 우회로에 그치고, 세부 단가 수집은 e하늘 API·위치정보법
  사업자 신고에 묶여 있어(→ `01-02`) 단기간에 풀리지도 않는다. 상세 검토는 `01-03`(폐기 처리됨) 참고.

  나머지는 `"가격 정보 준비중"`이었다 — 이 상태를 **정상으로 간주하고 더 채우지 않는다.**

### 🛠️ 4. 개발 전달용 백엔드 DB 스키마 타겟 규격
2026-08-05 작성 당시의 타겟 규격. 실제 스키마는 그 뒤로 크게 바뀌었다(`priceValue`·`bookings`는 제거, 태그는 별도 테이블 대신 `Facility.tags` 배열). 현행 정본은 `00-05`.

```prisma
// 시설 마스터 테이블
model Facility {
  id           String   @id @default(cuid())
  name         String
  type         String   // "장례식장", "묘지/수목장"
  location     String   // 도로명 주소
  lat          Float
  lng          Float
  price        String
  priceValue   Int
  rating       Float    @default(0.0)
  religion     String
  guests       String
  isPartner    Boolean  @default(false) // 제휴 파트너 여부
  createdAt    DateTime @default(now())

  tags         FacilityTag[]
  reviews      FacilityReview[]
  bookings     FacilityBooking[]
}

// 시설 리뷰 테이블
model FacilityReview {
  id         String   @id @default(cuid())
  facilityId String
  userId     String
  rating     Float
  content    String
  createdAt  DateTime @default(now())

  facility   Facility @relation(fields: [facilityId], references: [id])
}
```
