### 1.1 처음 진단 — 목업의 전역 싱글턴 (2026-08-12)

목업의 추모관은 **전역 싱글턴**입니다. 헌화 수가 42로 하드코딩돼 있고 방명록도 하나입니다.
누구의 추모관인지가 없으므로 실제 서비스로는 성립하지 않습니다.

### 2.1 처음 공개 범위 표 — `PUBLIC` 포함 3가지 (2026-08-12 · 09-29 `PUBLIC` 폐지)

| 값 | 의미 | 검색 노출 |
| :--- | :--- | :---: |
| `PRIVATE` | 개설자와 지정 유족만 | ❌ |
| **`LINK`** | **URL을 아는 사람만 (기본값)** | ❌ |
| `PUBLIC` | 이어봄 내 추모관 목록에 노출 | ⭕ |

**기본값을 `PUBLIC`이 아니라 `LINK`로 두는 이유**: 사망 사실과 유족 구성이 공개적으로 색인되면

- `PUBLIC`이어도 **생년월일·주소·유족 실명 등은 공개 응답에서 제외**합니다(§4.1 화이트리스트).

> 🔴 **`00-13` §2.2가 이 조항의 전제를 흔듭니다.** *"URL을 아는 사람만"* 이라는 표현은 **1차 수신자
> 에만 참이고 2차 재전파 이후에는 거짓**입니다. 링크 모델 확정 시 이 절을 정정해야 합니다.

### 2.2 처음 서술 — 링크 모델 결정 대기와 C안 (2026-08-12 · 08-14 E안 확정)

- 비공개 URL은 추측 불가능한 토큰(`slug`)을 씁니다 — 순번(`/memorial/1`)이면 열람이 가능해집니다.
- **현행 설계는 `slug` 1개 영구 불변**입니다. `00-13`이 이를 *"비밀번호 없는 영구 마스터 키 한 장"* 으로
  진단하고 4개 안(A 단일영구 / B 회전가능 / C 단계분리 / D 초대기반)을 제시했습니다.
- **C안이 채택되면** `Memorial.phase`(`OBITUARY` → `MEMORIAL`)와 **장례 정보 컬럼(빈소·발인일시·장지·
  조의금 계좌)이 이 문서에 신설**되며, Domain 07의 모바일 부고장이 이 도메인으로 흡수됩니다.

### 2.3 처음 서술 — 신고 즉시 비공개 · `PUBLIC`만 L2 (2026-08-12 · 09-29 닫힘)

3. **신고 창구 + 즉시 비공개 전환** — 신고가 접수되면 **운영자 확인 전까지 자동 비공개**로 전환합니다.
   사후 확인보다 선차단이 맞습니다. 피해가 되돌릴 수 없는 종류이기 때문입니다.

> 🔵 **`00-12` §4 사다리 적용**: 추모관 개설은 **L1**(자기신고+로그인), **`PUBLIC` 전환만 L2**(운영자
> 검토)입니다. 이것이 `05-02` §6.1이 미결로 남긴 개설 게이트의 답입니다.

### 2.4 처음 서술 — 비회원 헌화 억제 설계와 로그인 재검토 (2026-08-12 · 09-29 확정)

**현행 스펙**: 조문객 대부분은 **비회원**이므로 비회원 헌화를 허용하되 중복을 억제합니다.

- 로그인 사용자: `userId`로 **1인 1회** 보장(DB 유니크 제약).
- 비회원: 브라우저 토큰 + IP 해시 조합으로 중복을 **억제**합니다.
  **완벽하지 않다는 점을 명시합니다** — 브라우저를 바꾸면 우회됩니다. 헌화 수는 정확한 집계가 아니라
  **추모의 표현**이므로 이 수준이 적정합니다. 정확성이 필요한 지표로 쓰지 마십시오.
- **IP는 원문 저장하지 않고 해시로만 보관**합니다(개인정보 최소 수집).

> 🔴 **개발자 지적(2026-08-12)**: *"비로그인 사용자가 서비스를 이용한다? 나는 별로라고 생각해."*
> **로그인 필수로 전환하면** 위 "억제만 가능" 문단과 IP 해시 수집이 통째로 사라집니다.
> `00-13` §6.1에 링크 모델별 함의가 정리돼 있으며, **링크 모델 확정 후 결정**합니다.
