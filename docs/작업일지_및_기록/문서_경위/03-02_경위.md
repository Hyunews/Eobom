### 3.1 처음 진단 — "업종을 구분하는 필드가 없다" (2026-08-14)

*"`schema.prisma:98`의 `Partner`에는 업종을 구분하는 필드가 없습니다. 지금까지 파트너가 장사시설뿐이었기 때문입니다."* — 2026-08-18 `partnerType` 신설로 해소. 처음 제안 스키마는 `partnerType`·`serviceAreas`·`serviceTags`·`licenseNo` 4개를 한 번에 넣는 안이었고, 실제로는 `partnerType`만 먼저 들어갔습니다(§4.1 기록).

### 3.2 처음 판단 — "초기 목록 0건, 그릴 지도가 없다" (2026-08-14)

처음 표는 03의 초기 목록을 **0건**, 사용자가 보는 것을 **제휴 업체만**으로 적고 이렇게 썼습니다 — *"01은 '먼저 지도를 그려놓고 사업자를 불러들이는' 구조였는데, 03에는 그릴 지도가 없습니다. 유품정리업은 공공 데이터셋이 없습니다(§6.1 — 법정 업종이 아니기 때문)."* 그래서 *"`FacilityClaim`에 해당하는 절차가 03에는 없고, 대신 '직접 등록 심사'가 그 자리를 대신한다"* 고 했습니다.
2026-08-19 무심사 확정으로 "심사"가 빠졌고, 2026-08-21 `03-03`이 폐기물처리업 허가 명부(공공데이터)가 있다는 점을 들어 이 판단을 반박했습니다(`03-03` §1.1, 결정 대기).

### 4.1 ✅ `Lead`가 시설을 **필수로** 전제하고 있었습니다 — **2026-08-18 해소**

**처음 진단(08-14)**: 당시 `schema.prisma:162`의 원문은 아래였습니다.

```prisma
facilityId String                 // ❌ 필수. null 불가
facility   Facility @relation(fields: [facilityId], references: [id])
```

03의 리드에는 붙일 `Facility`가 없으므로 *"`Lead.facilityId`를 `String?`으로 전환하는 마이그레이션이 03 착수의 0단계"* 로 두고, 01 무결성을 지키려고 **앱 레벨에서 `partnerType`별로 강제**하자고 권고했습니다(`04-01` §3.1 `lastVerifiedAt`을 API 레벨에서 강제한 것과 같은 방식).

**2026-08-18 마이그레이션 완료** — `[Claude:Sonnet]` 구현(walkthrough (25) ✅통과 / `20260818004442_lead_facility_nullable_partner_type`).

| 항목 | 결과 |
| :--- | :--- |
| `Lead.facilityId` | `String` → **`String?`** |
| `Lead.facility` 관계 | `Facility` → **`Facility?`** (FK `ON DELETE SET NULL`) |
| `Partner.partnerType` | **신설** — `String @default("FUNERAL_FACILITY")` |
| 기존 데이터 영향 | **없음(실측)** — `Partner` 2건 전부 기본값, `Lead` 5건 전부 `facilityId` 유지 |
| 검증 | 백엔드·프론트 `tsc --noEmit` 0건 · 서버 기동 · `psql` 조회. 적용 전 `pg_dump` 백업 |

03 전용 필드 3개는 이때 넣지 않았습니다 — 쓰는 코드 없이 넣으면 빈 필드만 생긴다는 판단(범위 해석, 스펙 이탈 아님).

### 6.1 처음 권고 — 등록 심사 기준 (2026-08-14)

> 🔴 **그래서 등록 심사 기준을 이어봄이 직접 정해야 합니다.** 01은 공공데이터에 등재된 시설이라

> **무허가 업체를 매칭해 불법 투기가 발생하면 플랫폼이 지목됩니다.**
>
> 🟡 **권고**: 사업자등록증 + **폐기물 관련 허가·신고증(해당 시)** 을 필수 제출로 두고,
> 해당 없음을 주장하는 업체는 **"폐기물은 유족 명의로 배출"** 임을 서면 확인받습니다.
> ⚠️ 지자체별 운용이 다를 수 있어 **모집 전 행정사·지자체 확인**이 필요합니다(§8-2).

#### 🔵 개정 사유 — 개발자 확정(2026-08-19)

> 🔵 *"**더미 회사로 우선 진행할 예정.** 아직 서비스 단계가 아니기에 **목업을 꼼꼼히 만드는 데 집중.**"*

화면을 그린 행위가 아니었습니다. **해법은 이미 `00-14` §2.2가 확정해 뒀습니다** —
*"지우면 회의에서 보여줄 화면이 없어지고, 두면 거짓말입니다. **목업임을 화면에 명시**하면
둘 다 해결됩니다."* **03에도 같은 기준을 적용합니다.**
