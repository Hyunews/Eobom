### 6. 이메일 중복 감지(MERGE/CREATE_NEW) 브라우저 E2E 검증

- 자연 상태로는 서로 다른 provider가 정확히 같은 이메일을 반환하는 계정 2개를 갖추기 어려워, DB를 임시 조작해 분기를 강제 유발하는 방식으로 검증(GOOGLE `SocialAccount` unlink + `User.email`을 구글 이메일과 동일하게 SQL 변경 → 재로그인).
- **MERGE**: 새 User 생성 없이 기존 User(`8ac86beb`, 윤현우)에 GOOGLE `SocialAccount`만 추가됨 확인.
- **CREATE_NEW**: 새 User(`email=null`) + 새 GOOGLE `SocialAccount`(실이메일은 `SocialAccount.email`에만 보존)가 기존 User와 분리 생성됨 확인.
- 검증 후 테스트로 생긴 여분 User/SocialAccount 삭제, 원래 상태(카카오 합성 이메일, 3사 연동 단일 User)로 SQL 복구 완료.
- 재현 절차 상세는 `claude_tasks.md` 참고.

### 7. `MyPageAuthSettings` link/unlink 브라우저 E2E 검증

- 연동 해제(unlink): 네이버 → 구글/카카오 순으로 2회 연속 성공, 매번 `SocialAccount` 개수 감소 확인.
- 최소 1개 유지 규칙: 마지막 1개 남은 상태에서 해제 시도 → 정상적으로 차단, 에러 메시지 노출 확인.
- 연동하기(link, 재인증): 네이버·카카오 각각 재연동 성공, `providerId`까지 기존과 동일하게 같은 User에 재연결됨 확인.
- 최종적으로 카카오/네이버/구글 3사 전부 원래 상태로 복구.

### 8. 사용자 제보 버그 수정: 연동 해제 후 재로그인 시 중복 계정 생성

- **제보 시나리오**: 구글 로그인 → 마이페이지에서 구글·네이버 연동 해제(카카오만 남김) → 다시 구글로 로그인하면 어떻게 되는지?
- **분석 결과**: 연동 해제가 `SocialAccount` 하드 삭제라서, 재로그인 시 provider+providerId 매치도 실패하고 이메일 매치도 실패(User.email은 최초 가입 provider 이메일로 고정돼 있어 다른 provider 이메일과 다름) → 완전 신규 유저가 조용히 생성되는 실제 버그로 확인.
- **수정**: `SocialAccount.unlinkedAt` 컬럼 추가(마이그레이션 `20260805033209_social_account_soft_delete_unlink`), 연동 해제를 소프트 삭제로 전환. 로그인 1단계가 `unlinkedAt` 상관없이 provider+providerId로 계정을 찾아 복구하도록 수정. `/api/auth/me`, 마이페이지 목록, 최소 1개 유지 카운트는 `unlinkedAt: null` 필터 추가. mypage 재연동(link)과 confirm-link(MERGE/CREATE_NEW)도 소프트 삭제된 행을 만나면 재생성 대신 복구하도록 처리.
- **재검증**: 실제 시나리오(구글 연동 해제 → 로그아웃 → 구글 재로그인) 재현 → User 개수 그대로 1개 유지, 같은 계정으로 정상 복구 확인.

- 전화 버튼: 터치기기 판별(`matchMedia('(hover:none)')`)해서 모바일은 `tel:` 링크, 데스크톱은 커스텀 hover 툴팁으로 번호만 노출.
- FacilityPage 상단 히어로의 "24시간 긴급출동" 버튼 제거(전역 플로팅 버튼과 중복) + 그 전용이던 `EmergencyModal.tsx` 삭제.

### 15. 🐛 사용자 발견 CSV 데이터 오류: "전남광주통합특별시" 45건
