## 🔍 2. 왜 나누는 것이 맞는가 — 두 기능의 성격 대조

`06-04` §6.1이 9개 섹션을 한 화면에 담았는데, **③만 성질이 다릅니다.**

| | **디지털 엔딩노트** (①②④⑤⑥⑦⑧⑨) | **유족 메시지 보관함** (③) |
| :--- | :--- | :--- |
| 입력 성격 | **표준화·서식화** — 체크·선택·한 줄 | **자유 형식** — 특정하기 어려움 |
| 완료 판정 | *"칸을 다 채웠는가"* | 🔴 **없습니다.** 언제든 다시 쓰고 고칩니다 |
| 수신 구조 | 지정 유족 **전원 공통**이 기본 | **수신자별 1:1**이 본체 |
| 열람 시점 | 섹션마다 다름(즉시/응급/사후) | ✅ **사후 고정** — 예외 없음 |
| 정서적 무게 | 실무 정보 | **이 도메인의 정서적 본체**(`06-04` §3 ②) |
| 쓰는 빈도 | 한 번 쓰고 연 1회 확인 | 생각날 때마다 |
| 입력 수단 | 폼 | 텍스트 + **음성**(§5) |

> ✅ **한 화면에 두면 서식 칸 사이에 편지가 끼어 있는 모양**이 됩니다. 6070 시니어에게
> *"연명의료 3지선다"* 와 *"자녀에게 남기는 편지"* 를 같은 진행바 안에 놓는 것은
> **완료율에도 정서에도 손해**입니다. **사장님의 UX 판단에 동의합니다.**

> 🔵 **`00_DOCS_INDEX.md`의 06 도메인 정의는 유지됩니다** — *"고인이 유족에게 무언가를 남기는
> 유일한 통로"*(2026-08-12 확정). **통로가 둘로 늘어나는 것이 아니라, 한 통로 안의 방이 둘입니다.**

## 🔴 4. 가장 위험한 지점 — STT 초안(⑨)과 음성 메시지의 혼동

**`06-04` §6.4-2가 세운 원칙**: 말로 남기는 유언장 **초안(⑨)은 본인 전용이고, 사후에도 유족에게
전달하지 않습니다.** 유족이 받으면 ***"이게 아버지 유언장인가"*** 로 읽기 때문입니다.

**그런데 이제 유족에게 실제로 전달되는 음성이 생깁니다.** 같은 마이크, 같은 녹음 버튼입니다.

| 혼동 방향 | 결과 |
| :--- | :--- |
| 보관함에 **유언 내용**을 말함 | 🔴 `06-02` §4.3이 기각한 **녹음유언이 이어봄을 통해 유족에게 배달**됩니다. 형제 분쟁 시 *"아버지가 이렇게 말했다"* 의 증거로 쓰입니다 |
| 엔딩노트 ⑨에 **작별 인사**를 말함 | 🟡 유족에게 영영 가지 않습니다. 사용자는 남겼다고 믿습니다 |

### 4.1 ✅ 분리가 이 문제를 완화합니다 — 그것이 분리의 두 번째 이유입니다

화면이 물리적으로 갈리면 *"여기는 마음을 전하는 곳, 저기는 유언장을 쓰기 위한 도구"* 라는
경계가 생깁니다. **한 화면에 있으면 어떤 문구를 써도 이 경계가 서지 않습니다.**

### 4.2 🔴 ⑨는 엔딩노트에 남깁니다

**보관함으로 옮기지 않습니다.** ⑨는 ⑧(유언장 소재 안내)과 한 세트인 *"유언장을 쓰기 위한 도구"* 이고,
**전달되는 곳에 두면 사용자가 "여기 넣은 건 유족에게 간다"고 믿습니다.**

### 4.3 🔴 양쪽에 상반된 고지를 상시 노출합니다

| 화면 | 문구 |
| :--- | :--- |
| 엔딩노트 ⑨ | *"이 초안은 **유족에게 전달되지 않습니다.** 직접 손으로 옮겨 쓰시기 위한 도구입니다."* |
| **보관함** | *"여기에 남기신 글과 음성은 **사망 확인 후 지정하신 분에게 전달됩니다.** 재산 분배·상속에 관한 내용은 **남기지 마세요** — 유언의 효력이 없고 유족 간 다툼의 씨앗이 됩니다."* |

> 🔴 **검증은 약속하지 않습니다.** 무엇을 말했는지 이어봄은 알 수 없습니다 —
> `06-04` §6.4-2-3 · `06-03` §1의 *"지킬 수 없는 문장은 넣지 않는다"* 와 같은 태도입니다.

## 🎙️ 5. 음성 — 원안(mp3)과 현실의 거리

### 5.1 🔴 지금 넣지 못하는 이유

`.harness/systems.md` §5 실측:

> 업로드 사진이 백엔드 **로컬 디스크(`eobom/backend/uploads/`)**에 저장된다.
> **Render는 재배포 시 디스크가 초기화**된다. **추모 사진도 여기 묶인다** — 스토리지 교체 전
> **추모관 오픈 금지**(`05-01` §2.6).

| 사진과 음성 메시지의 차이 | |
| :--- | :--- |
| 추모관 사진 | 소실되면 다시 올릴 수 있습니다 |
| **유족 메시지 음성** | 🔴 **소실 시점에 본인이 이미 없습니다.** 다시 올릴 사람이 없습니다 |

> 🔴 **이 도메인의 음성은 "수십 년 뒤 사후 전달"이 전제**라 **로컬 디스크가 원리적으로 불가**합니다.
> 사진보다 **더 엄격한** 선행 조건입니다.

### 5.2 추가로 서야 하는 것 — 스토리지만이 아닙니다

| # | 항목 | 왜 |
| :---: | :--- | :--- |
| ① | ⏸ **오브젝트 스토리지**(`00-11`) | §5.1 |
| ② | 🔴 **파일 단위 암호화** | `utils/crypto.ts`의 `encryptField`는 **문자열 컬럼용**입니다. 음성은 blob이라 **그대로 쓸 수 없습니다** — 파일 암호화 + 키 관리를 새로 설계해야 합니다(`06-04` §13 #4의 06 전용 키와 한 세트) |
| ③ | 🔴 **보유기간** | ⏸ `00-20`. *"사망 확인 전까지 무기한"* 이 성립하는지 확인 필요 |
| ④ | 🟡 **길이·용량 상한** | `06-04` §6.4-2-2 #2와 같은 항목. 화면에 **먼저** 표시 |
| ⑤ | 🟡 **포맷** | `06-04` §6.4-2-2 #1 — **아이폰 음성 메모 기본 형식은 `m4a`**입니다. mp3만 받으면 대부분 못 올립니다 |

### 5.3 ✅ 단계화 — 두 번 만들지 않는 순서

| Phase | 입력 | 상태 |
| :---: | :--- | :--- |
| **1** | **텍스트만** (수신자별 편지) | ✅ 지금 가능 |
| **2** | **직접 녹음 + 파일 업로드** | ⏸ §5.2 ①②③ 선행 |

> 🔴 **Phase 1 화면에 *"음성 메시지"* 를 약속 문구로 쓰지 않습니다.**
> `06-04` §2.2가 잡아낸 패턴(*"화면이 약속했는데 뒷받침이 없다"*)이 **새 화면에서 처음부터
> 재발하는 것**이 이 분리 작업의 가장 흔한 실패 방식입니다.
> ✅ 표기가 필요하면 `06-04` §2.2 ⑤ 방식 — ***"🎙️ 음성 메시지 (준비중)"*** 한 줄까지입니다.

> 🔵 **사장님 원안과의 차이는 여기 하나뿐입니다** — **mp3를 빼는 것이 아니라 순서를 뒤로
> 놓는 것**입니다. Phase 1에서 수신자 지정·편지 작성·개봉 배선을 완성해 두면,
> Phase 2는 **입력 경로 하나를 얹는 작업**이 됩니다(`06-04` §6.4-2의 Ⓑ→Ⓐ 논리와 동일).

## 🖥️ 7. 화면·진입 구조

### 7.1 두 화면의 역할

| | 엔딩노트 (SCR-002) | 보관함 (SCR-002-B 🆕) |
| :--- | :--- | :--- |

### 7.2 🔴 크로스 링크는 양방향으로 답니다

분리의 실패 방식은 **사용자가 나머지 절반의 존재를 모르는 것**입니다.

- 엔딩노트 하단: *"가족 한 분 한 분께 하고 싶은 말이 있으신가요? → **유족 메시지 보관함**"*
- 보관함 하단: *"장례 희망·연명의료 등 남겨두실 것이 있습니다 → **디지털 엔딩노트**"*

### 7.3 🔴 가족 지정 0명일 때가 이 화면의 기본 상태입니다

`FamilyDesignation`이 없으면 **수신자 카드가 하나도 없습니다.** 빈 화면이 아니라
**가족 지정으로 유도하는 화면**이어야 합니다(`MyPageFamilyDesignation` 재사용 —
`06-04` Phase 2 #6과 같은 진입점).

> 🔴 `06-04` §8.2의 경고를 그대로 적습니다 — ***"수신자가 없으면 사후에 전달되지 않습니다."***

### 7.4 🔴 메인 진입(도메인 슬라이드)을 1개로 둘지 2개로 둘지 — **확정 필요**

`domainSlides.tsx`의 슬라이드는 **사업 도메인 단위**입니다(장사시설·전문가·부고·수거·추모관).
여기에 06을 2개 넣으면 **06만 비중이 2배**가 됩니다.

> 🟡 **권고: 메인 슬라이드는 1개 유지, 사이드바만 2개.**
> 슬라이드 본문의 bullet에서 *"유족에게 남기는 메시지"* 줄이 보관함으로 들어가는 입구가 됩니다.
> 🔵 **사장님이 *"UX적으로 압도적"* 이라고 보신 지점이 메인 노출이라면 2개로 갑니다** — 그 경우
> 슬라이드 순서·아이콘·문구를 새로 정해야 하므로 **별도 지시로 받겠습니다.**
