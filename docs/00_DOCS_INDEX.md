> **문서 목적**: 이어봄(Eobom) 프로젝트의 전체 기획, 기술 아키텍처, DB 명세, API 규격, 화면 설계, 경쟁사 분석 및 기술 솔루션을 **도메인 기반 마크다운(.md) 단일 진실 공급원(SSOT)**으로 아카이빙합니다.

## 🧭 도메인 번호 체계 (2026-08-11 재편)

**도메인 번호 = 웹 사이드바 메뉴 순서**입니다. 메뉴 3번을 찾으면 `docs/03_...`을 보면 됩니다.

| # | 도메인 | 화면(`tab id`) | 성격 | 대상 |
| :---: | :--- | :--- | :--- | :--- |
| **01** | 장사시설 매칭 | `facility` | 거래(매칭) | 유족 |
| **02** | 전문가 매칭 (상속·법률) | `counseling` | 거래(매칭) | 유족 |
| **03** | 디지털 유품 정리 · 추모관 | `digital-estate` | 정리·추모 | 유족 |
| **04** | 상중 · 행정 케어 | `care-guide` | 동반 가이드 | 유족 |
| **05** | 디지털 엔딩노트 · 유언 | `ending-note` | 생전 준비 | **본인** |

01~04는 **유족이 고인을 위해** 쓰는 사후 기능이고, 05만 **본인이 자신을 위해** 미리 쓰는 생전 기능입니다.
`00_핵심플랫폼`·`06_비즈니스_분석`은 특정 도메인에 속하지 않는 공통 영역입니다.

**문서 번호 규칙**: `<도메인번호>-<순번>` (예: `01-05`). 도메인 안에서 01부터 시작하되 전역에서 유일하게 특정됩니다.
코드 주석에서 `docs 01-05 §3.4`처럼 축약 참조할 수 있어야 하므로 이 형식을 지킵니다.
