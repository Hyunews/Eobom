# 🏷️ 01-06. 시설 태그(#해시태그) 분류 체계 명세서

> **문서 성격**: 시설 태그의 **역할·값 목록·걸러보기 규칙의 정본**(2026-10-15 개발자 결정으로 개정).
> 08-10판은 `[Claude:Sonnet]` 구현 메모였고 "공설·사설만 누를 수 있고 나머지는 라벨"이었다 — 그 내용은 §5와 경위로 옮겼다.
> 구현 위치: `eobomDev/frontend/src/components/facility/tagCatalog.ts`(값 목록) · `facilityController.ts` `buildWhere`(걸러보기).

---

## 1. 태그의 역할 — 한 줄 (10-15 개발자 결정)

> **태그 = 아래 2가지 분류(운영 주체 · 시설 종류)의 값만 담고, 누르면 그 값을 가진 시설만 걸러 보여주는 칸.**

- 🔴 **2가지 분류 밖의 값은 태그에 두지 않는다** — 소개 문구("조용함" 등)·편의시설은 태그가 아니다(편의시설은 `amenities` 칸).
- 화면의 태그는 **전부 누를 수 있다**(누를 수 없는 라벨 태그는 없어진다).
- "걸러보기"다 — 목록 순서를 바꾸는 정렬이 아니다.

## 2. 분류와 값

| 분류 | 저장 값 → 화면 표시 | 대상 시설 | 데이터 출처 |
|---|---|---|---|
| **운영 주체** | `공설` → 공설 · `사설` → 사설 | 장례식장 · 묘지/수목장 | 장례식장: 보건복지부 장례식장 API · 묘지: 보건복지부 CSV `공-사설 구분` |
| **시설 종류** | `병원` → **병원 장례식장** · `전문` → **전문 장례식장** | 장례식장 | 보건복지부 장례식장 API(이미 들어 있음) |
| ↳ (같은 분류) | `봉안당` → **봉안당** · `자연장` → **자연장·수목장** | 묘지/수목장 | 보건복지부 CSV — 어느 파일에서 왔는지(봉안시설 / 자연장지)로 정해진다(§4) |

- 저장 값은 짧게, 화면 표시는 `tagCatalog.ts`의 `label`로 바꾼다(DB 값을 고치지 않고 이름만 바꾸는 방식).
- **수목장은 법상 자연장의 한 종류**(장사법 — 수목장·잔디장·화초장)라 한 값으로 묶는다. 원천 데이터가 수목장을 따로 구분해 주면 그때 값을 나눈다. (10-15 CSV 확인: 두 파일 모두 종류 칸이 없고 파일 자체가 구분 · 이름에 "수목"이 든 곳 47/262이나 이름으로는 못 나눔 — 예 "국립하늘숲추모원" · 개발자 확인, 묶음 유지)
- **공원묘지(매장 묘지)는 값을 두지 않는다** — 들여온 CSV가 봉안시설·자연장지 2종뿐이라 데이터가 없다. 묘지 현황 데이터를 들여올 때 값을 더한다.
- 한 시설은 **분류마다 값 하나**를 가진다(예: `공설` + `병원`, `사설` + `봉안당`). 값을 모르면 그 분류 태그를 비워 둔다 — 추정해서 채우지 않는다.
- 두 분류를 같이 고르면 **시설 종류별 공설·사설 비교**가 된다(10-15 로컬 실측):

| 시설 종류 | 공설 | 사설 |
|---|---|---|
| 병원 장례식장 · 전문 장례식장(합계) | 78 | 995 |
| 봉안당 | 235 | 455 |
| 자연장·수목장 | 87 | 171 |

## 3. 걸러보기 규칙

| 항목 | 규칙 |
|---|---|
| 어디서 누르나 | ① 검색 필터 영역의 태그 칩 ② 시설 카드의 태그 — 둘 다 같은 동작 |
| 무엇이 보이나 | "시설 종류" 칩은 검색 화면에서 고른 큰 구분(장례식장 / 묘지·수목장)에 맞는 값만 보인다(장례식장을 고르면 봉안당·자연장 칩은 안 보임). 구분이 **전체면 4개 모두** 보인다(10-15 개발자 결정). "운영 주체" 칩은 늘 보인다 |
| 배치(데스크톱) | 분류별 **두 줄**, 줄 앞에 분류 이름("운영 주체" · "시설 종류")(10-15 개발자 결정) · 🔄 **"고른 태그" 줄은 두지 않는다**(10-15 개발자 결정 — 실화면에서 자리만 차지. 고른 칩이 진하게 보이는 것으로 충분) |
| 🔴 모바일 | **검색 화면과 카드에 태그를 두지 않는다**(10-15 개발자 결정 — 좁은 화면에서 빼기). "고른 태그" 줄도 없음. 걸러보기는 **필터 판(필터 아이콘으로 여는 판) 안에만** 둔다 — 운영 주체·시설 종류 두 줄을 구분 아래에 추가, 고른 값은 요약 줄 끝에 붙임(예: 위치 아이콘 + "인천 연수구 · 전체 · 공설·봉안당", 길면 말줄임 · 이모지 쓰지 않음). 판은 닫혀 있는 게 기본이라 목록이 내려가지 않는다(10-15 개발자 결정) |
| 여러 개 고르기 | 🔄 **같은 분류 안에서도 여러 개** 고를 수 있다 — 하나라도 가진 시설이 나온다(예: 봉안당 + 자연장·수목장)(10-15 개발자 결정, 구현 때 바꿈. 이전 = 분류마다 하나) |
| 분류끼리 | **모두 만족**하는 시설만(예: 공설 + 봉안당 = 공설 봉안당 · 공설 + (봉안당 또는 자연장·수목장)) |
| 해제 | 고른 칩을 다시 누르면 해제(모바일은 필터 판 안에서) |
| 값이 비어 있는 시설 | 그 분류로 거르면 **안 나온다**(모르는 것을 맞다고 보여주지 않음) |
| 주소창 | 고른 태그가 주소(쿼리)에 남아 새로고침·공유해도 같은 결과 |

## 4. 데이터 정리 — ✅ 로컬·운영 10-15

> **결과(10-15 로컬·운영 같음, 2,024 → 2,022곳 · 운영은 개발자 실행)**: 봉안당 690 · 자연장 258 추가 · 분류 밖 태그 0 · 묘지 948곳 `source` = `mohw_csv`.
> `source` 원인 = `import-facility-csv.ts`가 `source`를 넣지 않아 DB 기본값 `kakao`가 들어감(카카오 보강 스크립트 아님) → 스크립트 고침.
> 시드 3곳 = 이름·주소 대조로 용인 평온의숲·제주 양지공원은 CSV 시설과 같은 시설 → **삭제**, 천안 하늘공원은 짝 없음 → **남기고 태그 비움 · `source`=`manual`**(태그는 추정하지 않음, §2).
> 운영 10-15 조회 = 로컬과 같은 분포. 운영 실행 = `npm run cleanup:tags -- --target prod`(확인만) → 백업(`-Target prod`) → 같은 명령 `--apply` → `npm run report:tags -- --target prod`.

10-15 로컬 조회(시설 2,024곳) 기준 현황과 할 일(정리 전 기록):

| 현황 | 할 일 |
|---|---|
| 공설·사설 · 병원·전문 = 이미 있음(장례식장 1,073곳 · 병원/전문 비어 있는 4곳) | 그대로 둔다. 4곳은 비워 둔 채로 |
| 묘지/수목장 948곳은 보건복지부 CSV 출신이고 공설/사설이 붙어 있다. 시설 종류 값만 없다 — 그러나 시설 번호 앞부분이 들여온 파일을 가리킨다(`bongan_` 690곳 = 봉안시설 · `jayeon_` 258곳 = 자연장지) | 번호 앞부분대로 `봉안당`/`자연장`을 태그에 더한다(외부 대조 불필요). `import-facility-csv.ts`도 앞으로 이 값을 넣게 고친다 |
| 🟡 이 948곳의 `source` 칸이 `kakao`로 적혀 있다 — 실제 출처(보건복지부 CSV)와 다름 | 원인 확인 후 바로잡는다(카카오 보강 스크립트가 덮었을 가능성) |
| 수기 시드 3곳(`f_` 번호) · 분류 밖 태그 11종(각 1곳) | 태그에서 뺀다. 시드 3곳 자체를 지울지는 정리 때 따로 묻는다 |

- 🔴 태그를 빼거나 채우는 것은 **기존 행을 고치는 DB 쓰기**다 → `.harness/db-safety.md` 절차(몇 건인지 알리고 승인 → 백업 → 실행). 로컬·운영 각각.
- 앞으로 가져오기 스크립트(`import-facility-*` · `sync-kakao-funeral`)는 **§2 값만** 태그에 넣는다.
- `amenities`의 시드 문구는 이 문서 범위 밖이다(손대지 않는다).
- 🆕 **편의시설 라벨(예: "24시간 상담")은 화면에 보이지 않는다**(10-15 개발자 결정) — 업체별 값을 채울 길(제휴 업체 직접 입력 등)이 품이 많이 들어 일단 제외. 카드에는 §2 태그만.

## 5. 08-10판에서 바뀐 것

| 08-10판 | 10-15판 |
|---|---|
| 누를 수 있는 태그 = 공설·사설 2개, 나머지는 라벨 | 2가지 분류(운영 주체 · 시설 종류) 6개 값, 전부 누를 수 있음 · 분류 밖 값은 태그에서 뺌 |
| 태그 1개만 고름(`tag`) | 분류마다 1개씩, 분류끼리 모두 만족 |
| 화이트리스트 밖 "마케팅 문구 50여 종"은 라벨로 유지 | 10-15 실측으로 이미 11종(각 1곳)만 남음 → 뺀다 |
